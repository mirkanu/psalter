## What Was Built

### `scripts/uat/verify-staff-alignment.js`

Playwright E2E that loads each psalm at `/psalms/<n>?view=staff`, inspects the abcjs SVG DOM, and asserts alignment.

**DOM selector strategy (verified against live abcjs 6.6.3):**
- `g.abcjs-staff-wrapper` — one element per rendered staff row (confirmed via DOM inspection)
- `g.abcjs-note` within each wrapper — one element per note position (one syllable slot)
- `.abcjs-lyric` within each `g.abcjs-note` — present if note has lyrics; absent = empty position

**Failure signal:** `trailingEmpty > TOLERANCE` — counts consecutive final notes in a staff row that have no lyric child. This correctly identifies the "words cut off at right edge" bug.

**Features:**
- Configurable `PSALM_LIST`, `UAT_BASE`, `TOLERANCE` env vars
- Failure screenshots saved to `scripts/uat/screenshots/staff-alignment-failures/`
- JSON report at `scripts/output/staff-alignment-report.json`
- Hard 20-minute timeout
- Exits non-zero when failures detected (CI gate-compatible)

## Root Cause Confirmed by UAT

The sweep confirms Plan 02's DB migration did NOT correctly fix the alignment bug. Inspection of Crimond's `abc_notation` after migration:

```
c2a4bg | c'4bgf4 | e2f4a2 | a2g2g2=b4 |
% PHRASE_BREAK
% PHRASE_BREAK          ← consecutive empty phrase
=b2c'4a2 | ... | e2f4
% PHRASE_BREAK
```

Phrases after `splitOnPhraseBreaks`:
- Phrase 0: 15 note heads (CM lines 1+2 combined — should be 8)
- Phrase 1: EMPTY (between consecutive PHRASE_BREAKs)
- Phrase 2: 19 note heads (CM lines 3+4 combined — should be 8 and 6 separately)
- Phrase 3: EMPTY

The migration inserted PHRASE_BREAKs at ABC text-line boundaries (where the original ABC had a newline), not after counting exactly 8 note heads. For Crimond, the entire first half of the tune is on one ABC text line — so the algorithm put 2 PHRASE_BREAKs together at the end of that line (creating an empty phrase) rather than inserting them mid-line after 8 and 14 note heads.

### Auto-fixed Issues

**1. [Rule 1 - Bug] page.evaluate argument serialization — tolerance not defined in browser**
- **Found during:** Task 04-01, initial smoke test
- **Issue:** `page.evaluate(fn, { tolerance, psalmNum })` serialized as object but the function signature used destructuring syntax incompatible with Playwright's arg passing
- **Fix:** Changed to pass `{ tolerance: TOLERANCE, psalmNum }` as args object and access via `args.tolerance` inside evaluate
- **Files modified:** scripts/uat/verify-staff-alignment.js
- **Commit:** 152a06f (inline fix before commit)

**2. [Rule 3 - Blocker] Stale Next.js build causing chunk load errors**

- **Fix:** Ran `npm run build && pm2 restart psalter` from main repo directory
- **Files modified:** None (operational fix)
- **Commit:** N/A

**3. [Rule 1 - Bug] Note count selector over-counting — total notes vs per-note-group**
- **Found during:** Task 04-01, selector verification
- **Issue:** Counting `.abcjs-note` elements (which includes the `g` wrapper AND nested paths) inflated note counts (34 total vs 15 expected for Psalm 23 l0). Each `g.abcjs-note` is one note position; using `querySelectorAll('.abcjs-note')` on the parent counted nested elements too.
- **Fix:** Changed to `g.abcjs-staff-wrapper` parent selector + `g.abcjs-note` note-position groups + `.abcjs-lyric` presence check per note group
- **Files modified:** scripts/uat/verify-staff-alignment.js
- **Commit:** 152a06f (inline fix before commit)
