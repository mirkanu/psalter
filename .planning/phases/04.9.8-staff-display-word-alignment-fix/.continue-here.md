## Two Root Causes Diagnosed

### Bug 1 — Syllabification errors (confirmed via `syllabifyForAbc` test)

```
quiet  → "qu- i- et"   ← WRONG (3 syllables; should be "qui- et" = 2)
waters → "waters"       ← WRONG (1 syllable; should be "wa- ters" = 2)
```

These cancel out numerically (still 6 total syllables for CM last line) but put lyrics under the WRONG notes:
- Note 3 gets "i-" (phantom middle syllable of "quiet") instead of "-et" or "wa-"
- Note 5 gets "waters" as one unit instead of "wa-" (with "-ters" displaced)

**Root cause**: `syllabifyForAbc` uses an NLP library that splits "quiet" incorrectly (the "ui" vowel cluster becomes an extra phoneme). "waters" is not split at all.

**Fix**: Add word overrides to `PSALM_SYLLABLE_OVERRIDES` in `src/lib/lyrics.ts` — same pattern as the 25 archaic -eth verb overrides already in place:
```ts
'quiet': 'qui- et',
'waters': 'wa- ters',
```
Also audit other psalm words the NLP gets wrong.

The `insertPhraseBreaks` algorithm correctly placed the 3rd PHRASE_BREAK at note 22 (after 8+6+8 notes). But Crimond's ABC has **34 total note heads** (not 28 for standard CM). Phrase 4 = notes 23–34 = **12 notes**, 6 CM syllables → 6 trailing empty note heads.
