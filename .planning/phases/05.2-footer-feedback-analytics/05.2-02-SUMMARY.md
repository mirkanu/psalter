# Phase 05.2 Plan 02: Footer, Feedback & Analytics — Build Summary

**One-liner:** SiteFooter with About/Copyright/Feedback modals, unauthenticated feedback API route inserting into feedbackSubmissions, and Umami analytics Script wired into root layout.

## What Was Built

### Task 1: Feedback API Route (`src/app/api/feedback/route.ts`)

Unauthenticated App Router POST handler at `/api/feedback`. Accepts JSON body with `message` (required), `name`, `email`, `pageUrl` (all optional). Returns 400 for empty/whitespace message and invalid JSON. Coerces empty strings to null before inserting into `feedbackSubmissions`. No authentication — public form endpoint.

### Task 2: SiteFooter + FeedbackModal components

**`src/components/SiteFooter.tsx`** — Footer bar rendering on every page with:
- Three buttons: About, Copyright, Feedback (open dialogs on click)
- About dialog: "About this Psalter" with verbatim UI-SPEC copy
- Copyright dialog: "Copyright Notice" with verbatim public domain + copyright text
- "Made by GSD Labs" link to `https://gsdlabs.dev` with `target="_blank" rel="noopener noreferrer"`
- Embeds `<FeedbackModal>` controlled by local state

**`src/components/FeedbackModal.tsx`** — Feedback dialog form with:
- Message textarea (required, `resize-none`)
- Name input (optional)
- Email input (optional)
- "Include current page URL" checkbox (checked by default, `includeUrl` initial state `true`)
- POSTs to `/api/feedback` with `loading` → `success`/`error` state
- In-place success state showing "Thank you for your feedback" — does NOT auto-close
- Error state showing "Something went wrong. Please try again, or email us directly."

### Task 3: Root layout wiring (`src/app/layout.tsx`)

Two additions inside `<Providers>`:
1. `<SiteFooter />` after `<Toaster richColors />` — footer on every page, inside Providers for theme context
2. Conditional `<Script>` for Umami analytics, guarded by `process.env.NEXT_PUBLIC_PSALTER_UMAMI_WEBSITE_ID` — prevents empty `data-website-id` attribute in local dev
