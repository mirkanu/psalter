## Decisions Made

- Used `db.query.tunes.findMany` (relational API) rather than raw joins — produces a cleaner nested object shape that maps directly to the return type without manual group-by
- Psalm ID deduplication via `new Set(...)` then `.sort((a,b) => a-b)` — multiple psalmVersions can reference the same psalm; dedup avoids duplicate numbers in display
- `buildUrl(meter, mood)` helper function keeps both URL params in sync regardless of which filter changes — avoids the bug where changing meter drops the mood param

## Deviations from Plan

None — plan executed exactly as written. The Playwright test script was adapted to handle shadcn Select's DOM behaviour (multiple `[role="listbox"]` elements persist in DOM; the second listbox must be read via `.nth(1)` index rather than `.first()`).

## Issues Encountered

- Playwright smoke test initially failed because shadcn Select renders multiple `[role="listbox"]` elements in the DOM simultaneously (one per Select, kept mounted but hidden). Reading `.first()` always returned the Meter listbox. Fixed by using `locator('[role="listbox"]').all()` and indexing by position.
- App requires `npm run build && pm2 restart psalter` after code changes since it runs as a production build. Build completed successfully in ~90 seconds.
