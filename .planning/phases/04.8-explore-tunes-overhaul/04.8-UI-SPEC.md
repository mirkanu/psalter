## Reference Site Audit (EXP-01)

Playwright crawl of `psalter.cprc.co.uk` performed 2026-05-10. Findings:

### /explore (reference)

**Page title:** "Explore"

**Tagline:** "The Psalms categorised in different ways"

**Navigation tabs (top-level categories):**
1. Themes
2. Messianic
3. Quoted in New Testament
4. Other Topics
5. Authors etc
6. Creeds

**Under "Themes" tab — sub-filters visible:**
- Theme Type
- Main Topic
- Mood
- Song Type
- When you...

**Current /explore implementation (gsdlabs.dev) has:**
- Topics grid (from `topics` table) with psalm counts
- Nave's Topics expandable section
- Messianic Psalms link
- Authors grid (conditional, ≥2 authors)

**Gap analysis:** Reference site organises by tab (Themes / Messianic / NT / Other Topics / Authors / Creeds). Our current page is a flat list. The reference "When you..." section maps to a mood/situation taxonomy in our DB (the "when you are afraid / dealing with enemies" etc. categories visible in the crawl come from the `topics` table with `topicType = 'when you'`). The key sections to add/restructure are documented in the component inventory below.

### /tunes (reference)

**Page title:** "Tunes Database"

**Subtitle:** "To print or download, click the three dots in the top row here." (Airtable-specific — omit)

**Filter sidebar/panel — filter headings:**
- Mood (Cheerful, content, Fast, Last line repeated, long, minor key, ominous, sad, Slow, Strong)
- Meter (10 10 10 10 10, 66 66, 66 66 88, 76 76 D, 87 87, Common Meter (CM, 86 86), LM (long meter, 88 88), SM)
- In 1912 PRCA Psalter (true)
- Well-Known Hymn (true)

**Tune card columns (table layout):**
- Tune Name
- Meter
- Recommended Psalms (comma-separated psalm numbers, e.g. "58, 131, 38, 14, 53, 87")
- Mood (one or more mood tags)
- # in 1979 RP Psalter
- # in 1912 PRCA Psalter
- Famous Hymn (associated hymn name if applicable)

**Current /tunes implementation gap:** TuneGrid shows only Name + Meter badge. It lacks: Recommended Psalms, Mood tags, Hymn Book numbers, and Famous Hymn. Filters support Meter only; reference has Mood, Meter, PRCA Psalter, and Well-Known Hymn filters.

**DB mapping:**
- Mood → `tuneMoods` join → `moods.name`
- Meter → `tunes.meter`
- Recommended Psalms → `psalmVersionTunes` join → psalm IDs
- PRCA/RP Psalter numbers → not in current schema; these are Airtable fields not yet migrated — **treat as out of scope for this phase** unless found in DB
- Famous Hymn → not in current schema — **out of scope**
- Mood filter → available via `moods` table join

## Spacing Scale

Source: Existing codebase convention (Tailwind 4 default scale, multiples of 4). Pre-populated from observed patterns in `explore/page.tsx` and `TuneGrid.tsx`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps (`gap-1`), inline badge padding |
| sm | 8px | Compact element spacing (`gap-2`, `mb-2`) |
| md | 16px | Default element spacing (`px-4`, `gap-4`, `mb-4`) |
| lg | 24px | Section padding (`py-6`, `gap-6`, `mb-6`) |
| xl | 32px | Layout gaps (`py-8`, `mb-8`) |
| 2xl | 48px | Major section breaks (`my-8` separator) |

Exceptions:
- Touch targets for filter tags: minimum 44px height (`min-h-[44px]` on interactive rows)
- Tune card inner padding: 16px (`p-4`) consistent with existing TuneGrid

## Typography

Source: `globals.css` CSS variables + existing page components. Pre-populated.

Exactly 4 font sizes, exactly 2 weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (text-base) | 400 (normal) | 1.5 |
| Label / small / badge | 14px (text-sm) | 400 (normal) | 1.4 |
| Section heading | 20px (text-xl) | 600 (semibold) | 1.2 |
| Page heading | 30px md:36px (text-3xl md:text-4xl) | 600 (semibold) | 1.2 |

Rules:
- Page heading (`h1`): `font-sans text-3xl md:text-4xl font-semibold text-foreground` — match existing explore/tunes headings, semibold throughout (no font-bold)
- Section heading (`h2`): `text-xl font-semibold` — match existing pattern
- Badge text (meter, mood tags): `text-sm` (14px) — same as label role; do NOT use `text-xs`
- Tune name in card: `text-base font-semibold` — match existing TuneGrid pattern
- `font-bold` (700) is NOT used anywhere in this phase; all headings use `font-semibold` (600)

## Color

Source: `globals.css` CSS variables (shadcn Nova neutral palette). Pre-populated.

| Role | CSS Variable | Usage |
|------|-------------|-------|
| Dominant (60%) | `--background` = `oklch(1 0 0)` (white) | Page background, card surfaces |
| Secondary (30%) | `--muted` = `oklch(0.97 0 0)` (near-white gray) | Section filter panel bg, hover states, skeleton bg |
| Accent (10%) | `--primary` = `oklch(0.205 0 0)` (near-black) | Active nav links, selected filter state border, hover text color change |

Accent reserved for:
- Active/selected meter filter (border highlight `border-primary`)
- Active/selected mood filter (border highlight)
- Hover state on tune card: `hover:border-primary`
- Nav link active state (already in SiteHeader)

Accent is NOT used on: section headings, body text, psalm count badges, tune name text.

## Component Inventory

### /explore page — restructured layout

**Primary visual anchor:** The "Topics" section heading is the first visible landmark on `/explore` — it orients users to the page's organisational purpose before they scan individual items.

**Page header** (keep existing):
```
h1: "Explore"
subtitle: "Browse psalms by topic, theme, and category"
```

**Section structure — flat list (not tabbed):**
The reference uses JavaScript tabs to group categories. Our implementation uses server-rendered sections with `<Separator>` dividers — this is acceptable and already matches what we have. The gap is that we need to map the reference's taxonomy labels to our existing data.

**Section 1: "When you..." (NEW)**
- Source: `topics` where `topicType = 'when'` or similar (verify against DB)
- Layout: Same grid as existing Topics (`grid-cols-2 sm:grid-cols-3 lg:grid-cols-4 gap-2`)
- Each item: topic name + psalm count badge + link to `/explore/topics/[slug]`
- If `topicType` column doesn't segregate "when you" topics, this section is omitted

**Section 2: Topics (existing — keep)**
- Label: "Topics"
- Source: `topics` table (non-Nave's, non-"when" types)

**Section 3: Nave's Topics (existing — keep)**
- Label: "Nave's Topics"
- Keep NavesExpand expandable pattern

**Section 4: Messianic Psalms (existing — keep)**
- Label: "Messianic Psalms"
- Single link card to `/explore/messianic`

**Section 5: Authors (existing — keep)**
- Label: "Authors"
- Conditional: only shown if ≥2 authors in DB

**Separator** (`<Separator className="my-8" />`) between every section — existing pattern.

### /tunes page — expanded tune cards

**Primary visual anchor:** On `/tunes`, the tune name in the first visible card row is the dominant element — rendered at `text-base font-semibold`, it draws the eye before the meter badge or psalm list.

**Page header** (keep existing):
```
h1: "Tunes"
subtitle: "[N] tunes in the CPRC tune index, sorted alphabetically."
```

**Filter controls (expanded from current):**
- Meter filter: existing `<Select>` — keep
- Mood filter: NEW `<Select>` — filter by mood name (from `moods` table via `tuneMoods` join)
- Both filters use URL query params for shareability (`?meter=CM&mood=Slow`)
- Clear button: show when any filter is active (existing X button pattern)
- Filter controls row: `flex flex-wrap items-center gap-3 mb-6`

**Tune card — expanded fields:**
```
[Tune Name]                    [Meter badge]
Recommended psalms: 58, 131, 38...
Mood: [Slow] [content]
```
- Tune name: `text-base font-semibold`, link to `/tunes/[id]`
- Meter: `<Badge variant="secondary" className="text-sm shrink-0">`
- Recommended psalms: `text-sm text-muted-foreground` — comma-separated psalm numbers; show max 6 then "+N more"
- Mood tags: `<Badge variant="outline" className="text-sm">` — one badge per mood, flex-wrap row below name
- Card hover: `hover:border-primary hover:shadow-sm transition-all` (existing pattern)
- Card active: `active:scale-[0.98]` (existing pattern)

**Grid layout:** `grid-cols-1 sm:grid-cols-2 md:grid-cols-3 lg:grid-cols-4 gap-4` — keep existing

### /search route removal

**Remove:** `src/app/search/` directory (entire route)

**SiteHeader update:** Remove `{ href: "/search", label: "Search" }` from `navLinks` array.

**Nav order after removal:**
```
Psalms | Tunes | Explore | Daily Plan
```

**Redirect:** Add `next.config` redirect from `/search` → `/psalms` (301) so any bookmarked search URLs land on the inline-search-capable page.

| State | Trigger | UI |
|-------|---------|-----|
| Loading | Route navigation | Existing `loading.tsx` skeleton (already present) |

| Both filters | `?meter=CM&mood=Slow` | Combined filter; both badges show; clear button visible |
| No matches | Filter combo has 0 results | Empty state (see Copywriting) |

## Interaction Contracts

### /tunes filter behaviour

- Meter and Mood selects are independent; either or both can be active simultaneously
- Filter changes update URL params immediately via `router.replace` (no page navigation)
- Both selects read initial state from `useSearchParams` on mount
- Clear button: visible when `selectedMeter !== 'all'` OR `selectedMood !== 'all'` — clears both filters at once; navigates to `/tunes`
- Enter key in either select: default browser behaviour (no special handling)

### /explore navigation

- All explore links are standard Next.js `<Link>` elements (prefetch on hover)
- NavesExpand expandable: existing `<NavesExpand>` component — keep behaviour unchanged

### /search removal

- `src/app/search/page.tsx` and `src/app/search/loading.tsx` (if present) deleted
- `SiteHeader.tsx` `navLinks` array updated: remove Search entry
- `next.config.ts` redirect: `{ source: '/search', destination: '/psalms', permanent: true }`
- Any internal `<Link href="/search">` references updated (check `src/app/search/page.tsx` which links to `/explore` — now deleted, no action needed; check for any links TO /search in other pages)

### Click feedback

All existing tune cards already have `active:scale-[0.98]`. Explore topic links have `hover:bg-muted transition-colors`. No new interaction patterns beyond existing codebase conventions.
