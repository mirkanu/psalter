| marker-mismatch (SKIP) | 5 | PHRASE_BREAK count != expected — data-gap tunes |

**Dominant failure mode: split-mismatch (105/129 = 81% of analysed tunes)**

### What split-mismatch means

For failing tunes, the last phrase (abcjs-l3 for CM) contains far more note heads than the expected 6 (CM phrase 4 = 6 syllables). Examples from checker output:
- Psalm 3: lastStaff noteCount=15, notesWithLyric=6, trailingEmpty=9
- Psalm 8: lastStaff noteCount=24, notesWithLyric=7, trailingEmpty=17

These last-staff note counts (15, 24, 30+) far exceed the expected 6 for CM phrase 4, confirming the PHRASE_BREAK is placed too early — it's cutting the tune at note head 22 (the CM split point) but the music doesn't align to that boundary. Notes 23+ go into phrase 4 without any lyric tokens, causing the trailing-empty failures.

### What token-underproduction means

The 24 token-underproduction tunes have `wTokens = [0, 0, 0, 0]` for ALL phrases — they have zero `w:` lines anywhere. These are tunes that were annotated with PHRASE_BREAK markers but never had lyric (w:) lines generated. They need solfège OCR or syllabification to produce w: lines, not a PHRASE_BREAK fix.

## Recommended fix path for Plan 02

### Path A — Re-annotate ABCs (split-point fix)

**Evidence:** 105/129 (81%) of tunes are split-mismatch. The split points [8, 14, 22] for CM assume exactly 28 note heads total. Tunes with ornaments, passing notes, repeats, or >28 note heads will have their PHRASE_BREAK placed at the wrong position. The `annotate-phrase-breaks.ts --overwrite` flag supports re-annotation.

**Mechanism:** Run `npx tsx scripts/annotate-phrase-breaks.ts --overwrite` after updating `getSplitPointsForMeter` to handle the actual note-head distribution per tune (or switch from note-head-count-based splitting to line-count-based splitting, which already exists as a fallback).

**Why Path A and not the others:**
- Path B (fix w: token production) addresses the 24 token-underproduction tunes, not the 105 split-mismatch ones. Token-underproduction tunes have wTokens=0 everywhere — fixing the last phrase alone won't help.
- Path C (fix NotationRenderer counting) is not indicated — the split-mismatch is clearly a DB-side PHRASE_BREAK placement issue, not a client-side counting error.
- Path D (mixed) would apply Path A to 81% and Path B to 19%, which is valid but complex — recommend confirming Path A first since it covers the dominant failure mode.

**Scope:**
- Fix: Update `scripts/annotate-phrase-breaks.ts` `getSplitPointsForMeter` or switch the splitting strategy
- Re-run: `npx tsx scripts/annotate-phrase-breaks.ts --overwrite` (updates DB ABC for all affected tunes)
- Verify: `node scripts/uat/verify-staff-alignment.js` to confirm trailing-empty failures drop
- Note: No production build required (ABC is stored in DB; NotationRenderer reads it)

**Pass target after Path A fix:**
- 144 total tunes with ABC - 10 meter-n1 - 5 marker-mismatch = 129 eligible
- Expected: 105 split-mismatch fixed + 0 unclassified = ~105 more passing
- Remaining 24 token-underproduction will need a separate Path B fix
- Checker target: 54 (already pass) + ~105 = ~130+ passing; minus tolerance for tunes that may still have issues
