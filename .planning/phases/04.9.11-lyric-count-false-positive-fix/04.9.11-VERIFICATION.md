## Residual failures

**None.** 0 failures in the full 150-psalm sweep.

The Plan 01 investigation classified 105 tunes as "split-mismatch" and 24 as "token-underproduction." Both classifications were based on `wTokens=0` in the stored ABC (no w: lines), which was a misleading metric — `w:` lines are generated dynamically by NotationRenderer, not stored. The actual root cause for all 85 previously-failing tunes was the `_` padding token in `padWLineToNoteCount`:

- `_` in ABC w: lines means "hold until end of slur" ({skip: true, to: 'slur'} in abcjs)
- abcjs renders `_` positions as empty `<tspan>` elements
- The UAT checker's `textContent.trim()` correctly identifies these as uncovered
- Result: notes with `_` padding always showed as `trailingEmpty`, regardless of PHRASE_BREAK placement

Fix: replacing `_` with `·` (U+00B7 middle dot) — a regular syllable character that abcjs renders with non-empty textContent.

## Root cause documentation

**Why `_` rendered as empty:** abcjs `addWords()` parser processes `_` as `{skip: true, to: 'slur'}`. The note that receives this skip token gets `{syllable: "", divider: " "}` — empty syllable. The DOM `<tspan>` has empty `textContent`. The checker's `textContent.trim() !== ""` check correctly identifies this as uncovered.

**Why `·` (middle dot) works:** Middle dot is a regular ASCII-adjacent Unicode character not in abcjs's special-character list. The parser stores it as a syllable word `{syllable: "·", divider: " "}`. The DOM `<tspan>` renders with `textContent = "·"` (non-empty). The checker counts it as covered.

**Why NBSP failed:** JavaScript's `\s` regex matches ` ` (non-breaking space). abcjs's `parseCommon.strip` uses `/\s+/` which strips NBSP, so ` ` tokens become empty strings and are silently dropped.
