# Phase 15.2 Plan 02: Defer SiteHeader's always-on client weight

## One-liner

SiteHeader (in the root layout, hydrates on every route) now imports GlobalSearch and FeedbackModal via `next/dynamic({ ssr: false })` wrappers and consumes `authClient.useSession()` only after `requestIdleCallback`, taking ~290 LoC of dialog code + the per-route render cost of the Log Out link off first paint.

## What changed

- **`src/components/GlobalSearchClient.tsx` (new, 29 LoC):** `next/dynamic` wrapper for `GlobalSearch` with `null` Suspense fallback. The dialog is closed by default, so a null fallback produces no CLS — same shape as `PsalmPickerModalClient` from Phase 15.1-01.
- **`src/components/FeedbackModalClient.tsx` (new, 29 LoC):** Same shape for `FeedbackModal`. Defers the feedback form's `Input` / `Label` / `Textarea` / `Checkbox` shadcn primitives off every route's initial bundle.
- **`src/components/SiteHeader.tsx`:** Swapped the eager `GlobalSearch` and `FeedbackModal` imports for the Client wrappers (identifier-only changes, props unchanged). About / Copyright `Dialog` blocks stay inline — their render is gated behind `footerOpen === 'about' | 'copyright'`, and their `Dialog` primitive is shared with other header code, so extracting them buys nothing.
- **`src/components/SiteHeader.tsx` session gate:** A `sessionEnabled` state flag starts `false` and flips after `requestIdleCallback` (with a `setTimeout(..., 1)` fallback for Safari). The hook call itself stays unconditional — gates only consume `showLogout`, never the hook invocation, so there is no rules-of-hooks violation. Anonymous visitors never see the Log Out link; logged-in precentors get it one frame later, after the idle gate.
- **`src/components/GlobalSearchClient.test.tsx` (new, 38 LoC):** jsdom Wave-0 smoke test mirroring `PsalmPickerModalClient.test.tsx`. Verifies the dynamic import resolves without throwing on a closed dialog, and that the closed dialog renders no search input.
- **`src/components/SiteHeader.test.tsx` (new, 78 LoC):** Behavioural guard for the session deferral, using the `vi.hoisted` pattern from `ChangelogComposer.test.tsx`. Four cases: anonymous sees no Log Out on first render; anonymous still sees none after the gate fires; logged-in precentor eventually sees the link via `waitFor`; pending session never produces the link regardless of gate state.

### Note on `authClient.useSession()` — plan must_haves, honest result

The plan anticipated that Better Auth 1.6.9 might expose an `enabled` option on `useSession()`. It does not — the type definition is `useSession: () => { data, isPending, isRefetching, error, refetch }` (zero arguments). The `/api/auth/get-session` request therefore still fires on mount.

### Why this plan was always expected to be marginal

The plan's skepticism was correct: ~290 LoC of application code split out of every route is small compared to what moved in Phase 15.1 (PsalmListingGrid alone was 498 LoC + 1000 LoC of psalm-detail-app code moved ~3665 ms → 3030 ms scripting — worth ~+2 points on a single-run measurement we now know to carry ±6 noise). The session fetch is *the* critical-path win (it removes a network request, not just app code), but the hook signature doesn't support an `enabled` flag, so the request still happens — we only remove the Log Out link from the first-paint DOM, not the XHR.

Plan 15.2-03 (the next plan) will record whether the network trace shows `/api/auth/get-session` moved off the render-blocking critical path — which is the part of Plan 02 that *can* move LCP and explain why this plan's medians show zero net movement despite cleaner code.

## Realistic ceiling remains the same

The post-plan ceiling is still 0.63–0.70 on `/`, `/psalms`, and 0.65–0.70 on `/psalms/23` — unchanged from Plan 02's prediction table. Reaching 0.90 on mobile-simulated throttling requires reducing framework-runtime scripting (the 910–1134 ms in `0r5n9xaeyh.pb.js`), which can only happen by converting `SiteHeader` to a server component with tiny client islands — a refactor explicitly out of Phase 15.2's budget.
