## Findings → Phase 15.2 must address

1. **`qualities: [75, 90]` array added in Phase 15.1-03 Task 1 triggered the `/` regression.** Reverting to the simpler form restores baseline numbers. Either:
   - Drop the qualities tweak entirely (q=75 default, logo still sharp because sizes=175/350px picks a high-res variant automatically), OR
   - Revert logo quality attribute to default (`quality={undefined}`) and remove the `qualities: [75, 90]` from next.config.ts. The logo will still serve crisply at high DPR via srcset selection, just at default q=75 instead of q=90.
2. **Framework chunk `0r5n9xaeyh.pb.js` is the dominant TBT cost** at 1142-3030ms scripting per route. This is React 19 + Next.js 16 baseline. Splitting it requires `next.config.js experimental.serverActions` config + granular `next/dynamic` imports. Modest but real savings expected.
3. **`/psalms/23` (psalm detail)** has PsalmListingGrid transitively loaded through PsalmPickerModal — even with the 5 dynamic-import wrappers, PsalmListingGrid (498 LoC) leaks through the modal's Suspense boundary. Need to make PsalmPickerModal's import of PsalmListingGrid itself dynamic, gated behind a "modal opened" state.

## Realistic ceiling

- A 5-10 point improvement on `/` from reverting `qualities` to `[75]`
- A 5-10 point improvement on each route from dynamic-importing the heavy client components that are still loading on first paint (SingingView, OnboardingTour)
- If the framework chunk can be split: another 5-15 points

Best case: 90+ across all three routes achievable.
Likely case: 75-89 across all three routes — solid improvement even if not 90+.
