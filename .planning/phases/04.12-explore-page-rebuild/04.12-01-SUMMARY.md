# Phase 04.12 Plan 01: Schema Foundation for Explore Page Rebuild Summary

One-liner: Added 3 new columns, 3 new tables, and 3 Drizzle relation blocks to support Explore page sections, pushed to live psalter-db, and installed shadcn Collapsible + Table primitives.

## What Was Built

**Schema changes (src/db/schema.ts):**
- `psalms.dateBC` (`date_bc INTEGER`) — psalm composition date BC, for Timeline section
- `psalms.occasion` (`occasion TEXT`) — psalm use occasion, for context display
- `navesTopics.messianic` (`messianic TEXT`) — messianic classification flag on Nave's topic
- `navesTopicEntries` table (`naves_topic_entries`) — individual sub-entries per Nave's topic with `subTopic` and `quotation` fields
- `verseNavesTopicEntries` junction table (`verse_naves_topic_entries`) — composite PK (verseId, entryId) linking verses to topic entries
- `creedalReferences` table (`creedal_references`) — links verses to Westminster creedal questions with `creed`, `questionNumber`, `url` fields
- Relations for all three new tables (navesTopicEntriesRelations, verseNavesTopicEntriesRelations, creedalReferencesRelations)

**shadcn components:**
- `src/components/ui/collapsible.tsx` — Radix-based Collapsible primitive
- `src/components/ui/table.tsx` — Table, TableHeader, TableBody, TableRow, TableCell etc.

**Live DB push:**
- `db:push` applied all additive changes to `psalter-db` container with no data-loss prompts
- Verified via `information_schema` and `to_regclass` queries — all 3 columns and 3 tables confirmed present

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Worktree missing .env for db:push**
- **Found during:** Task 2
- **Issue:** Git worktrees only contain tracked files; `.env` is gitignored and therefore absent from the worktree. Running `npm run db:push` from the worktree directory failed with "Either connection url or host required".
- **Fix:** Passed `DATABASE_URL` inline as a shell environment variable: `DATABASE_URL=postgresql://... npm run db:push`. The drizzle.config.ts reads `process.env.DATABASE_URL` so this worked without any file changes.
- **Files modified:** None (environment-only workaround)
