### `middleware.ts` (middleware, request-response)

**Analog:** None — no middleware.ts exists yet in the project.

**Pattern from RESEARCH.md** (must live at project root alongside `src/`):
```typescript
// middleware.ts
import { NextRequest, NextResponse } from "next/server"
import { getSessionCookie } from "better-auth/cookies"
import { auth } from "@/lib/auth"

export async function middleware(request: NextRequest) {
  const { pathname } = request.nextUrl

  // Fast cookie check for /precent/* — any authenticated session
  if (pathname.startsWith("/precent")) {
    const sessionCookie = getSessionCookie(request)
    if (!sessionCookie) {
      const callbackUrl = encodeURIComponent(pathname)
      return NextResponse.redirect(new URL(`/login?callbackUrl=${callbackUrl}`, request.url))
    }
    return NextResponse.next()
  }

  // Full session + role check for /dev/* — admin required
  if (pathname.startsWith("/dev")) {
    const session = await auth.api.getSession({ headers: request.headers })
    if (!session) {
      const callbackUrl = encodeURIComponent(pathname)
      return NextResponse.redirect(new URL(`/login?callbackUrl=${callbackUrl}`, request.url))
    }
    if (session.user.role !== "admin") {
      return NextResponse.redirect(new URL("/login", request.url))
    }
    return NextResponse.next()
  }

  return NextResponse.next()
}

export const config = {
  runtime: "nodejs",  // Required — auth.api.getSession opens a DB connection
  matcher: ["/dev/:path*", "/precent/:path*"],
}
```

**Critical:** `runtime: "nodejs"` is mandatory. Edge runtime cannot open TCP connections to PostgreSQL.

## Migration Sequencing Note (for planner)

The D-19 data migration (add `user_id`, backfill existing rows, drop `precentor_name`) cannot be done with a single `drizzle-kit push`. RESEARCH.md Pitfall 2 documents this. The planner must sequence:

1. Wave 0: Install `better-auth`, run `npx auth@latest generate`, inspect output, add auth tables to schema, `drizzle-kit push` (auth tables only, `precentingSets` unchanged)
2. Wave 1: Seed admin account via `scripts/seed-admin.ts` to get the admin `user.id`
3. Wave 2: Use `drizzle-kit generate` to produce a migration file for `precenting_sets`, manually edit SQL to add `UPDATE precenting_sets SET user_id = '<admin-id>'` between column add and NOT NULL constraint, run `drizzle-kit migrate`
4. Wave 3: Update `src/db/schema.ts` to reflect final shape (remove `precentorName`, add `userId` FK)
