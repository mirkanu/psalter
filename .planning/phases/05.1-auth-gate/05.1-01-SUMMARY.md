## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] auth.api.listUsers requires active admin session in seed context**
- **Found during:** Task 2 (seed-admin.ts first run)
- **Issue:** `auth.api.listUsers({ query: {} })` threw `UNAUTHORIZED / 401` — the admin plugin's listUsers endpoint validates a session cookie, which does not exist in a CLI seed script context
- **Fix:** Replaced with `db.query.users.findFirst({ where: eq(users.email, email) })` — raw Drizzle query bypasses auth layer for the idempotency check. Only the `createUser` call still goes through auth.api (which accepts server-side calls without a session per admin plugin design)
- **Files modified:** scripts/seed-admin.ts
- **Commit:** 3c3b974

**2. [Rule 3 - Blocking] NODE_ENV=production blocked devDependency installation**
- **Found during:** Task 1 (drizzle-kit install)
- **Issue:** VPS has `NODE_ENV=production` set globally; npm excludes devDependencies in production mode; drizzle-kit (devDependency) was not being installed despite being in package.json
- **Fix:** Prefixed all npm/drizzle-kit/vitest/tsx invocations with `NODE_ENV=development` during this session
- **Files modified:** None (runtime-only fix; no tracked file change needed)
- **Note:** This affects all future dev tasks on this VPS — always prefix with `NODE_ENV=development` when running dev tooling
