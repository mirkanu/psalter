## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Generated migration was full CREATE TABLE, not ALTER TABLE**
- **Found during:** Task 1
- **Issue:** `drizzle-kit generate` produced a CREATE TABLE migration (because the project previously used `drizzle-kit push` with no migration tracking, so drizzle-kit treated it as a fresh schema). Running it would fail with "table already exists".
- **Fix:** Replaced the generated SQL with manual ALTER TABLE statements (add nullable, UPDATE backfill, SET NOT NULL, ADD CONSTRAINT, DROP COLUMN). Applied via `drizzle-kit migrate` which also created the `drizzle.__drizzle_migrations` tracking table.
- **Files modified:** `drizzle/migrations/0000_cynical_ares.sql` (gitignored, not committed)
- **Commit:** ea81aa1 (schema.ts only)

**2. [Rule 1 - Bug] TypeScript errors from precentorName removal cascaded to 5 files**
- **Found during:** Task 3 (post-build tsc check)
- **Issue:** Removing `precentorName` from schema made `precentingSets.userId` required (NOT NULL). This broke: `api/precent/route.ts` (INSERT missing userId), `precent/page.tsx` (serialized precentorName), `precent/[id]/page.tsx` (serialized precentorName), `PrecentingSetList.tsx` (interface field), `SetDetail.tsx` (interface field + render)
- **Fix:** Updated all 5 files — removed precentorName, added userId where needed; api/precent POST now reads session and injects `session.user.id`; SetDetail display line removed (Plan 03 will re-add via user JOIN)
- **Files modified:** src/app/api/precent/route.ts, src/app/precent/page.tsx, src/app/precent/[id]/page.tsx, src/components/precent/PrecentingSetList.tsx, src/components/precent/SetDetail.tsx
- **Commit:** 10285a4
