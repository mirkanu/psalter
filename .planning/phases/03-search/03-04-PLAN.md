  {results.map((r) => (
    <div key={r.id} className="py-4 flex items-start gap-4 hover:bg-muted rounded transition-colors">
      <span className="w-10 shrink-0 font-mono text-sm tabular-nums text-muted-foreground">{r.id}</span>
      <div className="flex-1 min-w-0">

          data-snippet
          className="text-sm text-muted-foreground line-clamp-2 mt-1"

        <Badge variant="secondary" className="shrink-0 text-xs">{r.meter}</Badge>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → /search?q= | User-controlled query string crosses into server-side FTS execution |
| ts_headline output → browser DOM | PostgreSQL-generated HTML fragments rendered via dangerouslySetInnerHTML |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-07 | Tampering | /search?q= SQL injection | mitigate | fetchSearchResults uses Drizzle sql template tag — `${query}` is bound as a parameter, never interpolated. plainto_tsquery additionally sanitizes tsquery special characters. |
| T-03-08 | Tampering | ts_headline dangerouslySetInnerHTML XSS | accept | ts_headline output is generated by PostgreSQL from its own lexeme matching — it does not include user-originated HTML. Output is `<b>matched term</b>` fragments only. `data-snippet` scoping prevents style bleed, not XSS. Risk accepted: source is the DB, not user input. |
| T-03-09 | Tampering | Open redirect via ?q= | accept | /search does not perform any redirect. Form submission navigates to /search?q= — same page. No redirect surface. |
</threat_model>
