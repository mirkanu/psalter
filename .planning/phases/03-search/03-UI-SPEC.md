### Search Page (`/search`)

Route type: **dynamic** (runtime PostgreSQL full-text query on each request).

Layout:
- Page title: "Search" — 28px semibold, `mb-2`
- Subheading: "Find psalms by keyword across metrical lyrics and KJV text" — 16px regular, `text-muted-foreground`, `mb-6`
- Search form: full-width input + submit button, `flex gap-2`, `mb-8`
  - Input: shadcn `Input`, `placeholder="Search psalms…"`, `type="search"`, `name="q"`, `aria-label="Search psalms"`, full flex width
  - Button: shadcn `Button`, variant `default`, label "Search" (text, not icon-only — accessibility), lucide `Search` icon 16px to the left of the label
- Results area: conditional on `?q=` param presence

Result list — when results exist:
- Results count label: "{N} results for "{query}"" — 14px, `text-muted-foreground`, `mb-4`
- List: `divide-y divide-border`, no card wrapper — clean list rows
- Each result row: `py-4 flex items-start gap-4`, min-height 44px
  - Left: psalm number — 14px Geist Mono, `text-muted-foreground`, `w-10 shrink-0 tabular-nums`
  - Center: psalm first line — 16px semibold linked to `/psalms/[id]`, then snippet on line below — 14px regular `text-muted-foreground`, `line-clamp-2`, `ts_headline` output (raw HTML from PostgreSQL — render with `dangerouslySetInnerHTML`; `<b>` tags from `ts_headline` styled as `font-semibold`)
  - Right: meter badge — shadcn `Badge`, variant `secondary`, `shrink-0`
- Row hover: `hover:bg-muted` transition

Empty state — query submitted, zero results:
- Heading: "No psalms found" — 20px semibold
- Body: "No results for "{query}". Try different words, or browse psalms by topic." — 16px, `text-muted-foreground`
- Link: "Browse topics" → `/explore` — inline text link, `text-primary underline-offset-4 hover:underline`

Empty state — no query yet (page loaded without `?q=`):

- Heading: "Search the Scottish Psalter" — 20px semibold

## Interaction Contracts

### Search form submission
- Form `method="GET"` action="/search" — browser navigates to `/search?q={value}` on submit
- Enter key in input triggers submit natively (standard form behaviour)
- No live-as-you-type requests — one DB call per explicit submit
- After navigation, input is pre-populated from `searchParams.get('q')` on the server component

### Matched text highlight
- `ts_headline` returns fragments with `<b>` tags wrapping matched terms
- Render via `dangerouslySetInnerHTML` on the snippet `<span>`
- Apply global CSS: `[data-snippet] b { font-weight: 600; }` — no inline risk, no XSS surface (PostgreSQL output only, not user-originated HTML)

### Explore taxonomy expand (Nave's Topics)
- Default: show top 24 topics by psalm count
- "View all {N} topics" button below grid: renders remaining items inline (no route change) using `useState(false)` toggle
- Button text toggles: "View all {N} topics" → "Show fewer"

### Explore navigation
- All taxonomy item links are standard `<Link>` components — Next.js prefetch on hover (default, do not disable)
- Row hover state: `hover:bg-muted` — CSS only, no JS

### Tunes meter filter
- `Select` `onValueChange` → `router.replace('/tunes?meter=' + value, { scroll: false })`
- "All Meters" option sets meter param to `undefined` (remove param from URL)
- Filter state initialised from `useSearchParams()` on mount
- No server round-trip — all tunes passed from RSC, filtered in `TuneGrid` client component

### Static rendering
- `/explore`, `/explore/topics/[slug]`, `/explore/naves/[slug]`, `/explore/messianic`, `/explore/authors/[author]` — all static via `generateStaticParams`
- `/search` — dynamic (runtime full-text query); no `generateStaticParams`
- `/tunes` — remains static for initial shell; `TuneGrid` filters client-side

## Slug Strategy

Source: CONTEXT.md deferred this to Claude's discretion.

Decision: use **slugified name** for Topics and Nave's Topics (not DB id).

Rationale: meaningful URLs that precentors and congregation members can read and share.

Slug function (apply at data-fetch time, not render time):
```
slug = name.toLowerCase().replace(/['']/g, '').replace(/\s+/g, '-').replace(/[^a-z0-9-]/g, '').replace(/-+/g, '-').trim('-')
```

Apply consistently in both `generateStaticParams` and link generation. Store no slug column in DB — derive at query time.

For Authors: use `encodeURIComponent(author)` as the URL segment — author values may contain spaces and punctuation; URL-encoding is safer than slugification for unknown free-text values.

---

## Pagination Strategy

Source: CONTEXT.md deferred this to Claude's discretion.

Decision: **no pagination in Phase 3**. Rationale:
- Psalm corpus is 150 psalms. No taxonomy listing will exceed 150 rows.
- Nave's Topics list may be large (hundreds of topics). For the `/explore` hub, cap display at 24 + expand toggle. On `/explore/naves/[slug]` result pages, show all matching psalms (≤150).
- Full-text search results: show all results up to a hard cap of 50 rows (PostgreSQL `LIMIT 50`). Add result count label so users know the cap.
