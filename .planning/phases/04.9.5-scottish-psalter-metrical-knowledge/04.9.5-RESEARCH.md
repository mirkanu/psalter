## Summary

This is a **doc-only research-meta phase**. No code. The deliverable of phase 4.9.5 is `.planning/research/scottish-psalter-structure.md`, sibling to the existing `tonic-solfa-notation.md`. The job of *this* RESEARCH.md is to surface what the planner needs in order to plan the production of that doc.

Three concrete things to know going in:

1. **The data-driven meter subset is small and tractable.** A single SQL query against the live PostgreSQL database (verified during this research) returns the complete enumeration: 5 named meters in `tunes` (CM, SM, "LM (long meter, 88 88)", 76 76 D, 87 87, 66 66, 66 66 88, 10 10 10 10 10) and 6 in `psalm_versions` (the same set minus 76 76 D and 66 66, plus 66 66 D). 14 tunes carry no meter label. The doc must cover these explicitly.
2. **DCM is structurally absent from the data label set but operationally present.** No tune or psalm_version is tagged "CMD" or "DCM". DCM appears only as: (a) the 76 76 D tunes (Aurelia, Rutherford, Webb) used against a "CM" psalm versification (Psalm 119:153-160 ↔ Aurelia is the canonical example in the live data); (b) potentially long-ABC tunes that are double-length but tagged "CM". This is a primary research finding the doc must resolve — *how is DCM identified given the data labelling?*
3. **The pattern doc (`tonic-solfa-notation.md`) is ~200 lines, dense, table-heavy, example-driven.** The new doc should match that shape: section headings → tables for taxonomy → inline worked examples → reference appendix. Not prose-heavy.

**Primary recommendation:** Plan as two plans per CONTEXT D-claude-discretion. Plan 1 = briefing capture + research questions + first research pass + working draft. Plan 2 = review/revision cycles + sign-off. Include a Wave-0-style data-inventory step in Plan 1 that runs the SQL queries verified below and pastes the actual result into the doc as the "data-driven subset" reference table.

### Critical structural finding: no explicit DCM/CMD label exists in the data

The data labelling scheme uses only `CM` for common-meter. There is no `CMD`, `DCM`, `8.6.8.6 D`, or similar marker. DCM presence is **inferred** in two ways:

1. **Cross-meter pairing.** Psalm 119:153–160 (lyric meter = `CM`) is paired in `psalm_version_tunes` with Aurelia (tune meter = `76 76 D`). This is the only non-matching pairing of its kind in the current pairings table that suggests double-length tune ↔ paired CM stanzas behaviour — though Aurelia is 76 76 D not CMD strictly, so it sets *eight* shorter lines against *eight* CM lines (two CM stanzas). This is the cleanest live data example of "double-meter tune sung against two single-meter stanzas".
2. **ABC notation length.** Some `CM`-tagged tunes may in fact be CMD with twice the bar count. Spot-check: Crimond ABC = 180 chars (~4 phrases, CM); Aurelia = 250 chars (~8 phrases, double). The planner should include a Wave-0 SQL check in Plan 1 to scan all CM-tagged tunes for length outliers — the doc may need to call out specific tunes that are mis-labelled or doubled in practice.
