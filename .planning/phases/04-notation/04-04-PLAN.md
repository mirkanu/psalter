Current fetchTuneDetail (src/db/queries/tunes.ts) — does NOT yet include lyrics:

```typescript
export const fetchTuneDetail = cache(async function fetchTuneDetail(id: number) {
  return db.query.tunes.findFirst({
    where: eq(tunes.id, id),
    with: {
      psalmVersionTunes: {
        with: { psalmVersion: { with: { psalm: true } } },  // ← psalmVersion only joins psalm, not its own columns
      },
      tuneMoods: { with: { mood: true } },
    },
  })
})
```

In Drizzle, `with: { psalmVersion: { with: { psalm: true } } }` returns ALL columns of psalmVersion by default plus the joined psalm. So `psalmVersion.lyrics` is already retrievable IF the schema column is named `lyrics`. The fix is to make this explicit and confirmed: switch to `with: { psalmVersion: { columns: { id: true, lyrics: true }, with: { psalm: true } } }` to be deterministic about what comes back, or — equivalently — leave the implicit all-columns behaviour and just consume `psalmVersion.lyrics` in the page. Use the explicit `columns` form to make the contract clear and avoid over-fetching.

Verse 1 is the first stanza of `lyrics` (already embedded in ABC w: field by Plan 02). Verses 2+ are stanzas[1..end] after splitting on double-newline:
