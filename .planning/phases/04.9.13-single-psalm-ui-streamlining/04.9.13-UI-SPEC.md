# Phase 04.9.13 — UI Design Contract

> Visual and interaction contract for Single Psalm UI Streamlining. Inherits all tokens and patterns from Phase 04.9.3 (LOCKED) and Phase 04.9.4 (LOCKED). Only delta decisions are recorded here.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn |
| Preset | base-nova (style), neutral (base color), CSS variables on |
| Component library | Radix (via shadcn) |
| Icon library | lucide-react |
| Font | Geist Sans (existing `next/font` setup) |

Already installed shadcn primitives reused: `button`, `sheet`, `dialog`, `popover`, `select`, `separator`, `badge`, `tooltip`, `skeleton`. Popover is the only newly activated primitive this phase — it was already installed but not yet used.

## What This Phase Changes

This is a STREAMLINING phase — targeted changes to existing components, not a redesign.

| # | Change | Component(s) | Delta |
|---|--------|-------------|-------|
| 1 | Gear Drawer → Gear Popover | `GearDrawer` → `GearPopover` | Sheet → Popover; main toggle (Music Notes / Lyrics Only) + conditional sub-toggles; "Restart tour" retained; "About this psalm" collapsed into "Study" button |
| 2 | Player bar narrows + right-aligns on desktop | `PlayMiniBar` | Narrower layout; abc ↔ SoundCloud toggle with localStorage; "lyrics may not match" disclaimer; applies to both `/psalms/[id]` and `/tunes/[id]` |

## Component Inventory (Delta)

### 1. `GearPopover` (replaces `GearDrawer`)

**Trigger:** Gear icon in the glass bottom-bar (unchanged trigger location).

**Primitive:** shadcn `Popover` anchored to the gear button.

**Popover content anatomy (vertical stack, no separators inside popover — popover has its own border):**

```
┌──────────────────────────────────────────┐
│  Main toggle (radio, mutually exclusive) │
│  ┌────────────────────┬────────────────┐  │
│  │  Music Notes       │  Lyrics Only   │  │
│  └────────────────────┴────────────────┘  │
│                                          │
│  Sub-toggles (conditional, only in Staff)│
│  [Staff] [Solfège]    ← only if Staff   │
│  [Split-leaf] [Inline] ← only if Staff  │
│                                          │
│  ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─  │
│  [ Study ]             ← text button    │
│  [ Restart tour ]      ← text button    │
└──────────────────────────────────────────┘
```

**Popover sizing:**
- Width: `w-72` (288px) — enough for sub-toggle rows without wrapping
- Max height: `max-h-[480px]` with scroll if content overflows
- Padding: `p-4` (16px — the `md` scale token) inside the Popover content
- Position: `align="end"` so the popover right-aligns with the gear button
- Side: `side="top"` so it opens UP from the gear button (avoids covering the stanza indicator)

**Main toggle (always visible):**
- Two options: "Music Notes" (renders live abcjs notation) and "Lyrics Only" (renders plain stanza text)
- Rendered as a segmented control (two buttons side by side, equal width)
- Active state: `bg-foreground text-background` (inherits accent pattern from 04.9.3)
- Inactive: `hover:background-muted text-muted-foreground`
- Height: 40px each
- This replaces the current Staff / Lyrics / Solfège three-way radio group in the gear drawer

**Sub-toggles (conditional — only visible when Main toggle = "Music Notes"):**

Sub-toggle A — Notation type:
- Label row: "Notation:" (12px `text-muted-foreground`)
- Two options: "Staff" (lucide `Music`) / "Solfège" (lucide `FileImage`)
- Rendered as icon buttons (32×32, compact)
- Hidden when Main toggle = "Lyrics Only"

Sub-toggle B — View layout (only for psalm pages, not tune pages):
- Label row: "Layout:" (12px `text-muted-foreground`)
- Two options: "Split-leaf" (lucide `Columns2`) / "Inline" (lucide `Rows2`)
- Rendered as icon buttons (32×32, compact)
- Hidden when Main toggle = "Lyrics Only"
- Hidden on `/tunes/[id]` (tune pages render only notation, no layout choice needed)
- Default: "Inline" (matches current default; "Split-leaf" is experimental)

**Divider:** 1px `<Separator />` between the main toggle block and the action buttons below.

**"Study" button:**
- Full-width, h-10, text-left, `text-muted-foreground` → `hover:bg-muted`
- Label: "Study" (14px regular)
- Icon: lucide `BookOpen` (16px, left side)
- Hover: `hover:bg-muted`
- Tapping: closes the popover and opens the existing `/psalms/[id]/study` surface (the legacy 7-tab panel) via the existing `studyHref` prop/metadata route
- This collapses the current "About this psalm" section from the gear drawer into a single launch point

**"Restart tour" button:**
- Identical styling to "Study" button — full-width, h-10, text-left
- Label: "Restart tour" (14px regular)
- Icon: lucide `HelpCircle` (16px, left side)
- Tapping: closes popover, calls `onRestartTour()` (identical behavior to current GearDrawer)

**State machine:**
- Main toggle = "Music Notes" → viewMode = 'staff' or 'solfege' (depending on sub-toggle A)
- Main toggle = "Lyrics Only" → viewMode = 'lyrics' (sub-toggles hidden)
- Sub-toggle A Staff → viewMode = 'staff'; Sub-toggle A Solfège → viewMode = 'solfege'
- Sub-toggle B Split-leaf → layout flag = 'split-leaf'; Inline → layout flag = 'inline'
- The popover does NOT persist its own state — it reflects `viewMode` + layout flag from the parent (`SingMode`)
- On open, the popover re-reads the current `viewMode` to sync toggle positions

**Popover open/close behavior:**
- Opens: shadcn default Popover animation (~150ms fade + scale from anchor)
- Closes: on any toggle selection (immediately, no 120ms delay — the toggle state is the feedback), on outside click, on Escape
- Focus: first interactive element in popover receives focus on open; focus returns to gear button on close
- `aria-label` on popover trigger (gear button): "Settings" (unchanged from 04.9.4)

### 2. `PlayMiniBar` — Desktop Right-Align + Narrower

**Current state (04.9.4):** Full-width bottom bar, h-44px, left/center/right layout with both abc controls inline.

**Delta:**

**Desktop (≥768px):**
- The play mini-bar right-aligns: `md:ml-auto md:max-w-md md:w-auto` (narrows to content width, right side only)
- Height: unchanged at 44px
- The bar anchors to bottom-right: `md:right-4 md:bottom-[56px] md:rounded-lg md:border md:border-border/40 md:shadow-lg`
- Surface: `bg-background/90 backdrop-blur-md` (unchanged), but on desktop gains rounded corners and a border — it becomes a floating card, not a full-width strip
- This reserves the desktop center area for stanza navigation + turn indicator (which moves to the glass bottom-bar center on desktop)

**Mobile (<768px):** Unchanged from 04.9.4 — full-width bottom strip.

**abc ↔ SoundCloud toggle (new):**
- New slot appears in the mini-bar right edge (before the collapse button on desktop, after BPM controls on mobile)
- Two-state toggle: `abc` label (lucide `Music`) and a sound-wave indicator (lucide `Radio`)
- Button: icon-only, h-9 w-9, rounded
- Logic: when the tune has a `soundcloudUrl`, tapping swaps the AbcAudioControls for a compact SoundCloud embed (soundcloud iframe at h-10)
- When no `soundcloudUrl` exists: the toggle is hidden (no SoundCloud option)
- localStorage key: `psalter-audio-source` = `'abc' | 'soundcloud'` — persists user's choice across sessions
- Default: `'abc'` (when no localStorage value exists)

**"Lyrics may not match" disclaimer:**
- Renders below the SoundCloud embed (NOT for abc) as a 12px italic muted line: "Lyrics shown are metrical; recording may use a different text."
- Hidden in abc mode
- Hidden when no SoundCloud embed is active
- Only visible when `soundcloudUrl` is present AND user has switched to SoundCloud

**Removal of redundant "Play recording" button:**
- Previously the solfège/lyrics view rendered a "Play recording" button (TuneAudioPlayer inline)
- This phase removes that redundant standalone button — the PlayMiniBar toggle is the sole entry point for recorded audio
- TuneAudioPlayer still renders (embedded in PlayMiniBar via the SoundCloud toggle), but the standalone button above stanza list is gone

**Applied to both routes:**
- `/psalms/[id]`: PlayMiniBar renders as currently wired in SingingView
- `/tunes/[id]`: A new `PlayMiniBar` instance is wired into the page alongside the existing NotationRenderer — placed at the bottom of the score section, not fixed position (static within the page flow). Uses the same abc/soundcloud toggle.

### 3. Split-Leaf View Overhaul (NotationRenderer solfege/lyrics branch)

**Current state:** The solfège view renders a JPG at fixed width with stanza list below in a single scroll.

**Delta:**

**Full-width mobile image:**
- On mobile (<768px), the JPG renders at `w-full` (unchanged), but the parent container's `px-4` padding is REMOVED for the JPG specifically — the image sits flush to screen edges
- The JPG aspect ratio is preserved via `h-auto`
- Caption "Solfège score" (12px muted, centered) renders below the image

**Multi-page thumbnail + arrow navigation:**
- For tunes with more than one score page (staffPages.length > 1 OR solfegePages.length > 1):
  - Below the full-width main image, renders a horizontal thumbnail strip: `flex gap-2 overflow-x-auto py-2`
  - Each thumbnail: 80×100px, current page highlighted with `ring-2 ring-foreground`
  - Arrow nav: `ChevronLeft` / `ChevronRight` icon buttons at strip edges (44×44 tap targets)
  - Only visible when `pages.length > 1`
- Thumbnails are lazy-loaded via native `loading="lazy"` on `<img>`

**Stanza browser (no-scroll, separate from main notation scroll):**
- When in split-leaf mode (sub-toggle B = "Split-leaf"), the stanza list renders to the RIGHT of the notation on desktop (split column) and BELOW on mobile
- Desktop split-leaf: 2-column grid — notation left (60%), stanza list right (40%)
- Mobile split-leaf: stacked — notation top, stanza list below
- The stanza list has its own scroll container: `max-h-[60vh] overflow-y-auto` (desktop) or `max-h-80` (mobile)
- Scroll is INDEPENDENT from the notation area — scrolling stanzas does not scroll the score

**abc/jpeg toggle between image and lyrics:**
- Within split-leaf mode, sub-toggle A controls what shows in the left column:
  - "Staff" → abcjs SVG + stanza list right
  - "Solfège" → solfège JPG + stanza list right
- NotationRenderer receives `viewMode` from the parent (as currently wired via GlassBottomBar or GearPopover sub-toggle A)

**Remove redundant "Play recording" button:**
- In solfège and lyrics views, the standalone "Play recording" button (rendered by TuneAudioPlayer in the NotationRenderer solfege/lyrics branch) is REMOVED
- Rationale: the abc/soundcloud toggle in PlayMiniBar is the canonical audio entry point
- TuneAudioPlayer component itself is NOT deleted — just not rendered in these view modes anymore

### 4. Desktop Max-Width Constraint for `/psalms/[id]`

**Current state:** SingingView renders at full viewport width. Notation body constrains its own width but the page chrome does not.

**Delta:**
Wrap the `<main>` region of `/psalms/[id]` (specifically the SingingView page-level container) in a max-width constraint matching `/tunes/[id]`:

```tsx
// In psalms/[id]/page.tsx — wrap SingingView output
<div className="max-w-4xl mx-auto">
  <SingingView ... />
</div>
```

- `max-w-4xl` = 512px effective width (80 × 16 = 80rem = 1280px? No — Tailwind 4XL = 5rem = 80px prefix? Clarification: Tailwind `max-w-4xl` = 5rem = 80rem = 1280px). Matches `/tunes/[id]` exactly.
- Both `mx-auto` centers the content
- On wide desktop viewports (>1280px) the notation will NOT stretch beyond 1288px — matches the tune page reading width
- Mobile viewports (<1280px) are unaffected — the constraint only caps at the upper bound
- The glass bottom bar and top bar also respect this max-width (they are `fixed` but their content is constrained via `max-w-4xl mx-auto` on their inner wrapper)

**Implementation note:** The `fixed` positioning of the top bar and bottom bar means they already span the full viewport. To constrain their content width, add an inner wrapper: `<div className="max-w-4xl mx-auto flex items-center ...">` inside both `PsalmTopBar` and `GlassBottomBar`. The bars themselves remain full-width fixed elements; only the content inside is constrained.

## Interaction States

### Gear Popover

- **Open:** Popover opens upward from gear button (150ms fade + scale). First toggle receives focus.
- **Main toggle select:** Immediately applies viewMode change. Sub-toggles appear/disappear with a 100ms fade. Popover stays open so the user can also adjust sub-toggles.
- **Sub-toggle select:** Immediately applies viewMode/layout change. Popover stays open.
- **Study button:** Closes popover, navigates to `/psalms/[id]/study`.
- **Restart tour:** Closes popover, triggers tour (identical to current GearDrawer behavior).
- **Close on outside click:** Yes (shadcn default).
- **Close on Escape:** Yes (shadcn default).
- **Focus return:** Focus returns to gear button on close.

### PlayMiniBar Desktop Right-Align

- **Entry animation:** Unchanged from 04.9.4 — `translateY(100%)` → `translateY(0)`, 200ms ease-out.
- **Desktop positioning:** `fixed bottom-[56px] right-4 max-w-md w-auto rounded-lg shadow-lg` — floats above the glass bottom-bar on the right side.
- **Mobile positioning:** Unchanged — full-width strip at bottom.
- **abc ↔ SoundCloud toggle:** Tap swaps the audio source. AbcAudioControls unmounts, SoundCloud iframe mounts (or vice versa). 150ms crossfade.
- **localStorage persistence:** `psalter-audio-source` key. Read on mount, write on toggle. Two-effect pattern (separate restore-on-mount and persist-on-change effects) to avoid race conditions — same pattern as existing BPM persistence in AbcAudioControls.

### Split-Leaf View

- **Sub-toggle B change (Split-leaf ↔ Inline):** Notation area re-renders with new layout. 150ms fade transition between layouts.
- **Thumbnail tap:** Main image swaps to the selected page. Thumbnail gains `ring-2 ring-foreground`. 100ms crossfade.
- **Arrow nav:** `ChevronLeft` / `ChevronRight` cycle through pages. Disabled at boundaries (first page: left arrow `opacity-40 pointer-events-none`; last page: right arrow same).
- **Stanza scroll:** Independent scroll container. Does not affect notation position.

### General Tap Feedback

All buttons: `active:scale-[0.95] transition-transform duration-75`. Reduced motion: `motion-reduce:active:scale-100`. Inherits from 04.9.4.

## Accessibility

- **Gear popover trigger:** `aria-label="Settings"` (unchanged from 049.4 gear button).
- **Main toggle:** `role="radiogroup"` with `aria-label="View type"`. Each option is `role="radio"` with `aria-checked`.
- **Sub-toggle A:** `role="radiogroup"` with `aria-label="Notation type"`. Each option is `role="radio"` with `aria-checked`.
- **Sub-toggle B:** `role="radiogroup"` with `aria-label="Layout"`. Each option is `role="radio"` with `aria-checked`.
- **Study button:** `role="button"`, `aria-label="Open full study view"`.
- **Restart tour button:** `role="button"`, `aria-label="Restart the onboarding tour"`.
- **PlayMiniBar abc/sc toggle:** `role="button"`, `aria-label="Switch to SoundCloud"` or `aria-label="Switch to abc audio"` depending on current state.
- **Disclaimer text:** `aria-live="polite"` — announced when SoundCloud mode is activated.
- **Split-leaf thumbnails:** Each thumbnail is a `<button>` with `aria-label="Page {N} of {M}"`. Current page has `aria-current="true"`.
- **Reduced motion:** All transitions respect `prefers-reduced-motion: reduce` (opacity-only fallback, 100ms).
