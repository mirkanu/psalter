Built the four always-visible chrome components for the new mobile-first singing view (PsalmTopBar, TuneSubBar, PsalmSelectorSheet, TuneSwitcherSheet) plus a shared types.ts. ## What Changed

### types.ts (Task 1)
Re-exports `AlternateTune as TuneOption` and declares `TuneSwitcherSections { current, recommended, other }`. Resolves RESEARCH Open Q §1 by typing the three-bucket split as data the parent must provide (parent computes "Recommended" from `psalmVersionTunes` editorial join; "Other" = meter-matched alts not in that set).

### PsalmTopBar.tsx (Task 1)
- Sticky `top-0 z-30 bg-background/95 backdrop-blur` with `pt-[env(safe-area-inset-top)]`.
- Heights: `h-12 md:h-14 landscape:h-10`.
- Prev/next render as `<Link>` with `onClick={(e) => { e.preventDefault(); startTransition(() => router.push(...)) }}` so right-click / cmd-click still works while the primary click path stays inside the transition.
- Disabled state at Psalm 1 / Psalm 150: `<span aria-disabled="true" aria-label="Already at Psalm N">` with `opacity-40 pointer-events-none`.
- Keyboard handler on `window`: ArrowLeft/ArrowRight without modifiers; bails when the active element is `INPUT`, `TEXTAREA`, `SELECT`, or `isContentEditable`.
- `useTransition`'s `isPending` renders a 2px bar at the top edge of the bar — `absolute inset-x-0 top-0 h-0.5 bg-foreground`.
- Narrow viewport: `<360px AND psalmId >= 100` → "Ps N"; otherwise "Psalm N".
- All icon buttons are `min-h-11 min-w-11` (WCAG 2.5.5 AAA / Apple HIG 44px floor).

### TuneSubBar.tsx (Task 2)
- Sticky just below the top bar: `top-12 md:top-14 landscape:top-10 z-20 bg-muted/60 backdrop-blur`.
- Whole row is the tap target (one `<button>` spans the bar).
- Meter abbreviation: "Common Meter" → "C.M.", "Long Meter" → "L.M.", "Short Meter" → "S.M.", "Double Common Meter" → "D.C.M."; raw "CM"/"LM"/"SM"/"DCM" forms are expanded with dots; already-dotted forms pass through.
- Tune name uses `truncate font-semibold text-foreground` with `min-w-0` so it shrinks before the meter prefix or the pencil.
- Empty state renders `Tune: — Choose` with "Choose" underlined and bold.
- Markers: `data-singing-subbar`, `data-tune-name`.

### PsalmSelectorSheet.tsx (Task 2)
- `Sheet side="bottom"` with `h-[90dvh] max-h-[90dvh] flex flex-col`.
- `SheetTitle`: "Jump to psalm".
- Body wraps the existing `PsalmListingGrid` (named export, prop `psalms: PsalmRow[]`); inner scroll container has `-mx-4 px-4 pb-4` to keep the grid full-bleed inside the sheet's default padding.
- Marker: `data-psalm-selector-sheet`.

### TuneSwitcherSheet.tsx (Task 3)
- `Sheet side="bottom" max-h-[80dvh]`; `SheetTitle`: "Choose a tune".
- Three sections in order, each separated by `<Separator />`:
  1. **Current** — single highlighted row (`bg-foreground text-background ring-1 ring-foreground` + "Current" badge).
  2. **Recommended for {meterLabel}** — only renders if `sections.recommended.length > 0`; section header includes meter inline when provided.
  3. **Other tunes** — only renders if `sections.other.length > 0`.
- Empty messages:
  - No data at all: "No tunes available for this psalm."
  - Current present but no alternatives: "No other tunes available for this meter."
- `TuneRow` is a 48px button (`h-12 min-h-11`) with `data-tune-slug={tune.id}` (UAT script asserts on this).
- Selection: `router.replace(`${pathname}?${params.toString()}`, { scroll: false })` then `setTimeout(() => onOpenChange(false), 120)`.
- Markers: `data-tune-switcher-sheet`, `data-tune-slug`.
