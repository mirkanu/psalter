# Phase 04.9.3 Plan 04: FAB-Side Chrome (Audio + Metadata + FAB Sheet) Summary

Built the three FAB-side components that wrap the singing view's non-notation interactions: a standalone audio block extracted from AbcPlayer (`AbcAudioControls`), the About-this-psalm content block (`MetadataPanel`), and the bottom-sheet container that composes them with the View-mode radiogroup (`PsalmActionsFAB`). None are wired into a route yet — Plan 05 composes them inside SingingView.

## What Changed

### AbcAudioControls.tsx (Task 1)
- 'use client', renders an off-DOM hidden `<div>` (`position: absolute; left: -9999`) with `abcjs.renderAbc(...)` to produce a `visualObj` for synth init — independent of the on-screen NotationRenderer.
- Buttons: Play/Pause (toggle), Key (Select with semitone transpose -6..+6), BPM ± (40..200, step 5), Reset (visible only when transpose or bpm differ from defaults).
- Audio path: `new abcjs.synth.CreateSynth()` → `synth.init({ visualObj, soundFontUrl, midiTranspose })` → `synth.prime()` → `synth.start()` + `new abcjs.TimingCallbacks(...).start()`. `eventCallback(null)` (end of tune) stops synth and clears playing state.
- BPM persists to `localStorage` key `psalter-bpm` (shared with AbcPlayer); reset clears the key.
- Marker: `data-abc-audio-controls`.
- AbcPlayer.tsx UNCHANGED (`git diff HEAD~3 HEAD -- src/components/AbcPlayer.tsx` is empty).

### MetadataPanel.tsx (Task 2)
- Renders psalm.bibleTitle (label-style), psalm.author, psalm.book, meter, psalmTopics (Badge list), sectionHeadings (Divisions list with `v.{verseStart}` prefix).
- Closing link: `SheetClose render={<Link href={studyHref}>Open full study view →</Link>}` — releases the sheet's focus trap before navigation.
- Markers: `data-singing-metadata`, `data-open-study-link`.

### PsalmActionsFAB.tsx (Task 3)
- FAB trigger: 56x56 circular button (`h-14 w-14 rounded-full bg-foreground text-background shadow-lg`) fixed at `right-4` + `bottom: max(1rem, env(safe-area-inset-bottom))`. Tactile feedback: `active:scale-95`.
- Sheet: `side="bottom"`, `max-h-[80dvh] flex flex-col`. SheetHeader is `sr-only` (visually hidden title "Psalm actions"); inner sections use their own visible headers per UI-SPEC.
- **Section A (View)**: `role="radiogroup"` with three `role="radio"` buttons (Staff / Lyrics only / Solfège). Active state uses the reserved accent (`bg-foreground text-background`). Each click fires `onViewModeChange(mode)` then `setTimeout(() => setOpen(false), 120)` so the user sees the active state register before the sheet auto-closes.
- **Section B (Audio)**: omitted entirely when `abcForAudio` is null — silent empty state per UI-SPEC.
- **Section C (About this psalm)**: "About this psalm" h3 + `<MetadataPanel/>`. Section ends with the SheetClose-wrapped study link.
- Markers: `data-singing-fab` (trigger), `data-singing-fab-sheet` (sheet content), `data-view-option={mode}` (per radio button).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] base-ui Dialog primitive does not accept Radix `asChild`**
- **Found during:** Task 2 (first `npm run build` after writing MetadataPanel)
- **Issue:** `Type error: Property 'asChild' does not exist on type 'IntrinsicAttributes & DialogCloseProps'.` — shadcn `sheet.tsx` in this repo is built on `@base-ui/react/dialog`, not Radix Dialog. base-ui uses a `render` slot prop pattern instead of `asChild`.
- **Fix:** Switched MetadataPanel's SheetClose from `<SheetClose asChild><Link/></SheetClose>` to `<SheetClose render={<Link/>}/>`, and PsalmActionsFAB's SheetTrigger from `<SheetTrigger asChild><button/></SheetTrigger>` to `<SheetTrigger render={<button/>}/>`. Semantically equivalent (composes the close/trigger behaviour onto the supplied element). The `data-open-study-link` marker stays on the inner Link so Plan 06 UATs are unaffected.
- **Files modified:** src/components/singing/MetadataPanel.tsx, src/components/singing/PsalmActionsFAB.tsx
- **Commits:** 85388b7, f194836
- **Plan acceptance impact:** Plan's must_haves pattern `SheetClose asChild` is no longer literally present; the equivalent `SheetClose\s+render=` and `SheetTrigger\s+render=` patterns express the same focus-trap-release semantics. The plan's `<verify>` grep gates do NOT check for the literal `asChild` string, so all acceptance grep checks still pass.

**2. [Rule 3 - Blocking] Inner sheet content padding adjusted**
- **Found during:** Task 3
- **Issue:** Plan suggested `px-1` for the scroll container inside SheetContent. base-ui's SheetContent has no built-in body padding (the shadcn wrapper only pads SheetHeader/SheetFooter), so `px-1` would have produced a too-tight gutter.
- **Fix:** Used `px-4 pb-4` on the inner scroll container — matches the 16px gutter UI-SPEC §Spacing prescribes for sheet section padding.
- **Files modified:** src/components/singing/PsalmActionsFAB.tsx
- **Commit:** f194836
