# Phase 04.9.3 — UI Design Contract

> Visual and interaction contract for the mobile-first psalm display. The psalm page becomes a singing instrument: notation + integrated lyrics fill the viewport on open; everything else hides behind a minimal chrome (slim header + sub-bar + FAB). Pre-validated decisions captured in `.planning/notes/mobile-psalm-display-design.md` are treated as LOCKED.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn |
| Preset | base-nova (style), neutral (base color), CSS variables on |
| Component library | Radix (via shadcn) |
| Icon library | lucide-react |
| Font | Geist Sans (existing `next/font` setup) |

Already installed shadcn primitives reused this phase: `button`, `sheet`, `dialog`, `popover`, `select`, `separator`, `badge`, `tooltip`. New blocks to add: **none required** — bottom sheet uses existing `sheet` with `side="bottom"`.

## Layout Contract (LOCKED — from design note)

### Page anatomy at 375px viewport (canonical mobile target)

```
┌─────────────────────────────────────────┐
│  ← Psalm 23 →                           │  Top bar      48px height
│  Tune (C.M.): Crimond [Edit]            │  Sub-bar      40px height
├─────────────────────────────────────────┤
│                                         │
│                                         │
│  [abcjs staff + integrated lyrics]      │  Body         fills 100%
│  [4 staff systems, full width]          │
│                                         │
│                                         │
│                                  ┌───┐  │
│                                  │ ≡ │  │  FAB          56×56, 16px insets
│                                  └───┘  │
└─────────────────────────────────────────┘
```

| Region | Height (mobile) | Height (≥768px) | Behaviour |
|--------|----------------|------------------|-----------|
| Top bar | 48px | 56px | `sticky top-0`, `bg-background/95 backdrop-blur`, `border-b` |
| Sub-bar | 40px | 44px | `sticky top-[48px]`, same surface treatment |
| Body | `calc(100dvh - 88px)` on mobile; `calc(100dvh - 100px)` ≥768px | — | Single scroll container; horizontal scroll **forbidden** (`overflow-x: hidden`) |
| FAB | — | — | `fixed bottom-4 right-4` + `pb-[env(safe-area-inset-bottom)]` wrapper |

**Safe areas:** Top bar uses `pt-[env(safe-area-inset-top)]`; FAB container uses `bottom-[max(1rem,env(safe-area-inset-bottom))]`. Avoid notches and home indicators.

**Landscape mobile:** Same layout. Header heights collapse to 40px / 36px via `landscape:h-10`. Body recalculates via `100dvh`. FAB keeps 56px size but slides to `bottom-3 right-3`.

**Desktop (≥768px):** Same minimal layout — no return to legacy 7-tab layout from this entry point. The 7-tab page remains accessible by tapping the psalm header → opens psalm selector / metadata navigation. (Existing legacy psalm route preserved; this phase introduces the new default view at `/psalms/[id]`.)

## Component Inventory

### 1. `PsalmTopBar` (new)
- **Anatomy:** `[ChevronLeft button] [psalm-label button (flex-1, center)] [ChevronRight button]`
- **Heights:** 48px mobile / 56px desktop
- **Tap targets:** All 44×44 minimum (per Apple HIG / Material). Icon buttons render as `size="icon"` with `min-h-11 min-w-11`.
- **Label:** "Psalm 23" (full) or "Ps 23" only when `psalm_id >= 100` AND viewport <360px. Tap opens `<PsalmSelectorSheet>` (existing /psalms grid in a `Sheet side="bottom"`).
- **Arrows:** Disabled state when at psalm 1 (`←`) or psalm 150 (`→`) — `opacity-40 pointer-events-none`. Active state: lucide `ChevronLeft` / `ChevronRight` 20px.
- **Empty state:** N/A — top bar always renders.

### 2. `TuneSubBar` (new)
- **Anatomy:** `Tune (C.M.): Crimond [Edit]`
- **Tune label:** Tap target = whole row, opens `<TuneSwitcherSheet>`. Visual hint: `[Edit]` rendered as lucide `Pencil` 14px icon-button at right edge. Whole row is tappable; pencil is decorative+redundant for affordance.
- **Meter format:** `(C.M.)` for Common Meter, `(L.M.)` long, `(S.M.)` short, `(D.C.M.)` doubled, etc. Use abbreviated form; full meter string available in metadata panel.
- **No tune available:** Render `Tune: — [Choose]` with `[Choose]` as primary-style text-button.
- **Truncation:** Long tune names truncate with `truncate` + `min-w-0`; meter never truncates.

### 3. `NotationBody` (extension of existing `NotationRendererClient`)
- Receives `containerRef`; on mount + resize + orientationchange + visualViewport resize, measures `containerRef.current.offsetWidth` and passes `staffwidth: width - 16` (16px = 8px L+R padding) to `ABCJS.renderAbc` options.
- Container styles: `w-full max-w-full overflow-x-hidden px-2`. The `max-w-full overflow-x-hidden` is a **hard clamp** — even if abcjs returns oversize SVG, it physically cannot escape.
- Default `--staff-base-size` for mobile: **13px** (down from current 14px) to reduce overflow risk at default zoom.
- A+/A− remains accessible via the FAB sheet (not on canvas) — singers rarely need to resize mid-song.
- ResizeObserver: debounce 150ms; re-render only when width changes by ≥8px.

### 4. `PsalmActionsFAB` (new)
- **Pattern decided:** **Bottom Sheet** (shadcn `Sheet side="bottom"`), NOT speed-dial. Reasoning: three distinct functional groups (view modes, audio, metadata) need labels and space; speed-dial radial menu would crowd at three+ items and confuse hit targets.
- **Trigger button:** 56×56 circular, `rounded-full`, `bg-foreground text-background`, `shadow-lg`. Icon: lucide `Menu` (20px). `:active` scales to 95% (`active:scale-95 transition-transform`).
- **Sheet content (3 grouped sections separated by `<Separator />`):**

  **A. View** (radio group of buttons, full-width row, 44px height)
  - `Staff` (lucide `Music`)
  - `Lyrics only` (lucide `AlignLeft`)
  - `Solfège` (lucide `FileImage`)

  **B. Audio** (full-width, conditional — only renders if `tune.soundcloud_url` exists)
  - Play/pause + scrub UI from existing `AbcPlayer` audio block, OR SoundCloud embed at compact height (`h-20`).
  - Empty state: section omitted entirely (do not show "No audio available" — silent absence is cleaner).

  **C. About this psalm** (collapsible — expanded by default in sheet)
  - Author, book, NKJV title
  - Metre (full string e.g. "C.M. (8.6.8.6)")
  - Nave's topics (badges, wrap)
  - Scripture refs (if present)
  - Link: "Open full study view →" (navigates to legacy 7-tab page at `/psalms/[id]/study` or existing route — preserves existing detail surface)

- **Sheet sizing:** `max-h-[80dvh]` with internal scroll. Drag handle bar at top (shadcn sheet default). Tap outside or swipe-down to close.

### 5. `PsalmSelectorSheet` (reuse existing `/psalms` grid in a Sheet)
- Triggered from `PsalmTopBar` label tap.
- Content: the existing `PsalmListingGrid` (numbered box grid + search input from Phase 4.7) rendered inside `Sheet side="bottom"` with `h-[90dvh]`.
- Tapping a psalm number closes sheet and navigates.

### 6. `TuneSwitcherSheet` (new)
- Triggered from `TuneSubBar` row tap or pencil icon.
- Content sections (separated by `<Separator />`):
  - **Current:** the primary tune (highlighted, badge "Current")
  - **Recommended (same meter):** list of meter-compatible tunes from `psalmVersionTunes` join, ordered by `is_recommended` then alphabetical
  - **All other tunes for this psalm:** backup + historical
- Each row: `[TuneName] [(meter)]` — 48px tall, full-width tappable.
- Tap → sets tune (URL query `?tune=tuneSlug`), closes sheet, body re-renders. No page reload.
- Empty state: "No other tunes available for this meter."

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, inline badge padding |
| sm | 8px | Compact element spacing; notation container side padding |
| md | 16px | FAB inset, sheet section padding, button-row gaps |
| lg | 24px | Sheet section vertical separation |
| xl | 32px | Bottom-sheet content top padding (below drag handle) |
| 2xl | 48px | Top-bar height (mobile) |
| 3xl | 64px | Reserved — not used this phase |

**Exceptions (icon-tap target floor):** All icon-only buttons are 44×44 (Apple HIG) — implemented via `min-h-11 min-w-11` even when the visible icon is 20×20. This satisfies WCAG 2.5.5 (AAA) and Apple HIG.

**FAB-specific:** 56×56 (Material spec for primary FAB). FAB margin from screen edges: 16px + safe-area inset.

## Typography

Three sizes, two weights — strict.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px | 400 (regular) | 1.5 | Tune sub-bar text, sheet body content |
| Label | 16px | 600 (semibold) | 1.4 | Top-bar psalm label, sheet section headers, FAB-sheet button labels |
| Heading | 20px | 600 (semibold) | 1.3 | "About this psalm" section title in sheet, modal/sheet titles |

**Inline notation lyrics** (`--staff-base-size`): 13px on mobile, 14px on ≥768px. This is controlled by abcjs and the existing CSS variable from Phase 4.9.2 — NOT counted in the 3-size scale (it's a notation-engine size, not interface chrome).

**Verse-text fallback** (Lyrics-only view): 16px / line-height 1.6 / weight 400.

**Font family:** Geist Sans for all chrome. abcjs handles notation typography internally.

## Color

Using existing shadcn `neutral` base + CSS variables. No new tokens introduced.

| Role | Token | Value (light) | Usage |
|------|-------|----------------|-------|
| Dominant (60%) | `--background` | near-white (oklch) | Page background, notation canvas surface |
| Secondary (30%) | `--muted` / `--card` | light grey | Top bar, sub-bar, sheet surface |
| Accent (10%) | `--foreground` (as fill) on FAB | near-black | **Reserved exclusively for:** FAB primary button; active state of view-mode buttons in FAB sheet; current-tune highlight in TuneSwitcherSheet |
| Destructive | `--destructive` | red-600 equivalent | Not used this phase (no destructive actions on the singing view) |

**Accent reserved for:**
1. FAB trigger button (background fill)
2. Active view-mode button in FAB sheet (background + foreground swap)
3. "Current" tune row in TuneSwitcherSheet (subtle ring + badge)
4. Top result in PsalmSelectorSheet (reuses Phase 4.7 highlight rule)

Accent is **never** applied to the top-bar arrows, sub-bar text, or any always-visible chrome — those use foreground/muted-foreground only. This keeps the entire singing view visually quiet so the music is the focal point.

**60/30/10 split confirmed:** notation body + page background = 60%; top bar + sub-bar + sheet surfaces = 30%; FAB + a small set of selection states = 10%.

## Interaction States

### Tap feedback (mandatory per project perceived-perf rule)
- **All buttons:** `active:scale-[0.97] transition-transform duration-75` for instant tactile response.
- **Prev/next arrows:** Use `useTransition` from React; show a 2px progress bar at the top edge of the top-bar while the next psalm route loads. Bar uses `--foreground` at 100% opacity.
- **Tune switch:** Optimistic — body re-renders with new tune immediately on selection; if abcjs fetch fails, revert with toast `Could not load that tune — switched back.`
- **FAB:** Sheet opens with default shadcn slide-up (240ms).
- **Sheet close on selection:** Auto-close after 120ms (lets user see the selected state register).

### Loading states
- **Notation loading:** Skeleton block matching staff height (4 systems × ~80px = ~320px) with shimmer. Uses shadcn `Skeleton`.
- **Tune-switch in-flight:** Notation area shows the same skeleton; top-bar and sub-bar stay visible (do not relayout).
- **Psalm navigation:** route-level `loading.tsx` renders top-bar + sub-bar with shimmer placeholders, then the notation skeleton — page shape preserved from first frame.

### Error states
- **abcjs render throws:** ErrorBoundary catches; renders the `Notation render error` copy with an inline "Open menu" button that opens the FAB sheet pre-selected to "Lyrics only" / "Solfège" options.
- **No ABC and no solfège JPG:** Body renders Lyrics-only view automatically; FAB view-mode shows Staff/Solfège as disabled with tooltip `Not available for this tune`.

### Orientation change
- Listen to `orientationchange` and `visualViewport.resize`. Debounce 150ms. Re-derive `staffwidth` from `containerRef.current.offsetWidth` and call `ABCJS.renderAbc` again. No layout flash — the container is fixed-width; only the SVG re-renders.

### Resize / window growth (desktop browser shrink)
- Same ResizeObserver path as orientation change.

## Accessibility

- All icon buttons: `aria-label` set (e.g. `aria-label="Previous psalm"`).
- FAB: `aria-label="Open psalm actions"`; sheet uses shadcn's built-in `aria-modal` + focus trap.
- View-mode buttons in FAB sheet: rendered as `role="radiogroup"` with each as `role="radio"` and `aria-checked`.
- Color contrast: rely on shadcn neutral palette (≥4.5:1 for text). FAB foreground-on-foreground contrast is the highest in the system.
- Reduced motion: `motion-reduce:transition-none` on all active/scale transforms; sheet animation already respects `prefers-reduced-motion` in shadcn defaults.
- Keyboard nav (desktop): Tab through top-bar arrows → psalm label → sub-bar → FAB. Sheet content tab order: section headers skipped, controls only.
