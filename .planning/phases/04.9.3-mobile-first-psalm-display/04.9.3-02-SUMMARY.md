# Phase 04.9.3 Plan 02: NotationRenderer Controlled-State + Chromeless Refactor Summary

Inverts NotationRenderer from purely-uncontrolled to optionally-controlled (viewMode + baseSize), adds a `chromeless` mode that suppresses the internal controlBar and disables fullscreen entry, and lowers the chromeless-mobile default `--staff-base-size` to 13 per UI-SPEC §3 — all without regression to existing call sites on `/psalms/[id]`, `/psalms/[id]/study`, or `/tunes/[id]`.

## What Changed

### Props interface (Task 1)

Four new optional fields added to `NotationRendererProps`:

```ts
viewMode?: ViewMode                          // controlled view mode
baseSize?: number                            // controlled notation size
onBaseSizeChange?: (size: number) => void    // size-change callback
chromeless?: boolean                         // suppress internal chrome
```

All fields optional; existing call sites compile and render unchanged.

### Component body (Task 2)

- Destructure adds `viewMode: viewModeProp`, `baseSize: baseSizeProp`, `onBaseSizeChange`, `chromeless = false`.
- `const allowFullscreen = !chromeless` at top of body.
- New constant `MOBILE_DEFAULT_SIZE_CHROMELESS: BaseSize = 13` added alongside (NOT replacing) existing `MOBILE_DEFAULT_SIZE: BaseSize = 24`.
- `normalSize` and `fullscreenSize` initializers branch on `chromeless`:
  - chromeless + `innerWidth < 768` → 13
  - !chromeless + `innerWidth < 480` + portrait → 24 (legacy preserved)
  - else → 14
- `isViewModeControlled = viewModeProp !== undefined`; internal state renamed to `viewModeInternal`/`setViewModeInternal`; the exposed `viewMode` is a ternary; `setViewMode` is a wrapper that fires `onViewModeChange` in both modes and only mutates internal state when uncontrolled.
- Persistence: viewMode useEffect now early-returns when controlled. The viewMode-notify useEffect is removed (redundant — wrapper handles it).
- `isBaseSizeControlled = baseSizeProp !== undefined`; `baseSize` resolves from `baseSizeProp ?? baseSizeUncontrolled` when controlled, else from `isFullscreen ? fullscreenSize : normalSize`. `setBaseSize` resolves updater→absolute then routes to `onBaseSizeChange` (controlled) or the appropriate internal setter (uncontrolled).
- The `useEffect` that wrote `STORAGE_SIZE_FS_KEY` is removed entirely (the key is now read-only legacy migration).
- Fullscreen branch: `if (isFullscreen && allowFullscreen)` — chromeless can never enter FS even if a stale state somehow set it.
- Normal-branch root `<div>` adds `data-notation-body` and `data-view-mode={viewMode}` attributes; renders `{!chromeless && controlBar}`.
