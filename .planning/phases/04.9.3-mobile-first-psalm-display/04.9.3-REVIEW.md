# Phase 04.9.3: Code Review Report

**Reviewed:** 2026-05-16
**Depth:** standard
**Files Reviewed:** 17
**Status:** issues_found

## Summary

The phase delivers a coherent mobile-first singing view with a clean controlled/uncontrolled split between `SingingView` and `NotationRenderer`. The architectural choices (chromeless mode, single-AbcPlayer multi-staff composition, controlled `viewMode`/`baseSize`) are sound and the SSR-safety pattern (initial state defaulted, then hydrated in `useEffect`) is correctly applied in `SingingView`.

That said, several real defects exist:

- The prev/next psalm links in `PsalmTopBar` unconditionally `preventDefault()` inside `onClick`, breaking middle-click / Cmd-click / Ctrl-click "open in new tab" and bypassing Next.js link prefetching. The same anti-pattern appears in two places.
- `NotationRenderer` reads `STORAGE_SIZE_FS_KEY` on init but never writes it — fullscreen size never persists.
- `AbcAudioControls` re-runs `abcjs.renderAbc` on every BPM change and stops any in-progress playback as a side effect, with no obvious recovery path; it also has no unmount cleanup that nulls the synth before tear-down.
- `NotationRenderer.unifiedAbc` does a blanket `replace(/\s*name="[^"]*"/g, '')` across every header line — not just `V:` lines — risking accidental stripping of header attributes that happen to use the same syntax.

Findings below are grouped by severity and reference specific files / lines.

## Blocker Issues

### BL-01: Prev/next Link `preventDefault` breaks middle-click and Cmd-click

**File:** `src/components/singing/PsalmTopBar.tsx:72-75, 98-101`
**Issue:** Both prev and next links wrap a Next.js `<Link>` with an `onClick` that unconditionally calls `e.preventDefault()` then `router.push()`:

```tsx
onClick={(e) => {
  e.preventDefault()
  startTransition(() => router.push(`/psalms/${prev}`))
}}
```

This **breaks** opening the link in a new tab via:
- Middle-click (mouse wheel button)
- Cmd-click on macOS, Ctrl-click on Windows/Linux
- Shift-click (new window)

It also bypasses Next.js's native `<Link>` accessibility (proper `aria-current` handling) for a hand-rolled `useTransition` indicator that the `<Link>` itself already supports via `router events` if needed.

**Fix:** Either drop the custom `onClick` entirely (Next 15 `<Link>` already renders an `<a href>` that the router intercepts on plain click), or guard the modifier keys:

```tsx
onClick={(e) => {
  if (e.metaKey || e.ctrlKey || e.shiftKey || e.altKey || e.button !== 0) return
  e.preventDefault()
  startTransition(() => router.push(`/psalms/${prev}`))
}}
```

The same fix applies to the next-link block at lines 98-101.

### BL-02: Fullscreen size is read from localStorage but never persisted

**File:** `src/components/notation/NotationRenderer.tsx:84-85, 237-258, 278-284`
**Issue:** The component declares two storage keys (`STORAGE_SIZE_KEY` and `STORAGE_SIZE_FS_KEY`) and reads from both in the initial-state lazy initializers (lines 213, 237). It also has a `useEffect` that **writes** `STORAGE_SIZE_KEY` from `normalSize` (lines 278-284) — but there is **no corresponding effect** for `fullscreenSize`/`STORAGE_SIZE_FS_KEY`. The key is read but never written, so user adjustments in fullscreen mode are silently dropped on reload.

**Fix:**

```tsx
useEffect(() => {
  try {
    localStorage.setItem(STORAGE_SIZE_FS_KEY, String(fullscreenSize))
  } catch {
    /* ignore */
  }
}, [fullscreenSize])
```

Also confirm whether this key was intentionally removed during the phase (the chromeless path bypasses fullscreen entirely) — if so, the dead read at line 237-258 and the unused constant at line 85 should be deleted.

### BL-03: `AbcAudioControls` cancels active playback on every BPM tick and lacks unmount cleanup

**File:** `src/components/singing/AbcAudioControls.tsx:86-109, 73-83`
**Issue:** The hidden-visualObj `useEffect` depends on `[abc, transpose, bpm]` (line 109). Every BPM ± button press changes `bpm`, which triggers the effect's cleanup:

```tsx
return () => {
  if (synthRef.current) { try { synthRef.current.stop() } catch { /* ignore */ } }
  if (timingRef.current) { try { timingRef.current.stop() } catch { /* ignore */ } }
  synthRef.current = null
  timingRef.current = null
}
```

This **stops in-progress playback and nulls the refs while `isPlaying` remains `true`** in React state. The user sees a Pause button that does nothing (clicking calls `onPause` which guards on `synthRef.current`, finding null, and `setIsPlaying(false)` does fire, but the state-vs-reality desync between the moment of BPM change and the next pause click is real). The cleanup also runs synchronously during render, so a single tap of `+` mid-song silently terminates playback.

Additionally there is **no separate unmount cleanup** — the only cleanup is bound to the abc/transpose/bpm effect. On a clean unmount (e.g. closing the FAB sheet), the cleanup does run, but if the sheet is closed while the synth's AudioContext is still active (some browsers retain a context per node), nothing here decrements the audio context. The cleanup also does not call `synth.stop()` on the timingRef object — it calls `stop()` only on synthRef.

**Fix:**
1. Move the `bpm` dependency out of the hidden-render effect. Only `abc` and `transpose` change the visualObj's musical content; BPM is passed to `synth.init({ millisecondsPerMeasure })` and `TimingCallbacks({ qpm })` at play time, so the visualObj does not need to be rebuilt for BPM. Re-render only on `[abc, transpose]`.
2. On playback, capture the BPM at start and re-init the synth when BPM changes only if playback is active (mirror `AbcPlayer.tsx`'s pattern more closely — that file has the same risk on lines 363/299 and should be audited too, see WR-05).
3. Add an explicit unmount cleanup `useEffect` with empty deps that calls `synthRef.current?.stop()` once.

### BL-04: `unifiedAbc` strips `name="..."` from every header line, not just `V:` declarations

**File:** `src/components/notation/NotationRenderer.tsx:608-617`
**Issue:** The chromeless header sanitizer is:

```tsx
const cleanedHeader = split.header
  .split('\n')
  .filter((l) => { /* drops T: and Q: */ })
  .map((l) => (chromeless ? l.replace(/\s*name="[^"]*"/g, '') : l))
  .join('\n')
```

The `.map` applies the regex to **every surviving header line**, not just `V:` lines. ABC headers can legally contain `name="..."` inside `%%score`, `%%MIDI`, `%%text`, or user-defined macros. Any such occurrence would be stripped, with quietly broken output. The comment immediately above says the intent is "strip the `name="..."` attribute from any `V:` voice declaration", so the implementation is broader than the documented intent.

**Fix:** Restrict the substitution to `V:` lines:

```tsx
.map((l) => (chromeless && /^V:/.test(l.trim()) ? l.replace(/\s*name="[^"]*"/g, '') : l))
```

This also makes the behaviour match the surrounding comment.

## Warnings

### WR-01: `useEffect` dep on `showLyrics` re-hydrates user-selected viewMode from localStorage

**File:** `src/components/singing/SingingView.tsx:99-103`
**Issue:** The hydration effect:

```tsx
useEffect(() => {
  setViewMode(readStoredViewMode(showLyrics))
  setBaseSize(readStoredBaseSize())
  setMounted(true)
}, [showLyrics])
```

Depends on `showLyrics`, so if a tune switch or navigation toggles `showLyrics` from `false` to `true`, the user's current in-memory `viewMode` is overwritten by whatever is in localStorage. This is almost certainly unintended — the effect was meant to run once on mount.

**Fix:** Either use an empty dep array and read `showLyrics` from a ref, or split the lyrics-fallback logic out:

```tsx
useEffect(() => {
  setViewMode(readStoredViewMode(showLyrics))
  setBaseSize(readStoredBaseSize())
  setMounted(true)
  // eslint-disable-next-line react-hooks/exhaustive-deps
}, [])

useEffect(() => {
  if (mounted && !showLyrics && viewMode === 'lyrics') setViewMode('staff')
}, [showLyrics, viewMode, mounted])
```

### WR-02: `TuneSwitcherSheet` close `setTimeout` runs against possibly unmounted component

**File:** `src/components/singing/TuneSwitcherSheet.tsx:71-77`
**Issue:**

```tsx
const handleSelect = (tune: TuneOption) => {
  // ...
  router.replace(`${pathname}?${params.toString()}`, { scroll: false })
  setTimeout(() => onOpenChange(false), 120)
}
```

`router.replace` is synchronous in URL state but client-render-async; the `setTimeout` is never cleared. If the user dismisses the sheet (or the route changes) before 120ms, the parent state setter still fires after unmount. React 18 is tolerant but this triggers warnings under StrictMode and is brittle.

**Fix:** Track the timer in a ref and clear it on unmount, or call `onOpenChange(false)` first and rely on `router.replace` afterwards (the URL change does not require the sheet to stay open).

### WR-03: `AbcPlayer` resize re-render aborts in-progress playback

**File:** `src/components/AbcPlayer.tsx:200-236, 299-363`
**Issue:** The render effect calls `stopAudio()` at the top and re-renders on every `staffWidth` change (debounced to ≥8px). On iOS Safari the URL-bar collapse on first scroll causes a `visualViewport` resize ≥8px, which silently kills any active playback when the user scrolls.

**Fix:** In the render effect, only call `stopAudio()` when the inputs that affect the synth (abc / transpose) changed. For pure layout changes (staffWidth, scale, staffWidthFactor) re-render the SVG but keep the synth alive; abcjs's `TimingCallbacks` track the visualObj reference, so you would need to either (a) re-create the timing only and reuse the synth, or (b) accept the playback stop but at least communicate it to the user via `onPlaybackStop`.

### WR-05: `AbcPlayer` autoPlay effect omits `onPlay` from deps with eslint-disable

**File:** `src/components/AbcPlayer.tsx:425-440`
**Issue:** The effect intentionally disables exhaustive-deps. Today this is safe because `onPlay` is recreated each render, so the next token bump runs with the latest closure values. But if a future refactor uses `useEvent` or otherwise stabilizes `onPlay`, this becomes a stale-closure bug that's very hard to find. Add a comment explaining the invariant (closure-capture-by-call), or use a ref pattern explicitly.

### WR-07: Inline `<style>` tag in `SingingView`

**File:** `src/components/singing/SingingView.tsx:175-179`
**Issue:** Embedding raw `<style>` inside a client component bypasses Next.js's CSS pipeline (no scoping, no minification, hydration warning under some configurations) and is fragile to React 19's hydration rules. The effect can be achieved with Tailwind's responsive utilities or a CSS-vars-on-element pattern.

**Fix:**

```tsx
<main
  data-notation-region
  className="overflow-x-hidden flex flex-col h-[calc(100dvh-147px)] md:h-[calc(100dvh-159px)]"
>
```

(`h-[…]` arbitrary values support `100dvh` units in Tailwind 4.)

### WR-08: Hardcoded soundfont URL points at a third-party GitHub Pages host

**Issue:** `SOUNDFONT_URL = 'https://paulrosen.github.io/midi-js-soundfonts/abcjs/'` is duplicated across the two files and depends on an external host that the project does not control. If `paulrosen.github.io` goes down, audio breaks silently (`catch` logs to console; user sees only "Audio not available in this browser."). ### WR-10: `abbrevMeter` regex is case-sensitive and misses lowercase abbreviations

**File:** `src/components/singing/TuneSubBar.tsx:11-22`
**Issue:**

```tsx
if (/^[A-Z]{2,4}$/.test(trimmed)) return trimmed.split('').join('.') + '.'
if (/^[A-Z](\.[A-Z])+\.?$/.test(trimmed)) return trimmed
```

Meter strings like `"cm"` or `"c.m."` fall through and render as-is. The DB content for `meter` is not strictly normalized (the `fetchTunesByMeter` path doesn't lower-case-compare). Either lowercase before matching or add explicit lowercase alternation.
