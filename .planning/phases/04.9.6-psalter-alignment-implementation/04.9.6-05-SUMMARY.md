# Phase 04.9.6 Plan 05: Renderer wiring (lyricsStructured + doubleLength) Summary

Promoted the NotationRenderer onto the canonical `lyrics_structured` + `tune.double_length` signals, removed Plan 04's transitional shim (`_doubleLengthHeuristic` + `as unknown as Stanza[]` cast + try/catch around `wLinesForPhrase`), and plumbed the two new props through every consumer (`src/app/psalms/[id]/page.tsx`, `src/app/tunes/[id]/page.tsx`, `src/components/PsalmTabs.tsx`, `src/components/singing/SingingView.tsx`). Wave 3 alignment now flows entirely on canonical data with a per-row legacy fallback (D-15) for the 6 quarantined psalm-versions.

## What was built

**Task 1 — fetchPsalmDetail + W3 FTS audit (landed pre-resume in commit `f826936`):**
- `src/db/queries/psalms.ts`: explicit column selection on `psalmVersions` adds `lyricsImportedRaw` AND `lyricsStructured`; `psalmVersionTunes.tune` selects all columns (including `doubleLength`).
- W3 audit: `src/db/queries/search.ts` already references `pv.lyrics_imported_raw`; no stale `lyrics`-column references; no FTS GIN index needed re-creation (none existed on the old column).

**Task 2 — Renderer wiring + shim removal (commit `32a37dc`):**

`src/components/notation/NotationRenderer.tsx`:
- Imports `type { StructuredLyrics }` alongside the existing `type { Stanza }`.
- `NotationRendererProps` gains `lyricsStructured: StructuredLyrics | null` and `doubleLength: boolean`.
- Function destructure adds both props.
- The old `lyrics` blob + `_doubleLengthHeuristic` `useMemo` block (lines ~185-211 of the prior file) is replaced by:
  - `stanzas: Stanza[]` useMemo: returns `lyricsStructured` when non-null; otherwise parses the legacy blob into a transient `Stanza[]` (one `Line` per non-empty trimmed metrical line). This single source feeds both `groupStanzasIntoCycles` and the legacy `<StanzaList>` consumer.
  - `stanzaStrings: string[]` useMemo: sibling derivation for `<StanzaList stanzas={…}>` (its prop type stays `string[]` until Plan 06).
  - `cycles = groupStanzasIntoCycles(stanzas, doubleLength)` — canonical signature, no cast, no heuristic.
- `wLinesForPhrase(i)` rewritten: the try/catch shim and `as unknown as Stanza[]` cast are gone; the function calls `mapCycleToPhraseSyllableLines(cycle, phrasesForMeter(tuneMeter))` directly and consumes `grid[i] ?? ['']` (B1 shape contract intact).
- `unifiedAbc` `useMemo` dependency list pruned: `stanzaMeter` is no longer referenced inside the memo body (the heuristic that used it is gone), so it's removed from the deps array. `stanzaMeter` remains as a prop for backwards compatibility with current callers.
- Three `<StanzaList>` call sites + their `stanzas.length > 0` guards now reference `stanzaStrings`.

`src/db/queries/tunes.ts`:
- `fetchTuneDetail`'s `psalmVersion` column list adds `lyricsStructured: true`.

`src/app/psalms/[id]/page.tsx`:
- Derives `lyricsStructured` from `activeVersion?.lyricsStructured` and passes it through to `<SingingView>`.

`src/app/tunes/[id]/page.tsx`:
- `<NotationRendererClient>` now receives `lyricsStructured={firstLinkedPsalmVersion?.lyricsStructured ?? null}` and `doubleLength={tune.doubleLength ?? false}`.

`src/components/PsalmTabs.tsx`:
- `<NotationRendererClient>` now receives `lyricsStructured={primaryVersion?.lyricsStructured ?? null}` and `doubleLength={activeTune.doubleLength ?? false}`. The `activeTune` builder (override branch) now copies `doubleLength` from the `AlternateTune`; the primary-tune branch already had `doubleLength` via `…primaryTune`.

`src/components/singing/SingingView.tsx`:
- Props interface gains `lyricsStructured: StructuredLyrics | null` (alongside the existing `lyrics: string`).
- `<NotationRendererClient>` call passes `lyricsStructured={lyricsStructured}` and `doubleLength={activeTune?.doubleLength ?? false}`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] `NotationRendererClient.tsx` does not require per-prop wiring**

- **Found during:** Task 2 caller audit.
- **Issue:** The plan says "Wrapper client (`NotationRendererClient.tsx`): Add the two new props (`lyricsStructured`, `doubleLength`) to its prop pass-through" with an acceptance bar of `grep -c "lyricsStructured" src/components/notation/NotationRendererClient.tsx >= 1`.
- **Reality:** The wrapper accepts `props: NotationRendererProps` and spreads `{...props}` into `<NotationRenderer />`. Adding the two new props to `NotationRendererProps` is sufficient — TypeScript propagates them through the wrapper automatically. Adding a redundant per-prop pass-through would either be dead syntax or duplicate the spread.
- **Resolution:** Type propagation through the spread satisfies the spirit of the acceptance bar (the wrapper does carry both props through). `npx tsc --noEmit` confirms callers `<NotationRendererClient lyricsStructured={…} doubleLength={…} />` type-check. The `grep` literal-count acceptance is not met for this single file but the contract is.
- **Files modified:** None for this point (the wrapper is already correct).

**2. [Rule 2 — Missing critical] `fetchTuneDetail.psalmVersion` did not select `lyricsStructured`**

- **Found during:** Wiring `src/app/tunes/[id]/page.tsx`.
- **Issue:** The tune detail page passes a linked psalm-version's `lyricsStructured` to the renderer, but `fetchTuneDetail`'s explicit `columns:` whitelist omitted that field, so it would always be `undefined`.
- **Fix:** Added `lyricsStructured: true` to the column list in `src/db/queries/tunes.ts`. The tune detail page still falls back to legacy parsing when the linked version's `lyricsStructured` is null.
- **Files modified:** `src/db/queries/tunes.ts`
- **Commit:** `32a37dc` (Task 2)

**3. [Rule 1 — Bug] Naming collision when renaming `stanzasStructured` → `stanzas`**

- **Found during:** Task 2 (after the strict acceptance regex `groupStanzasIntoCycles\(stanzas,\s*doubleLength\)` failed against my initial `stanzasStructured` identifier).
- **Issue:** Renaming the Stanza[] memo to `stanzas` collided with the existing legacy string-shaped `stanzas` memo (still required by `<StanzaList>`'s `string[]` prop type).
- **Fix:** Renamed the legacy string-shaped memo to `stanzaStrings` and updated all three `<StanzaList stanzas={…}>` call sites plus their `…length > 0` guards.
- **Files modified:** `src/components/notation/NotationRenderer.tsx`
- **Commit:** `32a37dc` (Task 2)
