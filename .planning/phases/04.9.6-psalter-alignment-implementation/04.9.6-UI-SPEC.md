| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions:
- The inline Bible verse superscript has no additional horizontal spacing
  between itself and the first syllable of the new verse. The superscript
  character is rendered inline with `vertical-align: super` — no `margin` or
  `padding` additions. This matches the existing `.verse-number` CSS class
  pattern established in globals.css and MUST reuse that class.

## The One Net-New Visual: Inline Superscript Verse Number

Source: CONTEXT.md D-07, Specific User Inputs §5.

### What it is

When a Bible verse boundary begins mid-stanza (i.e. a `bibleVerseRef` is set on
a `Line` that is not the first line of the stanza), the verse number is rendered
as an inline superscript character immediately before the first syllable of that
line. No space between the superscript and the word.

### Rendering rules

| Property | Spec |
|----------|------|
| HTML element | `<sup className="verse-number">{ref}</sup>` — reuses existing class |
| Position | Inline, immediately before the syllable text (no gap) |
| Staff-overlay mode | Appears in the `w:` field contribution or in the lyric overlay span; the superscript must not break abcjs syllable-to-note alignment |
| Lyrics-only mode | Appears inline in the `<StanzaList>` / lyrics prose render |
| Solfège mode | Same as lyrics-only (no staff, prose render only) |
| Mobile | No gutter, no hover, always visible — matches printed psalter convention |
| Color | Inherits foreground color — no special color |
| Size (staff mode) | `calc(--staff-base-size * 0.5)` — via `.verse-number` class |
| Size (lyrics/solfège mode) | `calc(--staff-base-size * 0.85)` — via `[data-view-mode="lyrics"] .verse-number` rule |

### Implementation note for abcjs `w:` field

The `w:` field in ABC notation is plain text — HTML is not rendered inside it.
The inline superscript for the **staff view** must therefore be injected via the
existing lyric text overlay mechanism (the rendered lyric spans beneath or above
the SVG staff), NOT inside the `w:` string itself. The `w:` field continues to
carry syllabified plain text for note-alignment; the superscript is a parallel
display element.

For the **lyrics-only view**, the superscript is rendered directly in the React
component tree using the `<sup className="verse-number">` pattern.

## Interaction Contract

### Feature-flagging (per-psalm)

The new alignment renderer activates **only** when `lyrics_structured` is
non-null AND the psalm-version is not in the quarantine bucket (D-15 from
CONTEXT.md). Quarantined psalm-versions continue through the current renderer
path. There is no user-facing toggle — the switch is transparent.

**Visual requirement:** there must be NO visible difference in the layout or
controls between a psalm rendered via the new alignment path and one still on
the legacy path. Both paths render into the same `NotationRenderer` shell.

### Loading / skeleton states

No new loading states. The existing `loading.tsx` skeletons and `<Suspense>`
boundaries from prior phases cover the psalm page shell. The alignment change
is purely in what data feeds the renderer.

### Error / quarantine state

Quarantined psalm-versions silently use the legacy blob renderer. No error
indicator is shown to the user. This is an internal data-quality state, not a
user-facing error condition.

### Stanza-cycle pagination (DCM fix)

When `tune.double_length === true`, two consecutive lyric stanzas appear under
one tune-pass. The existing pagination counter ("Stanzas N–M / Total") continues
to work correctly. The counter label is derived from stanza indices — no visual
change to the counter component is required.

## States Required

For each psalm-version, the renderer must support these states without visual
regression:

| State | Condition | Visual |
|-------|-----------|--------|
| Structured + active | `lyrics_structured` non-null, not quarantined | New alignment path; inline verse superscripts where applicable |
| Legacy (quarantine) | `lyrics_structured` is null OR psalm in quarantine | Existing renderer — identical visual to today |
| DCM double-stanza | `tune.double_length === true` | Two lyric stanzas under one tune-pass — existing pagination counter updates correctly |
| Mid-stanza verse split | `Line.bibleVerseRef` set on non-first line | Inline superscript before first syllable of that line |
| Single-stanza (normal) | `tune.double_length === false` | One stanza per tune-pass — no change from current |
| Alternate meter | e.g. `10.10.10.10.10` | Syllable-to-note alignment driven by structured `Line[]` — no visual change to controls |
