# Phase 04.9.6 Plan 01: Data Model + Type Contract Summary

Established the canonical TypeScript and DB-schema contract for structured psalter lyrics so Plans 02–06 can implement against a known shape with zero scavenger hunting.

## What was built

Three atomic deliverables, one per task:

1. **`src/lib/lyrics-structured.ts`** — new pure module exporting `Line`, `Stanza`, `StructuredLyrics`, `ParseResult`, plus `parseLyrics` and `serialiseLyrics` stubs (throw `'not implemented — plan 02'`). Zero forbidden imports (no React, Next, abcjs, drizzle, `@/db`). JSDoc documents the asymmetric whitespace rule (parser tolerates `\d+\s*`, serialiser emits strict `\d+\S`) per D-06 invariant 2.

2. **`src/db/schema.ts` rename + new jsonb column** — `lyrics: text('lyrics')` → `lyricsImportedRaw: text('lyrics_imported_raw')`; added `lyricsStructured: jsonb('lyrics_structured').$type<StructuredLyrics | null>()`. Imported the type from `@/lib/lyrics-structured` to make the Drizzle generic load-bearing. Every TS caller of the old field migrated:
   - Drizzle query `columns: {}` selectors in `src/db/queries/psalms.ts` and `src/db/queries/tunes.ts`
   - Raw SQL column reference `pv.lyrics` → `pv.lyrics_imported_raw` in `src/db/queries/search.ts`
   - `psalmVersions.lyrics` filter → `psalmVersions.lyricsImportedRaw` in `src/app/api/search/route.ts`
   - POJO accesses (`row.lyrics`, `v.lyrics`, `activeVersion.lyrics`, `primaryVersion.lyrics`, `firstLinkedPsalmVersion.lyrics`, `psalm.lyrics`, `p.lyrics`) → `.lyricsImportedRaw`
   - Transient interfaces (`PsalmOption` in `SelectPsalmDialog`, `PsalmsByTuneSection.Props.psalmsForMeter`, `fetchPsalmsByMeter` return type) renamed for end-to-end type correctness
   - `scripts/migrate-airtable.ts` insert + `onConflictDoUpdate.set` clauses (including the raw SQL `sql\`excluded.lyrics\`` → `sql\`excluded.lyrics_imported_raw\``)
   - `src/lib/lyrics.ts` JSDoc reference

   No DB push — that's Plan 03 Task 1 ([BLOCKING] schema-push). This commit edits schema source only.

3. **`.planning/REQUIREMENTS.md`** — inserted 11 new bullets (DATA-01..05, RENDER-01..06) under a new "Psalter Alignment" section between MOBILE-03 and the `---` separator preceding v2 Requirements; appended 11 matching traceability rows.

## Deviations from Plan

**Plan-driven extras applied (Rule 3 — blocking issues):**

1. **`scripts/migrate-airtable.ts` updated.** Plan §audit minimum list mentioned `scripts/`; this file contained two references (insert payload + `onConflictDoUpdate.set` raw SQL) that would have broken the migration script at runtime against the renamed column. Updated both. Commit `e6f2e0d`.

2. **POJO interface renames in `SelectPsalmDialog` / `PsalmsByTuneSection` / `fetchPsalmsByMeter` return type.** The plan's language is mixed on whether transient POJO field names should follow the schema rename. Chose to rename throughout so `fetchPsalmsByMeter`'s typed Drizzle output flows unchanged to the dialog and its rendering — keeping the field name identical to the Drizzle-row provenance eliminates a class of "did I forget to rename?" bugs and makes the type checker enforce alignment end-to-end. The component prop `lyrics` (a plain string, e.g. on `NotationRenderer`) was left as `lyrics` because it is no longer a column reference — just a string blob fed into the renderer.

3. **JSDoc reference in `src/lib/lyrics.ts`.** Comment said "Verses in psalmVersions.lyrics are separated by…" — corrected to `lyricsImportedRaw` so future grep/audit doesn't surface a false positive.

Out-of-scope discoveries logged but not fixed (pre-existing, unrelated to this plan):

- `tests/e2e/abc-player.spec.ts` and `tests/tune-notation.spec.ts` have pre-existing TS errors (`chromium` redeclaration, `TestResult` shape mismatch). Confirmed present at HEAD before changes; out of scope per executor SCOPE BOUNDARY rule.
