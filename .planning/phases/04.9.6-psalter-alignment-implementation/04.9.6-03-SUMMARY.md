# Phase 04.9.6 Plan 03: Lyrics-Structured Corpus Backfill Summary

Backfilled the new `psalm_versions.lyrics_structured` jsonb column for 178/184 psalm-versions by running the Plan 02 parser over the live corpus, with strict round-trip validation gating every write and a quarantine report capturing the 6 failures.

## What Shipped

**Task 1 — [BLOCKING] drizzle-kit push (cleared via human action before this agent resumed):**
- `ALTER TABLE psalm_versions RENAME COLUMN lyrics TO lyrics_imported_raw` applied via direct SQL.
- `npx drizzle-kit push --force` added `lyrics_structured jsonb`.
- Verified columns via `\d psalm_versions`; 184 rows had non-null `lyrics_imported_raw`; 0 rows had `lyrics_structured` populated.
- No GIN/FTS index existed on the old `lyrics` column (only btree on id + unique on airtable_id), so nothing to recreate.
- No code commit needed for Task 1 — the schema.ts edit landed in Plan 01.

**Task 2 — `scripts/snapshot-lyrics-corpus.ts` + `tests/fixtures/lyrics-corpus-snapshot.json`:**
- Reads every `psalm_versions` row with non-null `lyrics_imported_raw`, ordered by id.
- Writes a JSON array of `{id, psalterNumber, versionLabel, meter, lyrics}` to the frozen fixture.
- Output is 184 rows, ~75 KB; downstream regression tests pin against this byte-stable snapshot.

**Task 3 — `scripts/parse-lyrics-structured.ts` + `scripts/parse-lyrics-structured.test.ts`:**
- Backfill script supports `--dry-run` (report-only) and live mode.
- Per-row gate: `parseLyrics()` must return `ok: true` AND `serialiseLyrics(parsed)` must round-trip back to the original blob through a shared `normalise()` function.
- Failures (parse OR round-trip) are accumulated and written to `parse-failures.md` with id, psalter number, reason, and (when known) offending line index.
- Run-guard via `realpathSync(fileURLToPath(import.meta.url))` so the sibling test can import `normalise` without opening a DB connection.
- Corpus test (D-05) loads the snapshot, replays the same gate, asserts `quarantined ≤ 8` and `parsed ≥ 175`. Test passes with 178 parsed / 6 quarantined.

**Task 4 — live backfill applied:**
- `npx tsx scripts/parse-lyrics-structured.ts` ⇒ `Parse complete: 178 parsed, 6 quarantined.`
- DB verification: `SELECT count(*) FROM psalm_versions WHERE lyrics_structured IS NOT NULL` returns `178` (matches script).
- Psalm 23 verification (D-16 canary prerequisite): `id=35, psalter_number=23, jsonb_array_length(lyrics_structured)=5` — clean 5-stanza structure ready for the Plan 07 regression test.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Corpus test gate misaligned with backfill gate**
- **Found during:** Task 3 verification.
- **Issue:** The plan's example test code (`mismatched` list with `expect(mismatched).toEqual([])`) treated round-trip mismatches as fatal while the backfill script treated them as quarantine. With Psalm 124 (Second Version) genuinely round-trip-failing on its 10.10.10.10.10 blank-line layout, the test could never pass against the real corpus.
- **Fix:** Aligned the test with the backfill's actual gate: count round-trip mismatches as quarantined (they would silently lose data if persisted, so they belong with parse failures). Plan-level success criterion (`≥ 175 parsed, ≤ 9 quarantined`) is unchanged and still asserted.
- **Files modified:** `scripts/parse-lyrics-structured.test.ts`
- **Commit:** 18ef5e0
