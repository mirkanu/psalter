### 2. `src/lib/lyrics-structured.ts` (new — types, parser, serialiser)

**Analog:** `src/lib/abc-phrases.ts` — pure helper module idiom (no DOM/DB/Next imports; exports types + functions; thoroughly JSDoc'd; deterministic).

**Imports pattern** (`src/lib/abc-phrases.ts:1-10` comment):
```typescript

 * Pure helpers for ...
 * Pure module — no DOM, no abcjs, no Next/React imports.
 */
```
No imports needed — pure string/regex code. The parser MAY import `syllabifyForAbc` if it wants to round-trip via syllables, but per D-03 syllabification is render-time, so the parser does NOT.

**Type-export pattern** (`src/lib/abc-phrases.ts:12-15`):
```typescript
export interface SplitAbc {
  header: string
  phrases: string[]
}
```

**Types to define** (per CONTEXT D-03, D-06):
```typescript
export interface StructuredLyrics {
  stanzas: Stanza[]
}
export interface Stanza {
  lines: Line[]
}
export interface Line {
  text: string                    // plain text of the metrical line
  bibleVerseRef?: number          // present when this line starts a new Bible verse
  syllables?: string[]            // optional manual override (D-03 hybrid)
}
```

**Parser invariants to encode** (verbatim from CONTEXT D-06):
1. Every numeric digit in a `lyrics` blob is a Bible-verse number; lyric numbers are spelled out.
2. Verse numbers are glued to the next char with no space (`1The Lord's...`).
3. Stanzas split on `lyrics.split(/\n\s*\n/)` (already used at `NotationRenderer.tsx:185` and `lyrics.ts:22`).
4. One newline = one metrical line.
5. A Bible verse may start mid-line / mid-stanza; preserve relationships.

**Existing regex to mirror** (`src/lib/lyrics.ts:25` — verse-number stripping):
```typescript
const stripped = first.replace(/^\d+/, '')
```
The parser generalises this from "leading digit run" to "any digit run inside a line" — splitting on `/(\d+)(?=\S)/` to capture the verse number and re-attach to lines.

**Serialiser contract** (per D-05 strict round-trip):
```typescript
// serialise(parse(blob)) === blob (modulo whitespace)
export function parse(blob: string): { ok: true; lyrics: StructuredLyrics } | { ok: false; reason: string; line: number }
export function serialise(lyrics: StructuredLyrics): string
```

The discriminated-union return type matches the same idea as `SplitAbc`'s graceful-fallback approach in `abc-phrases.ts:38-49`.

**Iteration + update pattern** (`scripts/migrate-double-length.ts:24-47`):
```typescript
async function main() {
  const rows = await db.select().from(psalmVersions).where(isNotNull(psalmVersions.lyricsImportedRaw))
  let parsed = 0, quarantined = 0
  const failures: string[] = []
  for (const r of rows) {
    const result = parse(r.lyricsImportedRaw ?? '')
    if (!result.ok) {
      failures.push(`- psalm-version ${r.id} (${r.psalterNumber}): ${result.reason} @ line ${result.line}`)
      quarantined++
      continue
    }
    // Strict round-trip check (D-05)
    if (serialise(result.lyrics).replace(/\s+/g, ' ').trim()
        !== (r.lyricsImportedRaw ?? '').replace(/\s+/g, ' ').trim()) {
      failures.push(`- psalm-version ${r.id} (${r.psalterNumber}): round-trip mismatch`)
      quarantined++
      continue
    }
    await db.update(psalmVersions)
      .set({ lyricsStructured: result.lyrics })
      .where(eq(psalmVersions.id, r.id))
    parsed++
  }
  // Write parse-failures.md (planner picks path — likely
  // `.planning/phases/04.9.6-psalter-alignment-implementation/parse-failures.md`)
  console.log(`Parse complete: ${parsed} parsed, ${quarantined} quarantined.`)
  process.exit(0)
}

main().catch((e) => { console.error(e); process.exit(1) })
```
