# Phase 04.9.4 Plan 04: Onboarding Tour Summary

**Implemented a first-visit onboarding tour as a custom React portal (~157 LOC, zero new dependencies) that highlights four interaction anchors with a box-shadow spotlight, persists dismissal via `localStorage['psalter_tour_v1'] = 'done'`, and renders nothing on subsequent visits.**

## Performance

- **Duration:** ~5 min
- **Tasks:** 2
- **Files created:** 1
- **Files modified:** 1

## Accomplishments

- `OnboardingTour.tsx` created at `src/components/singing/OnboardingTour.tsx` — SSR-safe, portal-based, ~157 LOC including comments.
- Four steps target the existing `data-tour-target` hooks added by Plans 01 (`prev-next`, `tune-name`) and 02 (`view-controls`, `play-button`).
- Box-shadow spotlight cutout (`0 0 0 9999px rgba(0,0,0,0.60)`) wraps the target with 8px padding and `border-radius: 8px`.
- Tip bubble positioned below the spotlight when target sits in the top half of the viewport, above otherwise; width `min(320px, 90vw)`.
- Buttons render via shadcn `Button` (`variant="ghost"` for Skip tour, `variant="default"` for `Next →` / `Done`).
- Step indicator (`Step N of 4`), `aria-live="polite"`, `role="dialog"`, `aria-label="Onboarding step N of 4"`.
- `Escape` keydown anywhere dismisses the tour.
- Re-measures target on `resize` and `orientationchange`; if the target element disappears (race / target removed), the tour calls `dismiss()` rather than retrying indefinitely (T-04.9.4.04-03 mitigation).
- Final step button renders `Done` (not `Next →`) per Copywriting Contract.
- `motion-reduce` honored: only the overlay opacity transitions; no positional transitions to suppress.
- Mounted as the last child of `<div data-singing-view>` in `SingingView.tsx` (line 352), after `GearDrawer`.

## Decisions Made

- **Optimistic tourSeen=true** on first render so returning visitors never see a flash of overlay; the real value is read inside the post-mount `useEffect`. Mirrors the existing SSR pattern in `SingingView` (lines 95–115).
- **localStorage failure → seen=false:** A first-time user with disabled localStorage still gets the tour (per-visit, since dismissal cannot be persisted). The contract is "never crash"; degradation is benign.
- **Geometry-based bubble placement** (viewport-half test) over full collision detection. Four fixed targets at known top/bottom positions make this safe and keeps the component small.
- **Mounted after `GearDrawer`** as the last child so the portal mounts only once the top bar and bottom bar (with their `data-tour-target` anchors) are in the React render tree.
