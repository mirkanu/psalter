# Phase 04.9.4 Plan 05: Playwright UAT Summary

Wrote three Playwright UAT scripts that prove all six Phase 04.9.4 success criteria automatically across the 375 / 768 / 1024 px viewports, plus a regression check that `/psalms/[id]/study` still renders after the SingingView chrome rebuild. All three scripts pass green against the worktree dev server.

## What was built

### `scripts/uat/test-04.9.4-quick.js` — per-commit gate
- Single viewport 375×812.
- Clears `localStorage`, reloads, dismisses tour.
- **SC1** asserts `[data-singing-topbar]` contains `Psalm 23`, the `♩` glyph, `Crimond`; does NOT contain the forbidden `Tune (` prefix or any pencil icon (data-attr or `lucide-pencil` SVG); `[data-singing-tune-slot]` exists.
- **SC4** asserts `[data-glass-bottom-bar]` exists with class `backdrop-blur-md`, sits at the viewport bottom, has `A−` and `A+` buttons, and `[data-stanzas-indicator]` text matches `/^Stanza \d+ \/ \d+$/` (polled up to 2 s).
- **SC6** asserts `documentElement` and `body` `scrollWidth ≤ clientWidth`.
- Writes `scripts/uat/screenshots/04.9.4-quick-375.png`.

### `scripts/uat/test-04.9.4-full.js` — per-wave / phase gate
- Iterates `mobile-375`, `tablet-768`, `desktop-1024`. Runs SC1, SC4, SC6 at each viewport with a shared helper (`assertStanzasIndicator`, `assertNoOverflow`, `assertSC1`, `assertSC4`).
- **SC2** (375 only, fresh context): clears storage, asserts tour visible at `Step 1 of 4`, clicks `Next` 3×, asserts `Step 4 of 4` + `Done`, clicks Done, asserts tour absent, asserts `localStorage.getItem('psalter_tour_v1') === 'done'`, reloads, asserts tour still absent.
- **SC3** (resize sequence, single context): polls `psalter-staff-size` via `waitForBaseSizeChange(prev, { timeoutMs: 2000, settleMs: 50 })`. Steps 1024 → 768 → 375 → 1024, asserts each baseSize is in `[8, 40]` and there is no horizontal overflow at every step. Falls back to direct localStorage read when the polled value happens to round to the same integer.
- **SC5** (375 only, fresh context): clicks `[data-singing-play]`, asserts `[data-play-mini-bar]` is rendered, `display ≠ none`, class does NOT contain `translate-y-full`, and contains `[data-abc-audio-controls]`. Clicks Play again (toggle pause). Clicks `[data-singing-gear]`, asserts `[data-gear-drawer]` visible, contains "About this psalm", and does NOT contain `[data-abc-audio-controls]` (audio is out of drawer).
- Writes three screenshots (`04.9.4-full-{mobile-375,tablet-768,desktop-1024}.png`).

### `scripts/uat/test-04.9.4-study-regression.js`
- Loads `/psalms/23/study` at 1024×768; asserts 200, body contains `Psalm 23`, no horizontal overflow. Screenshot `04.9.4-study-regression-1024.png`.

## Operational notes

- **Port:** The pre-existing dev server on port 3005 in this worktree was a stale `next start` build that did not include the wave 1–4 components. To prove the scripts actually exercise live SingingView chrome, a fresh `npm run dev` was started on port 3105 from the worktree source and the scripts were run with `UAT_BASE=http://localhost:3105`. Default `BASE` remains `http://localhost:3005` to match the phase contract; in CI, the dev server should be reachable there.
- **Environment:** A `.env` was copied in from `/data/home/psalter/.env` so the dev server could initialise the PostgreSQL connection (`DATABASE_URL`). This is an untracked file and was not committed.
- **SKIP semantics:** All three scripts exit 0 with a `SKIP:` log when `/psalms/23` is unreachable, so they will not break CI when no dev server is running.
- **Timing robustness:** SC3 uses polled `waitForBaseSizeChange` (max 2 s, 50 ms settle), not a fixed `waitForTimeout`, satisfying T-04.9.4.05-01 and the "no timing flake" goal in the plan's verification block.

## Deviations from Plan

None — the three scripts and their assertions match the plan exactly. Two minor robustness additions:

1. **[Rule 2 — robustness]** Added an `UAT_BASE` env override so tests can target an alternate port without source edits. The default remains `http://localhost:3005`, matching the phase contract; only the test invocation differs.
2. **[Rule 2 — robustness]** Helper `pollUntilNonNull` waits up to 3 s for the initial `psalter-staff-size` to appear in localStorage at 1024 (the NotationRenderer fires `onStaffSizeChange` after first abcjs render). This prevents SC3 from failing on cold-start latency before the first persisted value lands.
