# Phase 04.9.4 — UI Design Contract

> Visual and interaction contract for staff-view refinements: consolidated header row, proportional zoom heuristic, glass bottom-bar, play mini-bar slide-in, gear drawer reorganisation, and first-time onboarding tour. Inherits all tokens and component patterns from Phase 04.9.3 (approved). Only delta decisions are recorded here.

## Layout Contract

### 1. Consolidated Header Row

Single row, ~48px tall on mobile / 56px on desktop (unchanged from 04.9.3 `PsalmTopBar` height).

```
┌─────────────────────────────────────────────────┐
│ [←]  Psalm 23    ♩ Crimond    [→]               │
└─────────────────────────────────────────────────┘
```

**Anatomy (left → right, single flex row):**

| Slot | Element | Size | Weight |
|------|---------|------|--------|
| Leading | `ChevronLeft` icon-button | 20px icon, 44×44 tap target | — |
| Center-left | "Psalm 23" label | 16px | 600 (semibold) |
| Center-right | "♩ Crimond" label (musical note + tune name) | 14px | 400 (regular) |
| Trailing | `ChevronRight` icon-button | 20px icon, 44×44 tap target | — |

**Gap between "Psalm 23" and "♩ Crimond":** 8px (sm token).

**Center group layout:** The two labels are flex items inside a single `flex-1` center zone with `justify-center` and `gap-2` (8px). They do NOT fill the entire center width — they are sized to content and centered as a unit.

**Tune name truncation:** `max-w-[40vw] truncate` on the tune-name span. Meter abbreviation (e.g., C.M.) is dropped from the header — meter lives in the gear drawer only.

**Musical note glyph:** Unicode `♩` (U+2669, quarter note), rendered in the same 14px/regular as the tune name. No lucide icon — the Unicode glyph is the correct semantic symbol for "tune".

**Sub-bar removal:** The 40px `TuneSubBar` from 04.9.3 is replaced entirely by this consolidated single row. The body scrollable area gains those 40px back.

**Surface treatment:** Identical to 04.9.3 top bar — `bg-background/95 backdrop-blur-sm border-b border-border/50`, `sticky top-0`, `z-50`, `pt-[env(safe-area-inset-top)]`.

### 2. Glass Bottom-Bar

Persistent bottom chrome, visible at all times (not inside any sheet).

```
┌─────────────────────────────────────────────────┐
│  [⚙]  [Staff ▾]  [Lyrics]  [Solfège]  [▶ Play] │
└─────────────────────────────────────────────────┘
```

**Height:** 56px on mobile; 60px on desktop.

**Surface:** `bg-background/70 backdrop-blur-md border-t border-border/50`. No box-shadow. Safe area: `pb-[env(safe-area-inset-bottom)]`.

**Button layout:** 5 items in a single `flex` row, `justify-around`, full width.

| Slot | Icon | Label | Behaviour |
|------|------|-------|-----------|
| Gear | `Settings` (lucide, 20px) | None (icon-only, `aria-label="Settings"`) | Opens gear drawer (Sheet side="bottom") |
| Staff | `Music` (lucide, 20px) | `Staff` (12px/regular below icon) | Activates staff view; active state: foreground fill |
| Lyrics | `AlignLeft` (lucide, 20px) | `Lyrics` (12px/regular) | Activates lyrics-only view |
| Solfège | `FileImage` (lucide, 20px) | `Solfège` (12px/regular) | Activates solfège view |
| Play | `Play`/`Pause` (lucide, 20px) | `Play`/`Pause` (12px/regular) | Triggers play mini-bar slide-in; toggles playback |

**Active view indicator:** The active view button (Staff / Lyrics / Solfège) renders with `text-foreground` at full opacity and a 2px underline in `--foreground`. Inactive buttons render at `text-muted-foreground` (reduced opacity ~60%).

**Gear button:** Always `text-foreground` at 60% opacity; no active state (it opens a drawer, not a mode).

**Tap feedback:** `active:scale-[0.90] transition-transform duration-75` on each button.

## Component Inventory (Delta — New or Changed This Phase)

### A. `PsalmTopBar` — Updated

Replace two-row layout (top-bar + sub-bar) with the single-row anatomy above. Remove `TuneSubBar`. Export remains `PsalmTopBar`; internal restructure only.

**Tune tap target:** "♩ Crimond" label group is tappable (opens `TuneSwitcherSheet`). Apply `cursor-pointer hover:text-foreground transition-colors` to the center group. No separate pencil icon in this row.

**Overflow at ≥100 psalm number + long tune name:** "Psalm 100" (8 chars) + "♩ St. George's Edinburgh" → truncate tune name only, not psalm label. Psalm label never truncates.

### B. `GlassBottomBar` (new)

Persistent bottom chrome described above. Manages active view mode state (Staff / Lyrics / Solfège) and emits callbacks to the parent notation container.

**aria roles:** The three view buttons form a `role="radiogroup"` with each as `role="radio"` and `aria-checked`. Gear and Play are standard `role="button"`.

### C. `PlayMiniBar` (new)

A mini playback control bar that slides up from the bottom edge when Play is tapped.

**Position:** `fixed bottom-[56px]` (sits immediately above the glass bottom-bar, accounting for safe-area in the bottom-bar itself). Full viewport width.

**Height:** 52px.

**Surface:** `bg-background/90 backdrop-blur-sm border-t border-border/40`.

**Anatomy (left → right):**

| Slot | Element | Size |
|------|---------|------|
| Leading | `ChevronDown` icon-button — collapses mini-bar without stopping playback | 20px, 44×44 |
| Center | Progress scrubber — thin 2px track, full-width minus padding, `--foreground` fill | full flex-1 |
| Trailing | `SkipBack` · `Play`/`Pause` · `SkipForward` icon group | 20px icons, 44×44 each |

**Entry animation:** `translateY(100%)` → `translateY(0)` combined with `opacity-0` → `opacity-100`. Duration 200ms, easing `ease-out`. Implemented via Tailwind `transition-all` + toggling a `translate-y-0`/`translate-y-full` class.

**Exit animation:** Reverse — `translateY(0)` → `translateY(100%)` + `opacity-100` → `opacity-0`, 150ms ease-in.

**Reduced motion:** `@media (prefers-reduced-motion)` — skip translate animation; opacity only (100ms fade).

**Collapse vs. Stop:** `ChevronDown` collapses the mini-bar (visually hides it) but does NOT stop playback. The Play button in the glass bottom-bar toggles to `Pause` while audio runs. Re-tapping Play button when mini-bar is collapsed: re-shows mini-bar at current playback position.

**Empty state:** Mini-bar never renders until Play is tapped for the first time in a session.

### D. `GearDrawer` (replaces / reorganises FAB sheet sections)

The gear icon in the glass bottom-bar opens a `Sheet side="bottom"` (same primitive as the FAB sheet in 04.9.3, now triggered from the bottom-bar instead of a FAB).

**Sheet sizing:** `max-h-[60dvh]` with internal scroll. Drag handle at top.

**Sections (separated by `<Separator />`):**

**Section 1 — View**
- Heading: `View` (16px/semibold)
- Same radio group as bottom bar: Staff · Lyrics only · Solfège (full-width 44px buttons)
- Active state: `bg-foreground text-background` fill on the active button

**Section 2 — About this psalm** (collapsible, expanded by default)
- Heading: `About this psalm` (16px/semibold)
- Author, book, NKJV title
- Metre (full string, e.g. "C.M. (8.6.8.6)")
- Nave's topics (badges, wrap)
- Scripture refs (if present)
- Link: `Open full study view →`

**What moved OUT of this drawer:** The Audio section from the 04.9.3 FAB sheet is now entirely behind the Play button in the glass bottom-bar (`PlayMiniBar`). It does not appear in the gear drawer.

**FAB removal:** The 56×56 circular FAB from 04.9.3 is removed. The `GlassBottomBar` replaces both the FAB and the sub-bar.

### E. Onboarding Tour (new — custom React portal, ~80 LOC)

A one-time tip sequence shown to first-time visitors. Stored in `localStorage` key `psalter_tour_v1` — once dismissed, never shown again.

**Spotlight visual:** Dark overlay (`bg-black/60`, `fixed inset-0`, `z-[200]`) with a rounded cutout over the target element. Cutout implemented via CSS `box-shadow: 0 0 0 9999px rgba(0,0,0,0.60)` on the highlight wrapper — browser clips to the element bounds + 8px padding. Highlight wrapper uses `border-radius: 8px`.

**Tour steps (4 total):**

| Step | Target | Tip copy |
|------|--------|----------|
| 1 | `[←]` arrow in top bar | `Swipe through all 150 psalms` |
| 2 | "♩ Crimond" tune label | `Tap to switch to a different tune` |
| 3 | Glass bottom-bar (Staff/Lyrics/Solfège buttons) | `Choose how you want to read — notation, lyrics, or solfège` |
| 4 | Play button in glass bottom-bar | `Tap to hear the tune played` |

**Tip bubble anatomy:**

```
┌─────────────────────────────┐
│  Tip copy (14px/regular)    │
│                             │
│  [Skip tour]  [Next →]      │
└─────────────────────────────┘
```

- Background: `bg-background border border-border rounded-lg shadow-lg`
- Padding: 16px (md token)
- Positioned below the spotlight target (8px gap) on mobile; above if target is in bottom half of viewport
- Width: `min(320px, 90vw)`
- `Next →` button: `Button variant="default"` (accent fill)
- `Skip tour` button: `Button variant="ghost"` (text only)
- Step indicator: `Step 1 of 4` (12px/regular, `text-muted-foreground`, centered above the two action buttons)

**Trigger:** Runs automatically on first page load of the new psalm view. Not triggered again unless `localStorage` key is cleared.

**Keyboard:** Escape key at any step = skip entire tour.

## Interaction States

### Proportional Zoom Heuristic

When the viewport width changes (orientation flip, browser resize, or initial render at a new width):

```
newStaffSize = clamp(baseSize × (newWidth / referenceWidth), 8, 40)
```

- `referenceWidth`: the viewport width at the moment the user last manually set a size via A+/A−, OR 375px if the user has never adjusted
- `baseSize`: the user's last explicit A+/A− value
- `clamp` bounds: 8px (minimum legible) to 40px (maximum before overflow risk)
- Trigger: ResizeObserver on the notation container, debounced 150ms, fires only when width changes by ≥8px

This heuristic runs silently — no notification to the user. A+/A− buttons remain available to override at any time; after an override, `referenceWidth` is updated to the current width.

### Play Mini-Bar — Entry / Exit

**Entry (Play tapped, mini-bar hidden):**
1. Mini-bar renders at `translate-y-full opacity-0`
2. Next frame: transition to `translate-y-0 opacity-100` over 200ms ease-out
3. Body scroll area remains unchanged — mini-bar is `fixed`, not in flow

**Exit (ChevronDown tapped):**
1. Transition to `translate-y-full opacity-0` over 150ms ease-in
2. After transition ends: set `display: none` (prevents focus trapping while hidden)

**Reduced motion fallback:** translate removed; only opacity transitions (100ms).

### Gear Drawer

Opens as `Sheet side="bottom"` — shadcn default animation (slide up, 240ms). Tap outside or swipe-down to close. Focus trap inside sheet while open.

### Tour Spotlight

1. Overlay renders at `opacity-0`, transitions to `opacity-100` over 150ms on mount
2. Target element receives `z-[201]` (above overlay) and the box-shadow cutout treatment
3. Tip bubble fades in 100ms after overlay completes
4. On `Next →`: overlay stays, target scrolls into view if needed, tip bubble cross-fades to next step (100ms fade-out → reposition → 100ms fade-in)
5. On `Skip tour` or `Done`: overlay fades out 150ms → unmount → write `psalter_tour_v1=done` to localStorage

**Scroll handling:** If a tour target is partially off-screen, `scrollIntoView({ behavior: 'smooth', block: 'center' })` before showing the step. The overlay and tip reposition after scroll settles (200ms delay).

### General Tap Feedback

All buttons: `active:scale-[0.95] transition-transform duration-75`. Reduced motion: `motion-reduce:active:scale-100`.

## Accessibility

Inherits all a11y requirements from 04.9.3, plus:

- **Bottom-bar view group:** `role="radiogroup"` with each view button as `role="radio"` and `aria-checked={active}`. Gear and Play are `role="button"`.
- **Play mini-bar:** Collapse button has `aria-label="Collapse player"`. Progress scrubber: `<input type="range">` with `aria-label="Playback position"`.
- **Tour overlay:** `aria-live="polite"` region announces step copy on change. Tour trap: focus locked to tip bubble while tour is active. Escape exits at any step.
- **Tour spotlight element:** Does not receive focus — it is a visual affordance only. Screen reader reads tip copy, not the spotlit element again.
- **Reduced motion:** All tour transitions respect `prefers-reduced-motion: reduce` (opacity-only fallback).
