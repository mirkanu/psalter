# Phase 04.9.4 Plan 03: Dynamic Zoom Summary

**Added the proportional zoom heuristic to SingingView: on viewport-width change (resize / orientation flip / visualViewport), baseSize recomputes as `clamp(baseSize × newWidth / referenceWidth, 8, 40)` with a 150ms debounce and 8px delta floor; manual A+/A− overrides reset the reference width.**

## Performance

- **Duration:** ~4 min
- **Tasks:** 1
- **Files created:** 0
- **Files modified:** 1

## Accomplishments

- `SingingView` now owns a `referenceWidthRef` initialised to `window.innerWidth` (375 SSR fallback) and a `baseSizeRef` that mirrors the `baseSize` state via a one-line sync effect.
- A single `useEffect` registers three viewport-width listeners (`resize`, `orientationchange`, `window.visualViewport.resize`) sharing one debounced handler.
- Handler: 150ms `setTimeout`, reads `window.innerWidth`, returns if delta `< 8px` (suppresses mobile URL-bar churn), otherwise computes `Math.round(Math.max(8, Math.min(40, current * newWidth / refWidth)))`, updates `referenceWidthRef`, and calls `setBaseSize` only when the rounded value changed.
- `handleBaseSizeChange` wrapper updates `referenceWidthRef.current = window.innerWidth` before forwarding to `setBaseSize` — wired to both `NotationRendererClient.onBaseSizeChange` and `GlassBottomBar.onBaseSizeChange` so manual A+/A− tap (from either surface) re-baselines the heuristic.
- localStorage persistence effect for `baseSize` (line 127) is untouched and continues to run on each `setBaseSize`.
- No changes to `NotationRenderer`'s own staffWidthFactor resize listener (per plan: do NOT touch).
- No horizontal-overflow regression: the body wrapper's `overflow-x-hidden` and AbcPlayer's `staffwidth - 16px` padding accounting from Phase 04.9.3 remain in place; the new heuristic only mutates `baseSize` state — it never bypasses the existing width clamp.

## Decisions Made

- Refs (not state) for `referenceWidth` and `baseSize` snapshot — handler runs inside a `setTimeout` closure that must read live values without re-binding listeners every time `baseSize` changes.
- Initialise `referenceWidthRef` twice: once at declaration (SSR-safe with 375 fallback), once at effect mount post-hydration (overrides the fallback with the real width before the first event fires).
- Inline `Math.max(8, Math.min(40, ...))` clamp at the call-site rather than extracting a helper — the formula appears once and inlining keeps the bounds visible alongside the multiplication.
- Skip `setBaseSize` when `rounded === current` to avoid a no-op re-render under continuous resize drags.
- Update `referenceWidthRef.current = newWidth` BEFORE the rounded-equality short-circuit so subsequent events scale from the latest reference even when the computed size hit a clamp boundary.
- `handleBaseSizeChange` is passed to both `NotationRendererClient` and `GlassBottomBar` — either surface that exposes a manual size control re-baselines the heuristic on use, satisfying the must-have "User manual A+/A− override updates the reference width".
