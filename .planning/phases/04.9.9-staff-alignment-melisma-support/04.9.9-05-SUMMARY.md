## What Was Built

### Root Cause A Fix — syllabicCountToRawIndex (abc-melisma.ts)

The old boundary code used `splitPoints` (e.g., `[8, 14, 22]` for CM) as raw indices into `allPassings[]`. When earlier phrases contain passing notes, the 22nd raw event is not the 22nd syllabic note — it may be in the middle of phrase 2. The new `syllabicCountToRawIndex()` helper walks `allPassings[]`, counting only non-passing (syllabic) events, and returns the raw index one past the Nth syllabic event, inclusive of any trailing passing notes.

Example: soprano with 6 passing notes in phrases 0-2 (36 total events):
- OLD: phrase 3 starts at raw 22 → 14 tokens (bleeds phrase-2 events into phrase 3)
- NEW: phrase 3 starts at raw 28 → 8 tokens (correct)

### Root Cause B Fix — padWLineToNoteCount (NotationRenderer.tsx)

Added a `padWLineToNoteCount(wLine, musicSubLine)` helper that:
1. Counts note heads in the corresponding music sub-line using `countNoteHeads()`
2. If tokens < noteCount, appends `_` tokens to reach exact alignment
3. Never truncates; catches any errors and returns wLine unchanged

Applied at both w: push sites:
- Proportional-split path: `chunk → padWLineToNoteCount(chunk, musicSubLines[sub])`
- Structured path: `wLineForSyllables(text, i) → padWLineToNoteCount(wRaw, musicSubLines[sub])`

### countNoteHeads (abc-phrases.ts)

Pure function copied verbatim from `scripts/annotate-phrase-breaks.ts` (which has Node-only top-level imports incompatible with browser bundling). Strips info-field lines (w:, K:, V:, etc.), grace note groups, text annotations, decorations; counts chords as 1; subtracts tied continuations. No DOM, no fs, no I/O.
