# Phase 04.9.9 Plan 02: buildWLineFromSolfa — Melisma-Aware w: Line Generator Summary

New pure module `abc-melisma.ts` implementing `buildWLineFromSolfa`: hybrid dot-pair + duration-heuristic `w:` line generator that emits `_` at passing-note positions for melismatic Scottish Psalter tunes.

## What Was Built

### src/lib/abc-melisma.ts

New module exporting `buildWLineFromSolfa(soprano, doh, time, phraseIndex, meter, syllables, warnings): string`.

**Algorithm:**

1. Calls `getPassingPositions(soprano, doh, time)` (Plan 01) to get a boolean array for all note events in the tune.
2. Slices to the correct phrase range using an inlined `getSplitPointsForMeter` (CM n=4 → `[8, 14, 22]`, LM → `[8, 16, 24]`, etc.).
3. Counts syllabic slots (non-passing positions) and compares to syllable token count from `syllabifyForAbc`.
4. **Duration heuristic:** When syllabic slots exceed syllable tokens, finds all non-passing notes, sorts by ascending duration, and promotes the shortest ones to passing (`_`) until counts balance. This handles tunes where 3-slot cells (e.g. `m:r:r`) create extra notes not tagged by dot-pair detection.
5. Logs a warning (not a crash) if mismatch remains after heuristic — only reachable in degenerate cases.
6. Builds the output string: `_` for passing positions, syllable token for syllabic positions, one token per note.

**Key implementation decision:** `getSplitPointsForMeter` is inlined as a pure TypeScript function. `scripts/annotate-phrase-breaks.ts` has the same logic but pulls in `dotenv`, `postgres`, and `node:fs` at the module top-level, which would break the browser bundle.

### src/lib/abc-melisma.test.ts

7 unit tests with calibrated test sopranos:

- `NO_PASSING_SOPRANO`: 22 single-beat events, phrase 0 = 8 notes with no dot-pairs.
- `CRIMOND_LIKE_SOPRANO`: 31 events, phrase 3 = 9 notes with 2 dot-pair passings (positions 3 and 8 within phrase).

Test coverage:
1. Phrase 0 exact match (8 syllables, 8 notes) → no `_` tokens, no warnings
2. Phrase 3 with dot-pairs → `_` at passing positions (≥2)
3. Token count equals note count for melismatic phrase (9 tokens for 9 notes)
4. Heuristic: 7 syllabic slots + 4 tokens → heuristic converts 3 more to `_`, final syllabic tokens = 4 correct words
5. Heuristic mono-syllable: 8 slots + 1 token → 7 `_` + 1 syllable = 8 total tokens
6. Warning path (too few notes for syllable count) → does not crash
7. Empty phrase (soprano beyond phrase boundary has 0 events) → returns `''`

**2. [Rule 1 - Bug] `*` fallback test was unreachable**

- **Found during:** Task 2 test run
- **Issue:** The plan's test for `*` emission assumed that too few syllables would leave syllabic positions unfilled. But the duration heuristic always achieves balance (all non-passing notes are candidates), so `sylTokens[sylIdx]` is never `undefined`. Result: heuristic converts surplus notes to `_` instead.
- **Fix:** Replaced `*` test with a heuristic behavior test (7 `_` for 1 monosyllabic token over 8 notes). The `*` fallback code remains in the implementation as a safety net but is unreachable in practice. Documented in decisions.
- **Files modified:** `src/lib/abc-melisma.test.ts`
