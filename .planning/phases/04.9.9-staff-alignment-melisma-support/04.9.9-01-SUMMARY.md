# Phase 04.9.9 Plan 01: Passing-Note Detection in Sol-Fa Parser Summary

Zero-cost melisma detection via index-aware dot-pair parsing: `NoteEvent.passing` flag and `getPassingPositions` export.

## What Was Built

Extended `solfege-parser.ts` so the parser tracks which note events arise from the second token of a dot-pair slot (e.g. `f.m` → f is syllabic, m is passing/melismatic). Added a new `getPassingPositions(soprano, doh, time): boolean[]` export that Plan 02 (`abc-melisma.ts`) will consume to decide whether to emit `_` or a syllable token in the ABC `w:` field.

## Changes

### src/lib/solfege-parser.ts

- `NoteEvent` interface: added `passing?: boolean` and marked as `export`
- `addNote` inner function: gains optional `passing?: boolean` parameter; spreads `{ passing: true }` when truthy
- `parseVoiceLine` subTokens loop: converted `for...of` to index-aware `for (let si = 0; si < subTokens.length; si++)`. `isPassing = halfBeat && si > 0` marks second+ tokens of dot-pairs
- Added `getPassingPositions` export (lines ~430–455) wrapping `parseVoiceLine`

### src/lib/solfege-parser.test.ts (new)

5 unit tests covering:
1. All-false for tunes with no dot-pairs
2. Second token of a single dot-pair tagged `true`
3. Hold token does not create a new event
4. Crimond-style phrase with two dot-pairs produces exactly 2 passing positions
5. First token of a dot-pair is NOT passing
