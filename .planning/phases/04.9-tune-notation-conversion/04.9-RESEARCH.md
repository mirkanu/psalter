## Summary

Phase 4.9 converts 168 solfège JPEG files into ABC notation strings via Claude vision, stores them in `tunes.abc_notation`, and enables live abcjs rendering on all tune and psalm pages without JPG fallback. The spike confirmed viability: Claude vision correctly extracts the soprano line, reads the DOH key from the image header, handles chromatic accidentals (`se` → `^G`), and produces valid ABC notation.

The key infrastructure facts are: `@anthropic-ai/sdk` is not yet installed in this project (the spike used raw `fetch()`); the correct model API IDs are `claude-haiku-4-5` and `claude-sonnet-4-6`; `abcjs.parseOnly()` works in Node.js without a DOM and is the right validation mechanism (presence of `.warnings` array indicates parse errors); the existing `slugifyTuneName` function in `scripts/download-tunes.ts` is the exact function to reuse for image-to-tune mapping.

**Critical gap:** Only 144 of 172 tunes have solfège images on disk. The maximum achievable ABC coverage from this pipeline is 144/172 = 83.7%, which is below the D-09 acceptance bar of 95%. This must be resolved in planning — either by adjusting the acceptance bar, sourcing the 28 missing tunes' ABC from staff images or another source, or treating dummy/admin tunes as excluded from the denominator.

**Primary recommendation:** Install `@anthropic-ai/sdk`, use `parseOnly()` for validation (no DOM required), import `slugifyTuneName` from `download-tunes.ts`, use sequential calls with a 1–2 second inter-call delay to stay within Tier 1 rate limits.

### Pattern 1: Claude Vision Call (Multi-Image)

**What:** Send one or more base64 JPEG images in a single `messages.create` call.
**When to use:** Always — both single-page and multi-page tunes use this same pattern (just include more image blocks for multi-page).

```typescript
// Source: [VERIFIED: official Anthropic docs + Context7 /anthropics/anthropic-sdk-typescript]
import Anthropic from '@anthropic-ai/sdk'
import * as fs from 'node:fs'

const client = new Anthropic({ apiKey: process.env.PSALTER_ANTHROPIC_API_KEY })

async function callVision(imagePaths: string[], prompt: string, model: string) {
  const imageBlocks = imagePaths.map(p => ({
    type: 'image' as const,
    source: {
      type: 'base64' as const,
      media_type: 'image/jpeg' as const,
      data: fs.readFileSync(p).toString('base64'),
    },
  }))

  const response = await client.messages.create({
    model,
    max_tokens: 2000,
    messages: [{
      role: 'user',
      content: [...imageBlocks, { type: 'text', text: prompt }],
    }],
  })

  return (response.content[0] as { type: 'text'; text: string }).text
}
```

### Pattern 2: abcjs Server-Side Validation

**What:** Use `abcjs.parseOnly()` in Node.js to detect malformed ABC — no DOM required.
**When to use:** After every LLM call; again before each DB write in `apply-abc-notation.ts`.

```typescript
// Source: [VERIFIED: live Node.js test against installed abcjs 6.6.3]
import * as abcjsModule from 'abcjs'
const abcjs = (abcjsModule as any).default ?? abcjsModule

function validateAbc(abcStr: string): { valid: boolean; warningCount: number } {
  const result = abcjs.parseOnly(abcStr)
  const tune = result[0]
  const hasNotes = tune.lines?.some((l: any) =>
    l.staff?.some((s: any) => s.voices?.some((v: any) => v.length > 0))
  )
  const warnings = tune.warnings ?? []
  return { valid: hasNotes && warnings.length === 0, warningCount: warnings.length }
}
```

**Key finding:** `parseOnly()` returns `tune.warnings` (array) when the ABC contains unknown characters or invalid tokens. An absence of `.warnings` means clean parse. Verified patterns:
- `^F` = F-sharp (correct ABC) — no warnings [VERIFIED]
- `F#` = F-sharp (wrong — spike used this) — produces warnings [VERIFIED]
- `F#2` = wrong; use `^F2` [VERIFIED]
- Corrected Dundee with `^F2` instead of `F#2` — zero warnings [VERIFIED]

### Anti-Patterns to Avoid

- **Using `F#` in ABC output:** ABC notation uses `^` for sharp, not `#`. The existing hand-crafted seed ABCs use `F#` which produces warnings. The LLM prompt must explicitly state "use `^` for sharps (e.g. `^F`, not `F#`)".
- **Top-level await in `.ts` scripts:** tsx errors with "Top-level await is currently not supported with the 'cjs' output format". Wrap all async code in `async function main() { ... }` and call `main().catch(...)`.
- **Committing `DEBATES_ANTHROPIC_API_KEY` usage permanently:** Use `PSALTER_ANTHROPIC_API_KEY` as the env var name; bootstrap with the Debates key but add a `PSALTER_ANTHROPIC_API_KEY` to `/home/services/.env.production` before committing the script.
- **Re-implementing slugifyTuneName:** Import from `./download-tunes` to guarantee consistency with how files were actually named during the original download.
- **Sending PNG files as `image/jpeg`:** A small number of staff images are `.png` (e.g., `diademata-staff-0.png`). Solfège files appear to all be JPEG, but check file extension before setting `media_type`.

## Common Pitfalls

### Pitfall 1: Sharp Notation — `F#` vs `^F`

**What goes wrong:** The LLM (and the spike) produce `F#` notation which is not valid ABC. `abcjs.parseOnly()` reports warnings. The existing hand-crafted seed ABCs in `scripts/seed-abc-notation.ts` also use `F#` — they fail validation too.
**Why it happens:** `F#` is standard music notation; ABC uses `^` prefix for sharps.
**How to avoid:** Explicitly state in the prompt: "ABC notation uses `^` for sharps (e.g. `^F` not `F#`, `^C` not `C#`)."
**Warning signs:** `parseOnly()` returns warnings containing "Unknown character ignored: ... `#`".

### Pitfall 2: Held Note Duration Underestimation

**What goes wrong:** Spike revealed the LLM slightly undercounts held note values (`c3` instead of `c4` for a whole note in C time).
**Why it happens:** Tonic sol-fa `d :—` with a following dash represents a whole note; the LLM may read each `:` division as a separate unit without correctly adding the prolongation dash.
**How to avoid:** Add rhythm clarification to the prompt: "In C time (common time), `d :—` means doh held for a full bar (4 beats = `d4` in ABC with L:1/4). `d :-` means doh held for 2 beats (`d2`). The colon marks a beat boundary; `—` adds one more beat."
**Warning signs:** Tunes where the ABC bar lengths don't add up to the time signature total.

### Pitfall 3: 95% Acceptance Bar vs. Actual Solfège Coverage

**What goes wrong:** D-09 sets a 95% acceptance bar (164 of 172 tunes). Only 144 tunes have solfège images on disk. Maximum achievable: 144/172 = 83.7%.
**Why it happens:** 28 tunes were added to Airtable without solfège attachments (staff-only or no images). Two are dummy admin entries (`"do NOT use aots for this psalm"`, `"use aots for this psalm"`).
**How to avoid:** Planning must either (a) adjust the acceptance bar to 144/172 or (b) source ABC for the ~26 missing non-dummy tunes via a separate mechanism. Flag this to the user before Wave 1 begins.
**Warning signs:** Script completes with fewer than 164 DB updates even when 0 LLM failures occur.

### Pitfall 4: Multi-Page Order Ambiguity

**What goes wrong:** `aurelia-solfege-0.jpg` and `aurelia-solfege-1.jpg` are named with page index from Airtable download order — which may or may not be musical page order.
**Why it happens:** Airtable attachment order is undefined; files were saved in download order.
**How to avoid:** Per D-07, send all pages in one LLM call and ask the LLM to determine ordering from visual cues. Prompt must include: "If multiple pages are provided, identify which is the first page based on the page number visible on each image or musical continuity, then transcribe the soprano line from page 1 first, continuing on subsequent pages."
**Warning signs:** Aurelia ABC has an abrupt musical break or repeats the first line.

### Pitfall 5: Rate Limit at Tier 1

**What goes wrong:** Tier 1 Haiku allows 50 RPM and 50,000 ITPM. A 1.5 MB image encodes to ~2 MB base64, which is roughly 1,600 image tokens per Anthropic's counting. With 144 sequential calls, each ~2,500 input tokens (image + prompt), total input is ~360,000 tokens. At 50,000 ITPM, this needs ~7 minutes. Sequential calls at 1–2 second intervals stay well within the RPM limit.
**Why it happens:** No rate limiting in the spike code — it's not a problem at 3 images, but 144 calls without any pacing could spike ITPM.
**How to avoid:** Sequential calls with a `await new Promise(r => setTimeout(r, 1000))` delay between tunes. Do NOT use `Promise.all` across all 144 tunes at once.
**Warning signs:** `429` errors with `retry-after` header appearing after first 20–30 calls.

### Pitfall 6: Unicode Tune Names in Slugification

**What goes wrong:** `Gräfenberg` slugifies to `gr-fenberg` (the `ä` is stripped, not transliterated). This is what the download script actually produced — the file on disk IS `gr-fenberg-solfege-0.jpg`.
**Why it happens:** The slug function strips non-ASCII via `[^a-z0-9]+` → `-`.
**How to avoid:** Use `slugifyTuneName` as-is from `download-tunes.ts`. Do not normalise unicode first — that would break the match.
**Warning signs:** `MISSING:` log entry for Gräfenberg.

## Code Examples

### Complete OCR Script Structure

```typescript
// Source: [ASSUMED] — based on patterns from seed-abc-notation.ts and download-tunes.ts
#!/usr/bin/env npx tsx
/**
 * OCR solfège JPEGs via Claude vision → solfege-ocr.json
 * Run: npx tsx scripts/ocr-solfege.ts
 * Resume: re-run; already-processed tunes are skipped if JSON entry exists with status=success
 */
import 'dotenv/config'
import * as fs from 'node:fs'
import * as path from 'node:path'
import Anthropic from '@anthropic-ai/sdk'
import { drizzle } from 'drizzle-orm/postgres-js'
import postgres from 'postgres'
import * as schema from '../src/db/schema'
import * as abcjsModule from 'abcjs'
import { slugifyTuneName } from './download-tunes'

const TUNES_DIR = path.join(process.cwd(), 'public/tunes')
const OUTPUT_PATH = path.join(process.cwd(), 'scripts/output/solfege-ocr.json')

const client = new Anthropic({ apiKey: process.env.PSALTER_ANTHROPIC_API_KEY })
const db = drizzle({ client: postgres(process.env.DATABASE_URL!), schema })
const abcjs = (abcjsModule as any).default ?? abcjsModule

async function main() {
  const tunes = await db.select().from(schema.tunes).orderBy(schema.tunes.id)
  
  // Load existing output to enable resume
  const existing: Record<number, any> = {}
  if (fs.existsSync(OUTPUT_PATH)) {
    JSON.parse(fs.readFileSync(OUTPUT_PATH, 'utf8')).forEach((e: any) => {
      existing[e.id] = e
    })
  }

  const results = []
  for (const tune of tunes) {
    if (existing[tune.id]?.status === 'success') {
      results.push(existing[tune.id])
      continue  // Skip already-processed
    }

    const slug = slugifyTuneName(tune.name)
    const pages = findSolfegePages(slug)
    
    if (pages.length === 0) {
      results.push({ id: tune.id, name: tune.name, slug, status: 'no_image', abc: null })
      continue
    }

    const abc = await tryGetAbc(pages, tune.name)
    results.push({ id: tune.id, name: tune.name, slug, ...abc })

    fs.mkdirSync(path.dirname(OUTPUT_PATH), { recursive: true })
    fs.writeFileSync(OUTPUT_PATH, JSON.stringify(results, null, 2))

    await new Promise(r => setTimeout(r, 1200))  // Rate limiting: ~50 RPM max
  }
}
```

### The Production Prompt

```typescript
// Source: [VERIFIED: spike script + corrections from pitfall analysis]
const PROMPT = `This image shows a page from a Scottish Psalter with tonic sol-fa (Curwen notation) arranged for SATB (4-part harmony). If multiple pages are provided, identify the first page from the page number or musical continuity, then read pages in order.

Extract ONLY the soprano (top) voice line and convert it to ABC notation.

Tonic sol-fa conventions:
- d=doh, r=ray, m=me, f=fah, s=soh, l=lah, t=te
- Apostrophe after note = upper octave (d' = high doh); subscript comma = lower octave (,l = low lah)
- Colons separate beats: "d :m :s :d'" = 4 crotchets in C time
- Dash (-) after a beat = hold for that beat: "d :- :m :-" = d for 2 beats, m for 2 beats
- Long dash (—) = hold entire beat group; "d :—" in a half-bar = 2-beat hold
- Chromatics: se = sharpened soh; fe = sharpened fah; te = flattened te; etc.
- | = barline; :|| or |: = repeat bar; double bar = end

ABC notation rules:
- Use ^ for sharps (^F not F#), _ for flats (_B not Bb)
- Note lengths: with L:1/4, a crotchet = 1, minim = 2, semibreve = 4; e.g. d4 not d alone for a whole note
- In C time (M:C), each bar has 4 quarter-note beats

Output a complete ABC string with these headers exactly:
X:1
T:[tune name from header]
M:[meter: C for common time, 3/4 for triple, etc.]
L:1/4
Q:1/4=76
K:[key from DOH: DOH=C → K:C, DOH=G → K:G, DOH=F → K:F, etc.]
[note sequence with barlines]

Respond with ONLY the ABC string, no other text.`
```
