# Phase 05.3: /daily Calendar View (INSERTED) - Context

**Gathered:** 2026-06-20
**Status:** Ready for planning

<domain>
## Phase Boundary

Replace the flat 365-row `/daily` list with: (1) a "today" hero card pinned at the top showing today's reading without scrolling, and (2) a monthly calendar grid with prev/next month navigation where each cell links to the psalm for that day. Includes a data migration to add `startingVerse` + `endingVerse` to `daily_readings` from Airtable.

</domain>

<decisions>
## Implementation Decisions

### Data Migration — Verse Ranges
- **D-01:** The Airtable "365 Days" table has `Starting Verse` and `Ending Verse` (number fields) that were never migrated. These MUST be added to `daily_readings` as `starting_verse integer` and `ending_verse integer` columns and backfilled from Airtable in this phase.
- **D-02:** Calendar cells and the today card will display psalm references in the format "50:1-8" (using the migrated verse range data). Without this migration, only "Ps 50" would be possible.

### Today Hero Card
- **D-03:** The top of `/daily` shows a visually prominent card with: today's full date, day number, psalm reference (e.g. "Psalm 50:1-8"), the psalm's KJV bible_title, and a **"Sing psalm"** button linking to `/psalms/[id]`.
- **D-04:** The today card must be visible without scrolling on page load (no client-side scroll trick needed — it's rendered at the top of the page).

### Monthly Calendar Grid
- **D-05:** The calendar shows Jan–Dec of the current year. Prev/next month buttons navigate between months. Wrapping past December loops to January (the plan is cyclic).
- **D-06:** The calendar heading shows the month and year (e.g. "June 2026").
- **D-07:** Each day cell shows two lines: the calendar day number (large) + psalm reference below (e.g. "50:1-8"). Matches the iOS calendar density pattern.
- **D-08:** Today's cell is highlighted (distinct background/border — consistent with today card above).
- **D-09:** Days with no reading entry (none expected — the plan covers all 365 days) are displayed as empty cells.

### Day Click Behavior
- **D-10:** Tapping a day cell navigates to `/psalms/[psalmId]`. No inline detail panel. No `/daily/[day]` detail page needed going forward (the existing `/daily/[day]` route may remain but is not linked from the calendar).
- **D-11:** On both desktop and mobile, click goes directly to `/psalms/[id]`. iOS monthly calendar density is sufficient to display the psalm reference without needing a tap-to-reveal step.

### Removed: Flat List
- **D-12:** The flat 365-row `<ol>` in `page.tsx` and the `DailyPlanClient` scroll-to-today component are replaced entirely. Both files will be rewritten.

### Future (not in this phase)
- Verse-range deep-linking into `/psalms/[id]` (pre-selecting correct verses) — deferred to a future phase when verse selection UI is built.

</decisions>
