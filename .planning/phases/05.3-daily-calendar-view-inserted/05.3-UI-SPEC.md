No intermediate weights. Only 400 and 600.

## Surface Anatomy

### Page Layout

- Route: `src/app/daily/page.tsx` (rewrite in place)
- `export const dynamic = 'force-dynamic'` — preserved (today detection requires runtime date)
- Container: `max-w-3xl mx-auto px-4 sm:px-6 lg:px-8 py-6 md:py-8` — matches existing pattern
- Page heading: `<h1>` "Daily Reading Plan" at 20px `font-semibold` above the today card. Consistent with site-wide h1 convention (`font-semibold` not `font-bold`, per 04.8 cross-cutting constraint).
- Stack order (top to bottom):
  1. `<h1>` — "Daily Reading Plan"
  2. Today hero card
  3. `<Separator>` (8px vertical margin above and below)
  4. Monthly calendar section (heading + grid + nav)

### Today Hero Card

- Component: shadcn `<Card>` with a left accent border stripe.
- Surface: `bg-muted` (Secondary color — makes it distinct from page background).
- Left border: `border-l-4 border-primary` — same accent stripe pattern as existing today row in flat list.
- Internal layout (top to bottom inside `CardContent`):
  1. Date + day number row: `<time>` formatted as "Saturday, 20 June 2026" (full weekday name, ordinal-free) + "Day {N}" badge. Both at 14px weight 400 `text-muted-foreground`. Horizontal row, small gap.
  2. Psalm reference: "Psalm 50:1-8" at 28px weight 600 `text-foreground`. This is the largest text on the page — draws the eye immediately.
  3. Psalm bible title (KJV `bible_title`): e.g. "The Lord Is My Shepherd" at 14px weight 400 `text-muted-foreground italic`. One line, truncate if overlong.
  4. "Sing psalm" button: `<Button>` with `variant="default"` (filled primary). Label: "Sing psalm". Links to `/psalms/{psalmId}` via `<Link>` wrapping or `asChild`. Placed below the psalm title, left-aligned. Full-width on mobile (`w-full`), auto-width on desktop.
- No verse range notes field displayed in the card (notes column in daily_readings is distinct from verse range; verse range is expressed via psalm reference "50:1-8" already).
- If `starting_verse` is null (migration not complete or missing data): display "Psalm 50" without the range. Never show "50:null" or "50:undefined".

### Monthly Calendar Section

- Section heading: "June 2026" (or current displayed month + year) at 20px weight 600. Centered or left-aligned — use centered for visual symmetry with month nav buttons.
- Month navigation row: `<button>` ChevronLeft | centered month heading | `<button>` ChevronRight. Horizontal flex, items-center, justify-between. Button variant: `ghost` (no filled background by default, shows on hover). Touch target: `h-11 w-11` on mobile.
- Calendar grid: 7-column CSS grid (`grid grid-cols-7`). No dependency on react-day-picker for rendering.
  - Day-of-week header row: Mon Tue Wed Thu Fri Sat Sun (abbreviated, 3 chars). 12px weight 400 `text-muted-foreground text-center`. (Scottish Psalter week begins Monday — confirm with site context if needed; use Monday-first as default matching the stated "iOS calendar" reference.)
  - Day cells: Each cell is a `<Link href="/psalms/{psalmId}">` wrapping a `<div>`.
    - Height: `min-h-[44px]` on mobile; `min-h-[52px]` on desktop.
    - Padding: `p-1` (4px internal).
    - Layout: day number on top line, psalm ref on second line. Stacked column layout within the cell.
    - Day number: 14px weight 600 `text-foreground`. Right-aligned within the cell (matching iOS calendar density pattern).
    - Psalm ref: 12px weight 400 `text-muted-foreground`. E.g. "50:1-8". No "Ps" prefix (space is limited). If no verse range: "50" only. Right-aligned below day number.
    - Today cell: `bg-muted border-l-2 border-primary rounded-sm` — consistent highlight with existing today-row pattern.
    - Hover state: `hover:bg-muted/60` on non-today cells. `transition-colors duration-100`.
    - Empty cells (days before the 1st of the month and after the last): render as `<div>` (not `<Link>`), no content. Same grid cell for layout alignment.
    - Days with no reading entry: render cell with day number only, no psalm ref, no link (non-clickable `<div>`). Expected to be zero in practice (plan covers all 365 days).
  - Border between cells: `divide-y divide-border` on rows, or `border border-border` on each cell with `rounded-none` — use minimal 1px borders to maintain grid readability without visual clutter. Match the existing site's `divide-border` convention.

### Loading State (`loading.tsx`)

- Today card skeleton: `<Skeleton className="h-32 w-full rounded-lg" />` — approximates card height.
- Calendar skeleton: `<Skeleton className="h-64 w-full rounded-lg mt-4" />` — approximates grid height.
- Page heading skeleton: `<Skeleton className="h-8 w-48 mb-6" />`.
- All skeletons use shadcn `<Skeleton>` component (already installed).

## Data Flow Notes (for executor)

- All 365 `daily_readings` rows are fetched once server-side (same as existing `fetchAllDailyReadings`). The query must be updated to include `starting_verse` and `ending_verse` columns once the DB migration in this phase adds them.
- `getDayOfYear()` from `src/lib/daily.ts` determines today's day number. Reuse without modification.
- Month state (which month is displayed) is managed client-side via `useState` — the calendar section is a `'use client'` component. The today card is server-rendered (RSC).
- Client calendar component receives all 365 readings as a prop; month navigation filters in-memory. No additional DB calls on month change.
- Psalm reference format: if `startingVerse` and `endingVerse` are both non-null → `"{psalmId}:{startingVerse}-{endingVerse}"`; if either is null → `"{psalmId}"` only.

## Accessibility Notes

- Day cell links must have an `aria-label` that includes the full date and psalm: `aria-label="Day {N}, {Month} {day}: Psalm {ref}"`. This ensures screen readers announce meaningful content rather than "50:1-8".
- Today cell must have `aria-current="date"` on the cell link element.
- Month navigation buttons must have `aria-label="Previous month"` and `aria-label="Next month"`.
- The 7-column header row cells should use `<abbr title="Monday">Mon</abbr>` etc. for screen reader expansion.
- The "Sing psalm" CTA is a link styled as a button — use `<Link>` with `<Button asChild>` pattern so it renders as `<a>` semantically (correct for navigation, not form submission).
