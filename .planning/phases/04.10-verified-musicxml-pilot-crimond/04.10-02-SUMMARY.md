## Accomplishments

- `parseSlursFromMusicXml`: extracts 34 soprano notes from `Crimond_deBoer.musicxml` with per-note slur-start/slur-stop flags (matches §8 ground truth on the first 10 notes verbatim).
- `buildWTokens`: implements the §6 algorithm — for each note, emit a syllable (or `_` if exhausted); if the note starts a slur, walk forward emitting `_` until the slur ends. Output length always equals input note count (abcjs requirement).
- `countWTokens`: counts whitespace-separated tokens on `w:` lines (including `_`), used by the in-script validator.
- `weaveWLinesIntoPhrases`: walks the phrased ABC body and appends a `w: ...` line directly after each phrase's music body, slicing `wTokens` by per-phrase note-head count.
- End-to-end script: xml2abc → soprano extract → slur parse → buildWTokens → insertPhraseBreaks → weave w-lines → validate → write fixture.
- Generated `crimond-verified.abc` (426 bytes, 4 phrases, 4 w-lines, 3 `% PHRASE_BREAK` markers).

## Decisions Made

- **O-1 option-b PHRASE_BREAK positions `[10, 16, 24]`** (user decision at Task 1 checkpoint). Crimond becomes the first DB row with non-heuristic phrase breaks — Plan 04 must `--apply` with this exact CLI invocation to reproduce.

## Deviations from Plan

### 1. [Rule 1 - Bug] xml2abc.py treats `-o` as output DIRECTORY, not file
- **Found during:** Task 2 implementation, first invocation
- **Issue:** Plan skeleton suggested `python3 scripts/xml2abc.py SOURCE -o /tmp/crimond-deboer.abc` expecting an output file. xml2abc.py instead created a directory and emitted `Crimond_deBoer.abc` inside.
- **Fix:** Use `/tmp/crimond-deboer-abc` (directory), then `ls $tmpDir/*.abc` to locate the generated file. Pre-clean with `rm -f $tmpDir/*.abc` for idempotency.
- **Files modified:** `scripts/convert-crimond-musicxml.ts` (main flow only)
- **Commit:** `65b4d77`

### 2. [Process — branch isolation] Initial test commit landed on `master` instead of worktree branch
- **Found during:** Task 2 RED commit
- **Issue:** Bash tool cwd is reset between commands per env note. A `cd /data/home/psalter && git commit` invocation correctly switched to main repo for that single call; the commit (`7613bb8`) landed on `master` (where HEAD was) rather than on `worktree-agent-aa09c6136e8eae394`.
- **Fix (no destructive recovery):** Per #2924, did NOT `git update-ref refs/heads/master` to roll back. Instead cherry-picked the commit onto the worktree branch (`6aaa791`) and proceeded. **The stray commit `7613bb8` on `master` is identical content to `6aaa791` on the worktree branch — it will become a no-op when the merge orchestrator unifies them (already-applied diff).**
- **Followup for orchestrator:** when merging this worktree back, expect `master` to already contain a same-content commit; resolve via standard fast-forward or accept-theirs.
