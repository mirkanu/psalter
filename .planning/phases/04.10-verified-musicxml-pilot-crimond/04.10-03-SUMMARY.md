## Task 1 (checkpoint:decision) Outcome — O-2

**Selected: option-a — Stanza 1 verified; stanzas 2-6 heuristic fallback.**

User rationale: pilot scope is "verify one tune end-to-end"; the sing-test
predicate naturally hits stanza 1 (page 1). Honours the W-3 / pilot framing
without piling new renderer code on top of an unverified algorithm.

**Implementation shape in the renderer (recorded for Plan 04 triage):**

- The new branch is taken when `showLyrics && hasEmbeddedWLines(phraseBody)`.
- Cycle 0 emits the phrase body VERBATIM (music line + authored `w:` line).
- The branch then `continue`s, intentionally not entering the OLD inner
  cycle loop. For Crimond this means:
  - **Stanza 1 (cycle 0):** verified de Boer alignment renders. ✅
  - **Stanzas 2-6 in lyrics-on mode:** the phrase ALREADY emitted verbatim
    cycle-0 lines, so subsequent visible cycles share the same staff system
    without per-stanza w-lines. Documented as the known O-2-option-a
    limitation; user's sing-test predicate is stanza 1.
  - **Music-only mode** (`showLyrics=false`): the embedded branch is NOT
    taken; phrase flows through OLD heuristic path naturally.

## Accomplishments

- **`renderEmbeddedWPhrase`** (pure, unit-testable, no DOM/React/abcjs):
  given a `phraseBody` carrying `w:` line(s), returns the verbatim cycle-0
  lines plus a `needsHeuristicFallback` boolean array indexed by cycle.
  Throws on precondition violation (call site MUST gate on `hasEmbeddedWLines`).
- **NotationRenderer additive branch** at line ~781, BEFORE the existing
  `phraseLines.filter(...)` w-strip. Imports `hasEmbeddedWLines` and
  `renderEmbeddedWPhrase`. Heuristic functions (`buildWLineFromSolfa`,
  `syllabifyForAbc`, `splitMusicIntoSubLines`, `padWLineToNoteCount`) all
  remain in the file and untouched — they continue to drive the 149
  non-Crimond tunes.
- **`/dev/musicxml-preview`** route:
  - Server shell reads `.planning/research/abc-samples/crimond-verified.abc`
    via `readFileSync(path.join(process.cwd(), …))`.
  - Client wrapper renders BOTH `AbcPlayerPanel` (raw abcjs) AND
    `NotationRendererClient` (production pipeline) side-by-side, with an
    editable textarea over the fixture for in-route experimentation.
  - Both panels wrapped in `.abcjs-container` divs so the Plan 01 UAT
    selector matches either panel (UAT passes when at least one panel
    renders abcjs lyric tspans).

## Decisions Made

- **O-2 option-a (user decision):** see Task 1 outcome above.
- **Pure-helper extraction before wiring:** per RESEARCH.md Pitfall 7,
  vitest cannot import NotationRenderer.tsx (it imports abcjs which DOMs
  itself). Extracting the rendering logic into `abc-embedded-w-branch.ts`
  lets us prove correctness with vitest before the visual check.
- **Branch shape: `continue` not "fall through to old path for cycles 1+":**
  the plan's `<action>` STEP C diff sketched two alternative shapes
  (intrusive `cycleSkipSet` vs. simple `continue`). I picked `continue`
  per the plan's own explicit guidance: *"for the pilot, ONLY support
  cycleCount===1 in the embedded branch — `continue` above and let
  `visibleCycles.length>1` pages render the embedded phrase with cycle 0
  only. The user's sing-test predicate is stanza 1, so this is acceptable."*
  This keeps the change additive and removes the need to restructure the
  OLD inner cycle loop.
- **Multi-line dynamic() import collapsed onto a single line:** the
  acceptance criterion grep `dynamic.*ssr.*false` is a single-line regex.
  Prettier had formatted the calls across multiple lines so the regex
  matched 0 occurrences; reformatted to satisfy the verify gate.
