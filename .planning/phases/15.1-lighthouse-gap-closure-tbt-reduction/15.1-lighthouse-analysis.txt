## Why / regressed

Main-thread breakdown for / on the wave-1 build:
- Parse HTML & CSS: **2972ms** (Phase 15 baseline: 108ms) — 27× spike
- Script Evaluation: 1678ms (was 129ms in baseline)
- Style & Layout: 656ms

The homepage doesn't use PsalmListingGrid, so 15.1-02 is irrelevant. The 5 dynamic-import wrappers in 15.1-01 don't touch `/`'s critical path either. The likely regression source is in the Geist font config — `sub-domain: 'preload: true'` was added in Phase 15, but Plan 15.1-03's logo quality tweak went through a build that also touched `next.config.ts`. The Turbopack chunk graph may have rebuilt fragments that interact differently with the empty-cache first render. **ROOT-CAUSE is unclear without a followup investigation; suspect: Turbopack chunk re-shuffle triggered by the `qualities` array change pushed more CSS parsing onto the critical path.**

## Why /psalms and /psalms/23 didn't improve as expected

- The "irreducible framework floor" from `0r5n9xaeyh.pb.js` is the dominant cost:
  - /: 1066ms scripting (was 1134ms in baseline — actually slightly better)
  - /psalms: 2290ms scripting (was 2518ms baseline — 228ms better, marginal)
  - /psalms/23: 3030ms scripting (was 3665ms baseline — 635ms better, biggest improvement)
- The PsalmListingGrid batching (Plan 15.1-02) saved ~500-1000ms of hydration cost on /psalms, but it gets erased by overlapping framework-chunk evaluation in TBT scoring.
- The 5 dynamic-import wrappers (Plan 15.1-01) saved bundle size on psalm-detail but didn't reduce parse time enough to compensate for the framework floor.

## Recommended next move

POLISH-03 stays deferred at `[ ]` in REQUIREMENTS.md. Phase 15.1 closes as "code shipped but goal unmet." Three followup candidates, in order of cost/effect:

1. **(cheap)** Disable Cloudflare bot-challenge JS for `/`, `/psalms`, `/psalms/[id]` via a WAF rule (mitigates 5-10 pts but requires user action on Cloudflare).
2. **(moderate)** Investigate the `/` HTML-parse regression — likely a Turbopack re-chunking artifact from `next.config.ts.qualities` — and possibly revert q=90 → q=75 if the regression is bigger than the saving.
3. **(expensive)** React Server Components / framework chunk split for `0r5n9xaeyh.pb.js`. Out of scope for gap-closure; would be a separate Phase 15.2.

Verdict: code improvements in 15.1-01 + 15.1-02 + 15.1-03-Task-1 are real and shippable, but they did NOT collectively close the gap to 90+. Honest call.
