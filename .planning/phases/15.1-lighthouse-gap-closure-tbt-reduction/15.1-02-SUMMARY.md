# Phase 15.1 Plan 02: PsalmListingGrid hydration-cost reduction Summary

## One-Liner

Replace 5 separate `useLocalStorage` hooks in `PsalmListingGrid` with a single batched `useEffect` that reads all 5 keys at once (one JSON.parse per key, one `setState` after hydration), plus defer the search-input autofocus, the `matchMedia` listener, and the auto-open-advanced effect to that same hydration ref.

## What Changed

### Before

```tsx
const [advancedOpen, setAdvancedOpen] = useLocalStorage('psalms.advancedOpen', false)
const [showFirstLine, setShowFirstLine] = useLocalStorage('psalms.showFirstLine', false)
const [showMeter, setShowMeter] = useLocalStorage('psalms.showMeter', false)
const [showRecommendedTune, setShowRecommendedTune] = useLocalStorage('psalms.showRecommendedTune', false)
const [meterFilter, setMeterFilter] = useLocalStorage('psalms.meterFilter', 'all')
const isNarrowViewport = useMediaQuery('(max-width: 639px)')

useEffect(() => {
  if (typeof window !== 'undefined' && window.innerWidth >= 768) inputRef.current?.focus()
}, [])

useEffect(() => { setSelectedIndex(0) }, [trimmedQuery, meterFilter])

useEffect(() => {
  if (hasAdvancedFilter) setAdvancedOpen(true)
}, [hasAdvancedFilter])
```

5 `useEffect`s fire on first mount → 5 separate `JSON.parse` round-trips + a `matchMedia` listener install + a synchronous focus() call all queued in the bootup-time scripting window. Estimated 2518ms scripting cost on `/psalms`.

### After

```tsx
// Batched state — one useEffect reads all 5 keys.
const [persisted, setPersisted] = useState({...defaults})
const [isNarrowViewport, setIsNarrowViewport] = useState(false)
const hydratedRef = useRef(false)
const [hydrated, setHydrated] = useState(false)

useEffect(() => {
  let nextAdvancedOpen = false
  // ... 4 more locals
  try { const a = localStorage.getItem('psalms.advancedOpen'); if (a !== null) nextAdvancedOpen = JSON.parse(a) as boolean } catch {}
  // ... 4 more try/catch reads
  setPersisted({...})
  hydratedRef.current = true
  setHydrated(true)  // triggers matchMedia effect on next render
}, [])

function updatePersisted(key, value) {
  setPersisted((prev) => ({ ...prev, [key]: value }))
  if (hydratedRef.current && typeof window !== 'undefined') {
    try { localStorage.setItem(`psalms.${key}`, JSON.stringify(value)) } catch {}
  }
}

// matchMedia effect deferred via [hydrated] dep array:
useEffect(() => {
  if (!hydrated) return
  if (typeof window === 'undefined' || typeof window.matchMedia !== 'function') return
  const mq = window.matchMedia('(max-width: 639px)')
  setIsNarrowViewport(mq.matches)
  const handler = (e: MediaQueryListEvent) => setIsNarrowViewport(e.matches)
  mq.addEventListener('change', handler)
  return () => mq.removeEventListener('change', handler)
}, [hydrated])

// Search-input autofocus gated on hydratedRef:
useEffect(() => {
  if (!hydratedRef.current) return
  if (typeof window !== 'undefined' && window.innerWidth >= 768) inputRef.current?.focus()
}, [])

// setSelectedIndex skips first render:
const isFirstRenderRef = useRef(true)
useEffect(() => {
  if (isFirstRenderRef.current) { isFirstRenderRef.current = false; return }
  setSelectedIndex(0)
}, [trimmedQuery, meterFilter])

// Auto-open-advanced already gated on hydratedRef (from Task 1's setter swap):
useEffect(() => {
  if (!hydratedRef.current) return
  if (hasAdvancedFilter) updatePersisted('advancedOpen', true)
}, [hasAdvancedFilter])
```

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Plan's matchMedia effect cannot run after hydration in a single effect pass**

- **Found during:** Task 2 verification (test suite regression)
- **Issue:** The plan's `hydratedRef.current = true` syntax sets the ref synchronously inside the hydration effect's body. Effects with `[]` deps run in declaration order on mount — so when the matchMedia effect runs (also `[]` deps), `hydratedRef.current` is already `true`, and `window.matchMedia(...)` is invoked immediately. In jsdom (no matchMedia stub), this throws `TypeError: window.matchMedia is not a function` for every test that doesn't stub matchMedia.
- **Fix:** Added a `const [hydrated, setHydrated] = useState(false)` flag alongside `hydratedRef`. Hydration effect calls `setHydrated(true)`. The matchMedia effect's deps become `[hydrated]`, so it ONLY runs after the `setPersisted`/`setHydrated` re-render — safely after the localStorage reads complete. This preserves the SSR-safe default (`isNarrowViewport = false`) without throwing in jsdom. The `hydratedRef` is retained for the `updatePersisted` write-gate (refs are perfectly fine for synchronous guards in event handlers, where a re-render isn't needed).
- **Files modified:** `src/components/PsalmListingGrid.tsx`
- **Commit:** `cf91e6b`

**2. [Rule 1 - Bug] Duplicate `isNarrowViewport` state declaration**

- **Found during:** Task 2 verification (esbuild transform error)
- **Issue:** When moving the `useState` for `isNarrowViewport` into the persisted-block (per the plan's design intent of "one batched hydration effect"), the older in-place declaration at line 170 wasn't removed — leaving two `const [isNarrowViewport, setIsNarrowViewport] = useState(false)` declarations in the same function body. esbuild rejects duplicate identifiers.
- **Fix:** Removed the original line-170 declaration; kept the one in the persisted block.
- **Files modified:** `src/components/PsalmListingGrid.tsx`
- **Commit:** `cf91e6b` (rolled into the same Task 2 commit since the duplicate was caused by the refactor)

**3. [Rule 1 - Test asset] `screen.getByDisplayValue('LM')` does not match the shadcn SelectTrigger render shape**

- **Found during:** Task 4 verification
- **Issue:** The plan's literal `screen.getByDisplayValue('LM')` assertion failed because the shadcn `<SelectTrigger>` doesn't expose the selected value as a form input's `defaultValue`/`value` attribute. The trigger renders the selected option's text content as visible text inside a button.
- **Fix:** Replaced with `screen.getAllByText(/^LM$/)` (matches both the trigger label and the SelectItem value); used `toBeGreaterThan(0)` to express "at least one LM node exists in the DOM after hydration".
- **Files modified:** `src/components/PsalmListingGrid.test.tsx`
- **Commit:** `0d7acfe`
