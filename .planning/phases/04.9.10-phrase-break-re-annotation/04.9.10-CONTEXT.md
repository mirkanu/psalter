### Meter coverage
- **D-04:** Do NOT preemptively extend `getSplitPointsForMeter`. Run `--overwrite` first, sweep, then triage residuals. ## Existing Code Insights

### Reusable Assets
- `scripts/annotate-phrase-breaks.ts`: exports `insertPhraseBreaks`, `getSplitPointsForMeter`, `countNoteHeads` — all tested pure functions. The CLI `main()` with `--overwrite` and `--tunes` flags is production-ready.
- `scripts/uat/verify-staff-alignment.js`: Production-ready sweep script. Run as-is.

### Established Patterns
- `--overwrite` strips `% PHRASE_BREAK` lines, strips `w:` lines, collapses blank lines, then re-annotates with Path NH. This is idempotent.
- `padWLineToNoteCount` in `NotationRenderer.tsx`: safety net that pads short `w:` lines to match actual note count — handles data-gap tunes at render time without needing correct PHRASE_BREAKs.
- `phrasesForMeter` in `src/lib/abc-phrase-meter-map.ts`: determines `n` (number of phrases) per tune. CM/LM/SM → 4; DCM/DLM/DSM → 8. Other meters → 2 or 1.

### Integration Points
- DB update path: `drizzle().update(schema.tunes).set({ abcNotation: updatedAbc }).where(eq(schema.tunes.id, t.id))`
- The dev server at `http://localhost:3005` must be running for the Playwright sweep (it is — it was running for Plan 07 sweep earlier today).

</code_context>
