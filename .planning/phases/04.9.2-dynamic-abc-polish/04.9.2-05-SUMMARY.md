## Final wiring per route

### `/psalms/[id]` → `PsalmTabs` → `NotationRendererClient`
```tsx
<NotationRendererClient
  abc={pickAbcWithMarkers(primaryTune)}             // see Fix 1
  lyrics={psalmVersion.lyrics}
  scoreJpgUrl={primaryTune.scoreJpgUrl ?? null}
  solfegeJpgUrl={primaryTune.solfegeJpgUrl ?? null}
  tuneName={primaryTune.name ?? 'Tune'}
  tuneMeter={primaryTune.meter ?? null}
  stanzaMeter={psalmVersion.meter ?? null}          // D-20
/>
```

### `/tunes/[id]` → `NotationRendererClient`
```tsx
<NotationRendererClient
  abc={pickAbcWithMarkers(tune)}
  lyrics={firstLinkedPsalmVersion?.lyrics ?? ''}
  scoreJpgUrl={staffPages[0] ?? null}
  solfegeJpgUrl={solfegePages[0] ?? null}
  tuneName={tune.name ?? `Tune ${tune.id}`}
  tuneMeter={tune.meter ?? null}
  stanzaMeter={firstLinkedPsalmVersion?.meter ?? null}
/>
```

`firstLinkedPsalmVersion = tune.psalmVersionTunes?.[0]?.psalmVersion ?? null`; `tunesLyrics` is `firstLinkedPsalmVersion?.lyrics ?? ''`. If a tune has no linked psalm version (rare), the lyric column is empty but the staff still renders.

### Visual re-review iterations (Fix 1-3)
After visual re-review of the deployed site surfaced "the staff is one long row again on CM tunes" — D-19 had regressed at the data layer.

**Fix 1 — `pickAbcWithMarkers` (7695599):**
Some tunes carry both `abc_notation` (Phase 2 backfill, has `% PHRASE_BREAK` markers) and `abc_satb` (older SATB column, no markers). The renderer was selecting `abc_satb` first on those rows, then `splitOnPhraseBreaks` returned a single phrase. Added `pickAbcWithMarkers(tune)` to `src/lib/abc-phrases.ts`: returns the variant containing `% PHRASE_BREAK` markers; falls back to `abc_notation ?? abc_satb ?? ''`. Both routes now call it.

**Fix 2 — Unified single AbcPlayer (81d2c78):**
The original D-19 design mapped one `<AbcPlayer>` per phrase. Functional gaps: (a) playback only sounded the first phrase; (b) BPM/transpose controls applied per-instance and didn't sync; (c) note-highlight CSS targeted the global `.abcjs-current-note` class but only one instance had an active synth, so off-screen phrase rows showed a stale highlight. Refactored to a single `<AbcPlayer>` whose ABC string concatenates all phrases with native newlines — abcjs renders the same visual N-row staff layout, but there is exactly one synth, one BPM source, one transpose, and one highlight target. Phrase rows are now a visual property of the ABC source rather than a React structural property. Also unified the control bar: Stanza nav, View Mode, Size, and Playback share a single horizontal region with dividers.

**Fix 3 — Auto-advance during playback (61618e6):**
With one instance and one synth it became possible (and necessary) to advance pagination automatically as playback crosses phrase / cycle boundaries. Hooked into the abcjs synth's `onEvent` callback to track the current note index; when the index crosses a phrase-end or cycle-end boundary, `cyclePage` and/or `halfPage` advance. Manual Prev/Next interrupts auto-advance; pausing the synth halts further automatic transitions. Known limitation: BPM or key changes mid-play reset the synth chain and stop auto-advance — see Known Follow-ups.

## Deviations from plan

Discovered during visual re-review that some rows carry both `abc_notation` (markers) and `abc_satb` (no markers) and the existing tune fetcher returned `abc_satb` first. Added `pickAbcWithMarkers()` helper and rewired both routes. Commit 7695599.
2. **[Rule 2 — Critical UX] Per-phrase AbcPlayer instances broke playback, BPM sync, and note highlighting.** The plan's D-19 wording ("one AbcPlayer per phrase row") was honoured by Plan 04 but failed under interaction. Restructured to single instance with ABC-newline-driven row layout. Commit 81d2c78. Visual outcome unchanged at idle; functional outcome dramatically better under playback.
3. **[Rule 2 — Missing critical functionality] Auto-advance.** Plan 05 did not specify auto-advance; the precentor would have had to click Next mid-verse. Added once the single-instance refactor made it tractable. Commit 61618e6.

## Known Follow-ups (recorded, NOT fixed in this plan)

1. **Plan 02 marker-position bug — Crimond `% PHRASE_BREAK` lands after measure 13 of 15 instead of the natural midpoint.** Cosmetic only under the current architecture (rendering uses ABC's native newlines, not the marker position) but the marker is semantically wrong — it should mark the phrase midpoint. Likely affects most CM tunes. Algorithm fix for `insertPhraseBreaks` belongs in a follow-up phase.
2. **DB data quality — Psalm 23 stanzas 1+2 are joined in the DB `lyrics` (missing blank-line separator).** The stanza splitter sees them as one stanza. Pre-existing migration issue; not specific to 04.9.2.
3. **SATB phrase-break backfill not run.** Plan 02 targeted only `abc_notation`. A future run with `--target abc_satb` would mean the SATB render path is preferred when present (currently the `pickAbcWithMarkers` heuristic skips SATB whenever it lacks markers).
4. **BPM/Key change mid-play resets the auto-advance chain** — intentional, known limitation; documented for v2 polish. Currently the synth tears down and rebuilds on transpose/BPM, so the `onEvent` subscription drops; pagination snaps back to the manual position. Acceptable behaviour for v1.
