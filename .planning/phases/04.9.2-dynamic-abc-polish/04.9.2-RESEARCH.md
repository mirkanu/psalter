# Phase 4.9.2: Dynamic ABC Polish — Research

**Researched:** 2026-05-14
**Domain:** Client-only music notation polish (abcjs 6.6.3) — syllable alignment, responsive sizing, phrase navigation, fullscreen
**Confidence:** HIGH (existing code + abcjs official docs verified) / MEDIUM (iOS fullscreen — verified caveats but workaround is design choice)

## Summary

Phase 4.9.2 is **not** a greenfield phase. The repo already has a working `AbcPlayer` (interactive playback, transpose, BPM), `PsalmNotationPlayer` (stanza grouping, view modes, sticky score), and `lib/lyrics.ts` (syllabification via `nlp-syllables`). The phase reorganises these into a new `NotationRenderer` that (a) splits tunes into **phrases** at import time using `% PHRASE_BREAK` ABC comments, (b) injects `w:` syllable lines for the current phrase only at render time, (c) drives sizing via a CSS custom property `--staff-base-size` (not React state), and (d) supports a pseudo-fullscreen mode with sticky bottom navigation.

The CONTEXT.md locks 13 decisions (D-01..D-13) plus 2 claude-discretion items (D-14, D-15). The UI-SPEC is the design contract; this research is mostly **how-to-implement** rather than **what-to-build**.

**Primary recommendation:** Build `NotationRenderer` as a new component that composes the existing `AbcPlayer` for the staff render of one phrase at a time. Implement phrase splitting as a pure function over the stored `abc_notation` string (split on `% PHRASE_BREAK`). For fullscreen, use a CSS `position: fixed` overlay (no Fullscreen API call) — this works on iOS Safari where element-level Fullscreen API does not. Reuse `nlp-syllables` via the existing `syllabifyForAbc()`; do NOT swap libraries.

## User Constraints (from CONTEXT.md)

### Locked Decisions

**Phrase-splitting:**
- **D-01:** Phrase boundaries calculated at ABC import time (NOT at render time).
- **D-02:** Phrase breaks marked with ABC comment markers `% PHRASE_BREAK` (non-invasive, parseable by regex).
- **D-03:** Meter-dependent phrase lengths via predefined lookup table (CM → 2 phrases, LM → 2, SM → 2, double-CM → 4, etc.). Not algorithmic.
- **D-04:** Phrase structure follows **lyrical meter** (line breaks), not tune meter alone. CM (8.6.8.6) → split after 8+6 syllables, then again after next 8+6. Lyric structure is source of truth.

**Font sizing:**
- **D-05:** Font sizing via CSS custom property `--staff-base-size` on a root container. Drives abcjs scale, inline lyric text, AND verse stanza text. Not React state.
- **D-06:** Range 12–18px in 2px increments (12, 14, 16, 18). Four discrete sizes.
- **D-07:** Persists to localStorage.

**Component organisation:**
- **D-08:** Create NEW `NotationRenderer` component. Do not extend `AbcPlayer`.
- **D-09:** `NotationRenderer` manages phrase state INTERNALLY (parent passes `abc`, `lyrics`, etc., not phrase index).
- **D-10:** Render ONE PHRASE AT A TIME (not all-scrollable). Lighter DOM, matches UI-SPEC fullscreen layout.

**Syllable alignment:**
- **D-11:** Syllabify ON RENDER (not pre-computed in DB). No schema changes.
- **D-12:** Enhance `lib/lyrics.ts` with `buildAbcWithSyllables(baseAbc, lyrics, phraseIndex)`. All lyrics logic in one place.
- **D-13:** Generate `w:` lines for CURRENT PHRASE ONLY (not all stanzas).

## Project Constraints (from CLAUDE.md)

These directives have the same authority as locked decisions:

- **abcjs is client-only.** Any component calling `ABCJS.renderAbc` MUST: (1) be `'use client'`, (2) be imported via `dynamic(() => import('./X'), { ssr: false })`, (3) render inside `useEffect` with a `useRef` container, (4) have a `<Suspense>` skeleton fallback. `NotationRenderer` inherits this — its `dynamic({ ssr: false })` wrapper must exist on the consumer side (psalm/tune detail page), not inside the component.

- **No Airtable URLs in DB.** Not relevant to this phase (no migration).
- **Always test the golden path** (global CLAUDE.md). Playwright must verify: phrase navigation, A+/A−, fullscreen enter/exit, lyrics-only toggle. Run on Chromium at 375px, 768px, 1024px.
- **Perceived performance:** every interaction shows visible feedback within ~16ms. A+/A− must NOT trigger a full abcjs re-render if avoidable (CSS variable change should be sufficient where possible — note: changing `staffwidth` or `scale` DOES require re-render; only the lyric text scaling can be pure CSS).

### Pattern 1: ABC `w:` field syntax for syllable alignment
**What:** Lyrics under notes are aligned via `w:` lines immediately after the music line. Each token in the `w:` line aligns with one note in the preceding music line.
**When to use:** Every staff render that should show inline lyrics.
**Token meanings** [CITED: abcnotation.com/wiki/abc:standard:v2.1, section 5]:

| Token | Meaning |
|-------|---------|
| `word` | A whole-word syllable on one note. |
| `syl-` | Syllable continues to next syllable on the next note (hyphen = within-word break). |
| `_` (underscore) | Extends the previous syllable across this note (melisma). |
| `*` (asterisk) | Skip this note (no syllable). |
| `~` (tilde) | Hard space — multiple words on one note, displayed with a space. |
| `\-` | Literal hyphen character (rare in psalter use). |
| `|` (pipe) | Bar-line alignment marker — keeps lyrics aligned with the next bar. |
| `+:` | Continuation of a long `w:` line on the next line. |

**Example:**
```abc
w: Praise- ye the Lord with one ac- cord
```
Maps "Prai-" "se" to first two notes (hyphen rule), then "ye" "the" "Lord" "with" "one" "ac-" "cord" to the next 7 notes.

**Existing `syllabifyForAbc()` output verified compatible:** it produces hyphen-suffixed tokens (e.g., `beau- ti- ful`), matches abcjs expectations exactly.

### Pattern 2: Phrase splitting via `% PHRASE_BREAK` comments
**What:** Insert `% PHRASE_BREAK` lines into the ABC body at phrase boundaries. ABC comments start with `%` and are ignored by abcjs parser.
**When to use:** Once per tune at annotation time (D-01).
**Example:**
```abc
X:1
T:Old Hundredth
M:L.M.
L:1/4
K:G
| G2 G G | G F E D | E G F E | D2 D2 |
% PHRASE_BREAK
| D2 D D | E G F E | D F E D | G2 G2 |
```
**Phrase splitting algorithm (client side):**
1. Extract header (everything up to and including `K:` line).
2. Body = everything after.
3. Split body on `/^\s*% PHRASE_BREAK\s*$/m`.
4. Each phrase = `header + bodyChunk[i]`.

**Code skeleton:**
```typescript
// src/lib/abc-phrases.ts
export function splitOnPhraseBreaks(abc: string): { header: string; phrases: string[] } {
  // Headers end after the K: line (first line starting with "K:")
  const lines = abc.split('\n')
  let kIdx = lines.findIndex(l => /^K:/.test(l.trim()))
  if (kIdx === -1) return { header: '', phrases: [abc] }
  const header = lines.slice(0, kIdx + 1).join('\n')
  const body = lines.slice(kIdx + 1).join('\n')
  const phrases = body.split(/^\s*%\s*PHRASE_BREAK\s*$/m).map(s => s.trim()).filter(Boolean)
  return { header, phrases: phrases.length ? phrases : [body] }
}

export function buildPhraseAbc(header: string, phraseBody: string): string {
  return `${header}\n${phraseBody}`
}
```

### Pattern 3: Injecting `w:` lines for current phrase only (D-13)
**What:** Take the syllabified verse text(s) for the stanzas visible in this phrase, emit `w:` line(s) after the music in the phrase ABC.
**When to use:** Every render of the staff view.
**Multiple stanzas:** abcjs supports MULTIPLE consecutive `w:` lines after a music line — each renders as a separate verse row below the staff.

**Code skeleton (extends existing `lib/lyrics.ts`):**
```typescript
// src/lib/lyrics.ts — new function
export function buildAbcWithSyllables(
  phraseAbcWithoutLyrics: string,
  stanzas: string[]   // text of stanzas to display under this phrase
): string {
  // Strip any pre-existing w: lines (defensive)
  const cleaned = phraseAbcWithoutLyrics.replace(/^w:.*$/gm, '').replace(/\n\n+/g, '\n').trim()
  const wLines = stanzas
    .map((s) => `w: ${syllabifyForAbc(s).replace(/\n/g, ' ')}`)
    .join('\n')
  return wLines ? `${cleaned}\n${wLines}` : cleaned
}
```

Existing `PsalmNotationPlayer.buildAbcWithStanzas()` already does this — just rename/relocate to `lib/lyrics.ts` and apply `syllabifyForAbc()` to each stanza.

### Pattern 4: abcjs sizing options
**What:** Control width, scale, and line wrap.
**Key options** [VERIFIED: docs.abcjs.net/visual/render-abc-options.html]:

| Option | Default | Effect | Use in 4.9.2 |
|--------|---------|--------|--------------|
| `responsive: 'resize'` | undefined | SVG fills container width; reflows on resize. | YES — already in `AbcPlayer`. Required for NOTATION-03. |
| `staffwidth` | 740 px | Spacing budget for the engraver. NOT a hard width — affects layout, not viewport. | OPTIONAL — let `responsive: resize` handle it. |
| `scale` | 1 | Multiplier on rendered size (1 = normal, 2 = double). DOES NOT change layout, only zooms. | YES — derive from `--staff-base-size` (e.g., `scale = baseSize / 14`). |
| `wrap` | `{ preferredMeasuresPerLine: 0, minSpacing: 1, maxSpacing: 2 }` | Controls automatic line breaks based on measure count. | YES — set `preferredMeasuresPerLine` to match phrase length (typically 4 for CM phrase = 8 beats over 4 measures). |
| `add_classes: true` | false | Adds CSS classes to SVG elements (needed for note highlighting). | YES — already in `AbcPlayer`. |
| `visualTranspose` | 0 | Transpose key for display only. | EXISTING — preserved from 4.9.1. |
| `defaultTempo` | from `Q:` | `{ duration, bpm }` | EXISTING — preserved. |

### Pattern 5: Pseudo-fullscreen via CSS (D-15)
**What:** Conditionally apply `fixed inset-0 z-50 bg-background` to NotationRenderer's outer div instead of calling `requestFullscreen()`.
**Why:** iOS Safari does not support element-level Fullscreen API for non-video elements (verified). Native Fullscreen also has finicky useEffect timing (useLayoutEffect needed).
**When to use:** Always (cross-platform).

```tsx
const [isFullscreen, setIsFullscreen] = useState(false)

useEffect(() => {
  if (!isFullscreen) return
  const onKey = (e: KeyboardEvent) => { if (e.key === 'Escape') setIsFullscreen(false) }
  window.addEventListener('keydown', onKey)
  // Optional: prevent body scroll while fullscreen
  const prev = document.body.style.overflow
  document.body.style.overflow = 'hidden'
  return () => { window.removeEventListener('keydown', onKey); document.body.style.overflow = prev }
}, [isFullscreen])

return (
  <div className={cn(
    'space-y-3',
    isFullscreen && 'fixed inset-0 z-50 bg-background overflow-auto p-4 pb-20'
  )} style={{ '--staff-base-size': `${baseSize}px` } as CSSProperties}>
    {/* … */}
    {isFullscreen && (
      <div className="fixed inset-x-0 bottom-0 h-12 bg-background border-t flex items-center justify-between px-4 z-50">
        <Button onClick={prevPhrase} disabled={phraseIndex === 0}>← Prev</Button>
        <Button onClick={() => setIsFullscreen(false)}><X /></Button>
        <Button onClick={nextPhrase} disabled={phraseIndex === phrases.length - 1}>Next →</Button>
      </div>
    )}
  </div>
)
```

### Pattern 6: CSS custom property for font size (D-05)
**What:** Set `--staff-base-size` on the NotationRenderer's root element; read it from JS only when computing abcjs `scale`; CSS rules use `var(--staff-base-size)` directly for lyric/verse text.
**Why:** Avoid React re-renders on every A+/A− click for non-abcjs parts. abcjs itself DOES need a re-render to apply new `scale`, but the surrounding text scales purely via CSS.

```tsx
const [baseSize, setBaseSize] = useState<number>(() => {
  try { return Number(localStorage.getItem('psalter-staff-size')) || 14 } catch { return 14 }
})
useEffect(() => { localStorage.setItem('psalter-staff-size', String(baseSize)) }, [baseSize])

// Apply to root
<div style={{ ['--staff-base-size' as any]: `${baseSize}px` }}>
```

In `globals.css`:
```css
:root { --staff-base-size: 14px; }
.verse-text { font-size: var(--staff-base-size); }
.verse-number { font-size: calc(var(--staff-base-size) * 0.5); vertical-align: super; }
```

Pass `scale={baseSize / 14}` to abcjs `renderAbc` options.

### Anti-Patterns to Avoid
- **Calling `element.requestFullscreen()` on iOS Safari** — silently fails for non-video elements. Always use the CSS overlay pattern.
- **Storing `% PHRASE_BREAK` markers in a separate DB column** — explicitly rejected by D-02. Keep them inline in `abc_notation` text.
- **Computing phrases on the server and passing as props** — D-10 + static rendering requires client-side phrase split. Server passes raw ABC; client splits on render.
- **Calling `screen.orientation.lock('landscape')`** — not supported on iOS Safari; will throw. If implemented at all, wrap in try/catch and treat success as best-effort. UI-SPEC says "landscape preferred" not "forced".
- **Re-rendering abcjs on every A+/A− click via React state cascade** — yes, abcjs render is needed for `scale` change, but ensure the re-render is debounced or only fires when `scale` actually changes (cf. existing `AbcPlayer.tsx` useEffect deps).
- **Swapping `nlp-syllables` for a new library "for accuracy"** — out of scope. The library produces the dash-suffixed format abcjs expects; switching would cascade.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Syllabify English words | Hand-rolled vowel-counting heuristic | Existing `syllabifyForAbc()` in `lib/lyrics.ts` (uses `nlp-syllables`) | Already works; covered by tests in Phase 4. |
| Align syllables to notes | Manual character math, custom SVG positioning | abcjs `w:` field syntax (hyphen-suffix tokens) | abcjs handles alignment, spacing, melisma, multi-line. Months of edge cases. |
| Fullscreen overlay | Native Fullscreen API + vendor prefixes + iOS workaround | CSS `position: fixed inset-0 z-50` + Escape key handler | Cross-platform with zero browser caveats. |

## Common Pitfalls

### Pitfall 1: Blank lines in ABC string are interpreted as "new tune"
**What goes wrong:** abcjs treats a blank line as a tune separator; only the first chunk renders.
**Why it happens:** When stripping/replacing `w:` lines or splitting on phrase breaks, you can accidentally leave a `\n\n`.
**How to avoid:** Always collapse `\n\n+` → `\n` after string manipulation. The existing `buildAbcWithStanzas()` already does `.replace(/\n\n+/g, '\n')` — preserve this in the new function.
**Warning signs:** Score renders only first phrase / first half; subsequent stanzas missing.

### Pitfall 2: abcjs CJS interop in Next.js
**What goes wrong:** `import abcjs from 'abcjs'` may yield `undefined` due to CJS/ESM mismatch; `abcjs.renderAbc` throws.
**Why it happens:** abcjs ships CommonJS; the bundler's interop is inconsistent across Next.js versions.
**How to avoid:** Use the existing pattern from `AbcPlayer.tsx` lines 4-7:
```ts
import * as abcjsModule from 'abcjs'
const abcjs = (abcjsModule as any).default ?? abcjsModule
```
**Warning signs:** `TypeError: Cannot read properties of undefined (reading 'renderAbc')`.

### Pitfall 3: iOS Safari Fullscreen API silently fails for non-video elements
**What goes wrong:** `element.requestFullscreen()` returns a rejected Promise or no-ops on iPhone Safari. Users on iOS see nothing happen when they click "Full Screen".
**Why it happens:** As of iOS 17, only `<video>` elements may go fullscreen. Element-level FS API is unsupported.
**How to avoid:** Do NOT use the Fullscreen API. Use the CSS `position: fixed inset-0` pattern (D-15, Pattern 5 above).
**Warning signs:** Works on desktop Chrome/Firefox; nothing visible happens on iPhone.
[CITED: MDN — Element.requestFullscreen, Apple Developer Forums thread on iOS fullscreen]

### Pitfall 4: `screen.orientation.lock('landscape')` throws on iOS
**What goes wrong:** Unhandled Promise rejection: "screen.orientation.lock is not a function" or "NotSupportedError".
**Why it happens:** iOS Safari lacks the Screen Orientation API method.
**How to avoid:** If used at all, wrap in `try/catch` and `'orientation' in screen && typeof screen.orientation.lock === 'function'`. UI-SPEC's "landscape preferred" can be achieved with `@media (orientation: landscape)` CSS hints, not enforcement.
**Warning signs:** Errors only on iPhone; works on Android Chrome.

### Pitfall 5: `staffwidth` does not constrain SVG width when `responsive: 'resize'` is set
**What goes wrong:** Developer sets `staffwidth: 300` expecting a 300px-wide score on mobile; gets full-width anyway.
**Why it happens:** `responsive: 'resize'` overrides — SVG fills container.
**How to avoid:** Use `responsive: 'resize'` AND control width via the wrapper `<div>`'s CSS. Use `wrap.preferredMeasuresPerLine` to manage measures-per-line, not `staffwidth`.
**Warning signs:** Layout ignores `staffwidth` value.

### Pitfall 6: Note highlight CSS leaks across remounts
**What goes wrong:** `<style>` injected via `dangerouslySetInnerHTML` accumulates; old highlight classes interfere.
**Why it happens:** Multiple `AbcPlayer` instances on the same page (e.g. fullscreen overlay + background) each inject the same style block.
**How to avoid:** Move the `noteHighlightStyle` rule to `globals.css` permanently, not per-instance. This is a Phase 4.9.1 holdover worth cleaning up here.
**Warning signs:** Duplicate `<style>` tags in DOM.

### Pitfall 7: `nlp-syllables` is unmaintained and may mis-syllabify rare words
**What goes wrong:** Words like "praise", "righteousness", "Selah" may produce odd syllable splits; old archaic English ("ye", "thee") may be single-syllable but flagged as multi.
**Why it happens:** Library last published 2022; uses heuristic rules.
**How to avoid:** Accept the imperfection — Scottish Psalter language is repetitive (psalms recycle ~500 words). Add a small override map in `lib/lyrics.ts` for known problem words if QA surfaces them. Do NOT switch libraries.
**Warning signs:** Specific words display oddly under notes in QA; addressable case-by-case.

### Pitfall 8: A+/A− triggers full abcjs re-render which feels slow
**What goes wrong:** Each click re-runs `abcjs.renderAbc`, taking 50-200ms on slow phones; UI feels laggy.
**Why it happens:** abcjs `scale` option requires re-render (no live CSS scaling).
**How to avoid:** (a) Show button :active state immediately (CSS), (b) wrap the abcjs render in a `useLayoutEffect` with debounced state if needed, (c) consider applying `transform: scale()` to the SVG container for INSTANT visual feedback while debouncing the actual `renderAbc` call — but this is optimisation, only do if profiling shows it's needed.
**Warning signs:** A+/A− clicks feel sluggish on mobile.

## Code Examples

### Splitting an ABC string into phrases
```typescript
// src/lib/abc-phrases.ts
export interface SplitAbc { header: string; phrases: string[] }

export function splitOnPhraseBreaks(abc: string): SplitAbc {
  const lines = abc.split('\n')
  const kIdx = lines.findIndex(l => /^K:/.test(l.trim()))
  if (kIdx === -1) return { header: '', phrases: [abc] }
  const header = lines.slice(0, kIdx + 1).join('\n')
  const body = lines.slice(kIdx + 1).join('\n')
  const phrases = body
    .split(/^\s*%\s*PHRASE_BREAK\s*$/m)
    .map(s => s.trim())
    .filter(Boolean)
  return { header, phrases: phrases.length ? phrases : [body] }
}

export function buildPhraseAbc(split: SplitAbc, phraseIndex: number): string {
  const body = split.phrases[phraseIndex] ?? split.phrases[0] ?? ''
  return `${split.header}\n${body}`
}
```

### Injecting syllabified w: lines for current phrase
```typescript
// src/lib/lyrics.ts (additions)
import { syllabifyForAbc } from './lyrics'  // existing

/**
 * Inject syllabified verse text(s) as w: lines into an ABC phrase.
 * - Strips any pre-existing w: lines (defensive)
 * - Collapses double-newlines (abcjs treats blank lines as new tune)
 * - Each stanza becomes one w: line; multiple w: lines render as stacked verses
 */
export function buildAbcWithSyllables(phraseAbc: string, stanzas: string[]): string {
  const cleaned = phraseAbc
    .replace(/^w:.*$/gm, '')
    .replace(/\n\n+/g, '\n')
    .trim()
  if (stanzas.length === 0) return cleaned
  const wLines = stanzas
    .map(s => `w: ${syllabifyForAbc(s).replace(/\n/g, ' ')}`)
    .join('\n')
  return `${cleaned}\n${wLines}`
}
```

### Phrase-meter lookup table (D-03)
```typescript
// src/lib/abc-phrase-meter-map.ts
// Number of phrases per stanza based on Scottish Psalter metre conventions.
// One phrase = one displayed line of staff + corresponding lyric line break.
export const PHRASES_PER_STANZA: Record<string, number> = {
  'CM': 2,           // 8.6.8.6 → two halves (8+6 syllables each)
  'LM': 2,           // 8.8.8.8 → two halves
  'SM': 2,           // 6.6.8.6 → two halves
  'DCM': 4,          // 8.6.8.6.8.6.8.6 → four halves
  'DLM': 4,          // 8.8.8.8.8.8.8.8
  'DSM': 4,
  '8.7.8.7': 2,
  '7.6.7.6': 2,
}

export function phrasesForMeter(meter: string | null): number {
  if (!meter) return 1
  // Normalise: "CM (common meter, 8.6.8.6)" → "CM"
  const normalised = meter.trim().split(/\s+/)[0].toUpperCase()
  return PHRASES_PER_STANZA[normalised] ?? 1
}
```

## Open Questions

1. **Phrase ↔ stanza mapping (A2 above) — BLOCKING for plan.**
   - What we know: UI-SPEC says "1 staff line + 3 stanzas below" per phrase view; D-13 says w: lines for "current phrase only."
   - What's unclear: For a 6-stanza psalm with 2 phrases, does phrase 1 show stanzas 1-3 and phrase 2 show 4-6 (paging through stanzas)? Or does each phrase show stanzas 1-3 always, and the user navigates between phrases of the SAME stanzas (each phrase = different half of the melody, same lyrics)?
   - Recommendation: **planner asks user during plan-check or runs a focused discussion.** The most likely answer based on the hymnal convention is: each phrase displays the same stanzas (1-3 by default) but with the melody-half corresponding to that phrase; phrase navigation = melody section; stanza scrolling/paging = separate concept.

2. **Verse numbering positioning (UI-SPEC line 240 says "TBD via implementation").**
   - What we know: Verse numbers at 50% font size; integrated inline with first word.
   - What's unclear: Superscript or subscript? Inline as a separate span?
   - Recommendation: Plan to use `<sup>` with `font-size: calc(var(--staff-base-size) * 0.5)`. Confirm visually in QA. Low-risk to pick a default.

3. **Should the annotation script also support an `--overwrite` flag (re-annotate rows that already have phrase breaks)?**
   - Useful if the meter map evolves. Low complexity. Default off.

4. **Cleanup of `PsalmNotationPlayer` and `AbcPlayerSection`.**
   - What we know: NotationRenderer replaces PsalmNotationPlayer (D-08).
   - What's unclear: Does `/tunes/[id]` also switch to NotationRenderer, or only `/psalms/[id]`? The UI-SPEC implies both. Planner should make this explicit.
   - Recommendation: Update BOTH pages; deprecate `PsalmNotationPlayer.tsx` (delete after migration verified).
