## How D-19, D-20, D-21 were resolved

### D-19 — one staff row per phrase

The legacy "one giant staff" branch is gone. The view-area for `viewMode === 'staff'` is a list comprehension over `visiblePhraseIndices`, each producing its own `<AbcPlayer>`:

```tsx
{visiblePhraseIndices.map((i) => {
  const wLines = wLinesForPhrase(i)
  const phraseAbc = buildPhraseAbc(split, i)
  const abcWithLyrics = buildAbcWithSyllables(phraseAbc, wLines)
  return (
    <div key={i} className="phrase-row">
      <AbcPlayer abc={abcWithLyrics} scale={scale} tuneName={tuneName} />
    </div>
  )
})}
```

A CM tune (T=2) renders as 2 rows; a double-CM tune (T=4) renders as 4 rows. Stanza-cycle data is stacked under each row as multiple `w:` lines via `buildAbcWithSyllables`.

### D-20 — stanza-cycle model

Stanza grouping is done at the cycle level, not the stanza level:

```tsx
const cycles = useMemo(
  () => groupStanzasIntoCycles(stanzas, tuneMeter, stanzaMeter),
  [stanzas, tuneMeter, stanzaMeter],
)
```

`groupStanzasIntoCycles` returns `string[][]` — each inner array is the stanzas that fit under one full pass of the tune. For double-CM × CM the cycle size is 2 (paired stanzas); for CM × CM it's 1.

Inside the staff render, `mapCycleToPhraseSyllableLines(cycleSlice, tuneMeter, stanzaMeter)` is called once per visible cycle and returns the T-length per-phrase syllable grid for that cycle. The renderer concatenates each phrase's contribution across all visible cycles, producing stacked `w:` lines under that phrase row.

### D-21 — two independent pagination axes

**Axis A — Stanza pagination** (always available):

```ts
const totalStanzaPages = Math.max(1, Math.ceil(cycles.length / CYCLES_PER_PAGE))
const visibleCycles = cycles.slice(cyclePage * 3, (cyclePage + 1) * 3)
```

Staff rows do not change when paginating stanzas; only the stacked `w:` lines under each row update.

**Axis B — Tune-half pagination** (landscape-narrow only):

```ts
const isLandscapeNarrow = useMediaQuery('(orientation: landscape) and (max-width: 900px)')
const paginateTuneHalf = isLandscapeNarrow && T > 2
```

When active, `visiblePhraseIndices` is either `[0..T/2)` or `[T/2..T)` depending on `halfPage`. The `wLinesForPhrase` helper slices each visible cycle to the matching stanza-half before mapping:

```ts
const cycleSlice = paginateTuneHalf
  ? halfPage === 'A'
    ? cycle.slice(0, Math.ceil(cycle.length / 2))
    : cycle.slice(Math.ceil(cycle.length / 2))
  : cycle
const grid = mapCycleToPhraseSyllableLines(cycleSlice, tuneMeter, stanzaMeter)
return grid[i] ?? ['']
```

### D-21 — combined cycle order (tune-half flips first)

```ts
function next() {
  if (paginateTuneHalf && halfPage === 'A') {
    setHalfPage('B')
  } else {
    if (paginateTuneHalf) setHalfPage('A')
    setCyclePage((p) => Math.min(p + 1, totalStanzaPages - 1))
  }
}
function prev() {
  if (paginateTuneHalf && halfPage === 'B') {
    setHalfPage('A')
  } else {
    if (paginateTuneHalf) setHalfPage('B')
    setCyclePage((p) => Math.max(p - 1, 0))
  }
}
```

For a 12-stanza CM × double-CM tune on mobile landscape this yields the four-page sequence from CONTEXT.md D-21: half-A {1,3,5} → half-B {2,4,6} → half-A {7,9,11} → half-B {8,10,12}.

`atStart` / `atEnd` correctly disable the buttons only at the absolute extremes:

```ts
const atStart = cyclePage === 0 && (!paginateTuneHalf || halfPage === 'A')
const atEnd   = cyclePage === totalStanzaPages - 1 && (!paginateTuneHalf || halfPage === 'B')
```

The pagination indicator adapts to the active axes — `Page X/Y` when both, `Half A/B` when only B, `Stanzas n/N` when only A.

## Other implementation notes

- **A+/A− buttons remain visible in all three view modes** (Staff, Solfège, Lyrics-only). The size group is rendered in the control bar unconditionally; Lyrics-only mode honours the `--staff-base-size` CSS variable via the existing `.verse-text` / `.verse-number` rules from Plan 03.
- **localStorage persistence** uses lazy useState initialisers guarded with `typeof window` and try/catch. Stored values are validated (`isBaseSize`, `isViewMode`) before being accepted.
- **`cyclePage` clamp effect** — when cycle count shrinks (e.g. on prop changes), `cyclePage` is clamped to `totalStanzaPages - 1` to avoid out-of-range page indices.
- **`halfPage` reset effect** — when `paginateTuneHalf` flips from true → false, `halfPage` resets to `'A'` so re-entering landscape starts fresh.
- **Fullscreen** uses Plan 03's `FullscreenOverlay`. Bottom-bar contents: Prev / Exit / Next when any pagination axis is active; the empty `<span aria-hidden />` placeholders keep the flex layout consistent when pagination is disabled.
- **`data-notation-renderer` attribute and `--staff-base-size` CSS var are set on BOTH render branches** (non-fullscreen and fullscreen), so downstream CSS targeting `[data-notation-renderer]` works in either context.

## Deviations from the RESEARCH skeleton

The RESEARCH skeleton (lines 548-667) predates D-19 / D-20 / D-21 and modelled the older "render one phrase at a time, paginate when phrases > 2" design. This plan deliberately diverges in three places:

1. **No `phraseIdx` state.** Replaced with `cyclePage` (axis A) + `halfPage` (axis B). The "current phrase" concept is gone — D-19 says ALL phrases of a tune are rendered as separate rows in every render (subject to axis B's half-slice).
2. **No `paginate = split.phrases.length > 2` boolean.** That single-axis trigger is replaced with `paginateTuneHalf = isLandscapeNarrow && T > 2` (axis B) AND independently `totalStanzaPages > 1` (axis A).
3. **`wLinesForPhrase(i)` accumulates across cycles.** The skeleton's `phraseStanzas = stanzas.slice(phraseIdx, phraseIdx + 1)` is replaced with a `flatMap` over `visibleCycles` that calls `mapCycleToPhraseSyllableLines` for each cycle and concatenates the per-phrase contributions — this is how stacked `w:` lines per phrase row are produced.

The skeleton's localStorage / fullscreen / A+/A− patterns survived essentially unchanged.
