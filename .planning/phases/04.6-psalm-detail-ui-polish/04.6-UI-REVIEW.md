## Top 3 Priority Fixes

1. **BLOCKER — Lyrics duplicated on every psalm page** — Users see all stanzas as plain text, then the notation player immediately below also shows them (in Staff mode as `w:` lines, in "Lyrics only" mode as plain text again). The "Lyrics only" toggle is therefore redundant and confusing. Fix: remove the static stanzas block from `page.tsx` (lines 68–84); the notation player is the canonical lyrics surface. If you keep the static block, hide the PsalmNotationPlayer when `displayMode === 'lyrics-only'` and ensure the static section is not a duplicate.

2. **BLOCKER — Mobile header overflows to two lines** — At 375px the nav ("CPRC Psalter | Psalms | Tunes | Search | Explore | Daily Plan") breaks "Daily Plan" onto a second row, creating a ~56px header. This consumes valuable vertical space and looks broken. Fix: add a hamburger/sheet menu for mobile using shadcn's Sheet component; keep only the logo on mobile, collapse nav behind a menu button.

3. **WARNING — Stanza numbers are run-on ("1All people", "2Him serve")** — The DB lyrics field stores inline stanza numbers without a separator. Every stanza heading reads as a concatenated word. Fix: in `page.tsx` and `PsalmNotationPlayer.tsx`, add a space after leading stanza number with a regex: `stanza.replace(/^(\d+)([A-Z])/, '$1 $2')`. This is a display-layer transform — no DB changes needed.

## Detailed Findings

### Pillar 1: Copywriting (2/4)

**BLOCKER — Inline verse numbers in lyrics body**
The Scottish Psalter source data embeds stanza numbers directly into the first word of each stanza (`1All people`, `2Him serve`, `3Know that`). The page renders this verbatim at `page.tsx:79` and `PsalmNotationPlayer.tsx:162`. The resulting text looks like corrupted output to any reader unfamiliar with the data source.
- File: `src/app/psalms/[id]/page.tsx:79`
- File: `src/components/PsalmNotationPlayer.tsx:162`
- Fix: `stanza.replace(/^(\d+)([A-Za-z])/, '$1 $2')` at both sites — no DB migration needed.

**WARNING — Section headings are all-caps small labels**
"METRICAL LYRICS", "DIVISIONS", "CATEGORIES" use `text-sm font-semibold uppercase tracking-wide text-muted-foreground`. This is a neutral pattern and legible, but "METRICAL LYRICS" appears three times on the same page (tab content, below tabs, and Study tab when scrolled down). The repetition signals structural duplication rather than intentional design.

**WARNING — "No historical tunes recorded." is hardcoded**
`PsalmTabs.tsx:342`. This is the correct placeholder per plan spec, but the string implies data should exist and doesn't. More honest empty-state: "Historical tune variants are not yet catalogued." This is minor but worth fixing in Polish phase.

**PASS — Error and empty states are specific**
"No tune assigned to this psalm.", "No reading plan entry for this psalm.", "No backup tunes recorded for this psalm." — all domain-specific, not generic. "Score not yet available." is clear. "No messianic data recorded for this psalm." is factual. No generic "No data" or "An error occurred" patterns found.

**PASS — CTAs are purposeful**
"Staff", "Solfège", "Show notation", "Lyrics only", "← Prev", "Next →" — all concrete and domain-specific.

### Pillar 2: Visuals (2/4)

**BLOCKER — Mobile nav header overflows to two rows**
At 375px, the SiteHeader renders "Daily Plan" on a second line because there is no mobile nav collapse. The header visually appears as two stacked rows. The brand name also wraps to "CPRC / Psalter" on the narrowest viewports. Confirmed in mobile screenshot.
- File: `src/components/SiteHeader.tsx`
- No `lg:hidden`, `sm:hidden`, or hamburger pattern exists in `SiteHeader.tsx`.

**BLOCKER — Lyrics content duplicated vertically**
The "Metrical Lyrics" section (all stanzas, plain text) renders ABOVE the notation player. The notation player in Staff mode also shows those same stanzas embedded as `w:` lyric lines beneath the score. In "Lyrics only" mode the player shows them as a third copy of the same text. This violates the principle of a single focal point and creates a confusing hierarchy: which lyrics surface is the authoritative one?
- Files: `src/app/psalms/[id]/page.tsx:68–84` (static stanzas) and `src/components/PsalmNotationPlayer.tsx` (dynamic stanzas)

**WARNING — Tab bar wraps into content area at 375px**
With 8 tabs (`flex-wrap`) the tab bar wraps onto 2.5 rows at 375px. The last tab "Historical Tunes" renders at the bottom of the wrapping cluster but visually bleeds into the tab content region with no clear separator. The `mb-6` margin on `TabsList` is insufficient when the list wraps.
- File: `src/components/PsalmTabs.tsx:43`

**WARNING — Two-column layout intent not observable**
The design specifies a lyrics/notation left column and SoundCloud right column. All production psalms that have `soundcloudUrl` populated contain placeholder text ("need to upload", "poor recording", "sole start") rather than real URLs. The right column is always absent on the live site. The two-column layout cannot be visually verified.
- Note: this is a data gap, not a code bug. The code correctly guards `primaryTune?.soundcloudUrl`.

**PASS — Notation score renders cleanly**
The abcjs SVG for Old 100th renders with 4 stave lines, correct note values, and readable `w:` lyric text below. Score is well-proportioned in the left column.

**PASS — Visual hierarchy in header is clear**
H1 (`text-2xl md:text-4xl font-bold`) dominates. Psalm number label above in `text-sm text-muted-foreground` correctly subordinates.

### Pillar 3: Color (3/4)

**WARNING — External links (`text-primary`) are near-invisible on light theme**
`--primary` in light mode is `oklch(0.205 0 0)` — effectively near-black. The Study tab's three external links use `className="text-primary underline underline-offset-2"` (`PsalmTabs.tsx:208,218,228`). The underline provides differentiation, but the text color offers zero contrast signal beyond the underline itself against `text-foreground` (`oklch(0.145 0 0)`). The primary color is visually indistinguishable from body text. Standard convention for links is a blue or brand hue to signal interactivity.
- Fix: use `text-blue-600 dark:text-blue-400` or define a `--link` CSS variable. Alternatively accept this as a deliberate low-key design choice.

**PASS — No hardcoded hex/rgb values in psalm detail components**
Zero instances of `#xxx` or `rgb(` in any audited file. All color is via design tokens.

**PASS — `text-primary` used only for links (3 instances)**
Primary color is not over-applied. Background color on active toggles uses `variant="default"` (dark fill, white text) which is appropriate for a pressed/active state.

**PASS — Accent color usage is disciplined**
`text-muted-foreground` used correctly for subordinate metadata. Badge components use `variant="secondary"` for category chips — correct 30% role.

### Pillar 4: Typography (3/4)

**Font sizes in use (psalm detail scope):**
- `text-xs` — verse numbers in KJV text, stanza number prefix in lyrics-only mode, `v.1` verse markers
- `text-sm` — section labels, metadata rows, tab content body text, control button labels
- `text-2xl` (mobile h1) / `text-4xl` (desktop h1) — psalm title
- `text-base` is absent — body prose defaults to `text-sm`

4 distinct sizes — within the 4-size limit.

**Font weights in use:**
- `font-medium` — nav links, metadata row keys
- `font-semibold` — section headings (DIVISIONS, CATEGORIES, etc.)
- `font-bold` — H1 psalm title

3 distinct weights. The informal best-practice is 2 for body content. The third (`font-semibold`) is used exclusively for section labels and is defensible. Minor flag.

**WARNING — No `text-base` prose size**
All body content in tabs uses `text-sm`. For extended reading (Haddington Introduction, KJV text, metrical lyrics), `text-sm` (14px) is below comfortable reading size for older congregation members. The Study tab renders full paragraphs and multi-verse scripture at 14px. Consider `text-base` (16px) for prose-heavy tab content.
- File: `src/components/PsalmTabs.tsx:176,286,304`

**PASS — Title sizing is correct**
`text-2xl md:text-4xl` creates a good responsive title scale. `Geist Sans` (loaded via `next/font`) renders cleanly.

### Pillar 5: Spacing (3/4)

**Spacing classes from audit (top frequency):**
All spacing uses Tailwind scale values (2, 3, 4, 6, 8). No arbitrary `[Npx]` or `[Nrem]` values found in any audited file.

**WARNING — Dead space between static lyrics and notation player**
`page.tsx:73` applies `space-y-4 mb-6` to the static stanzas block. The notation player immediately follows. This creates ~24px of gap between the last stanza of the plain-text block and the control buttons of the notation player. When both are visible, the spatial relationship is unclear — are these two separate sections or one unified block? Fix: either remove the static stanzas block (preferred) or wrap both in a visually connected container.

**WARNING — Tab content sections inconsistent vertical rhythm**
Study tab uses `space-y-6` between sections; other tabs use `space-y-4` or `space-y-2` with no pattern. The inconsistency is minor but perceptible when switching tabs.

**PASS — Page container spacing is correct**
`max-w-4xl mx-auto px-4 sm:px-6 lg:px-8 py-6 md:py-8` matches the global pattern used across other pages.

**PASS — Below-tabs grid gap is appropriate**
`gap-6` between notation column and SoundCloud column is correct.

### Pillar 6: Experience Design (2/4)

**BLOCKER — No `error.tsx` on `/psalms/[id]` route**
`find src/app/psalms -name "error.tsx"` returns nothing. If `fetchPsalmDetail` throws (DB unavailable, network error), Next.js will render a blank white screen or uncaught error page. The `loading.tsx` skeleton is present but the error recovery surface is missing.
- Fix: create `src/app/psalms/[id]/error.tsx` with a `'use client'` component offering a "Try again" reset button and a contextual message ("Could not load this psalm.").

**BLOCKER — "Lyrics only" mode is redundant given static stanzas above notation**
The UX design intent (D-10) was to let users hide the score and read just the lyrics. However, ALL stanzas already appear in plain text above the notation player on every page load. Clicking "Lyrics only" on the player removes the score but shows the same stanzas again in a different format — a third render of identical content. This makes the toggle feel broken.
- Root cause: the static stanzas block in `page.tsx` was not removed after the notation player was wired in.
- Fix: remove the static stanzas section from `page.tsx:68–84`. The notation player's "Lyrics only" mode then becomes the only stanza surface, making the toggle meaningful.

**WARNING — No error state for abcjs rendering failure**
If `AbcRenderer` fails (malformed ABC string, abcjs exception), there is no catch boundary. The component would either silently render nothing or throw into the Suspense boundary showing the Skeleton indefinitely.
- File: `src/components/AbcRenderer.tsx` (review needed)

**WARNING — Notation player has no "no tune" message when `primaryTune` is null**
When `primaryTune` is null, `PsalmNotationPlayerClient` is simply not rendered (guarded at `page.tsx:87`). The left column shows only stanzas with no indication that notation is unavailable. A contextual "No notation available for this psalm." message in the left column would improve the experience for psalms without tunes.

**PASS — Loading states are present on all routes**
`loading.tsx` exists at `/psalms`, `/psalms/[id]`, `/tunes`, `/tunes/[id]`. PsalmDetailSkeleton correctly mirrors the two-column layout. PsalmNotationPlayerClient uses `<Suspense>` with a `h-52` skeleton.

**PASS — Disabled states on navigation buttons**
"← Prev" and "Next →" have `disabled={groupIndex === 0}` and `disabled={groupIndex === stanzaGroups.length - 1}` respectively. Correct.

**PASS — `aria-pressed` on all toggle buttons**
Staff, Solfège, Show notation, Lyrics only all carry `aria-pressed={...}`. Nav buttons carry `aria-label`. Correct.

**PASS — Empty states are handled across all tabs**
All 8 tabs handle null/empty data with `italic text-muted-foreground` messages that are contextually meaningful.
