## Summary

Phase 4.6 is a pure UI polish pass on the single psalm view (`/psalms/[id]`) and the global `SiteHeader`. No new data capabilities, no schema changes, no new routes (except `error.tsx`). The work consists of 17 locked decisions spanning layout restructure, mobile navigation, accessibility controls, error surfaces, and visual consistency.

The codebase is well-structured and all affected components are identified with line-level precision in the UI review. The critical insight from reading the live source is that the page already has the notation player below tabs (contrary to D-01) — the refactor inverts this ordering so notation is first. The static stanzas block (`page.tsx:68–84`) remains and causes duplication; removal is the highest-priority change.

The `Sheet` component is NOT yet installed — `ls src/components/ui/` confirms only: badge, button, card, input, select, separator, skeleton, tabs. Adding the hamburger menu requires running `npx shadcn add sheet` first.

**Primary recommendation:** Execute as three plans in wave sequence — (1) layout restructure + static block removal, (2) player controls + error surfaces, (3) SiteHeader hamburger + visual polish. This ordering ensures the most impactful blocker (lyrics duplication) is fixed first.

### Pattern 1: Next.js error.tsx Error Boundary

**What:** A `'use client'` component that receives `error` and `reset` props from Next.js App Router. `reset()` re-triggers the route segment's fetch.

**When to use:** Any route that has a server data fetch that can fail. Required for `/psalms/[id]` (currently missing).

```tsx
// Source: Next.js App Router docs — error.tsx convention
'use client'

import { useEffect } from 'react'

export default function PsalmDetailError({
  error,
  reset,
}: {
  error: Error & { digest?: string }
  reset: () => void
}) {
  useEffect(() => {
    console.error(error)
  }, [error])

  return (
    <div className="max-w-4xl mx-auto px-4 sm:px-6 lg:px-8 py-12 text-center space-y-4">
      <p className="text-foreground font-medium">Could not load this psalm.</p>
      <button
        onClick={reset}
        className="text-sm text-muted-foreground underline underline-offset-2"
      >
        Try again
      </button>
    </div>
  )
}
```

[ASSUMED] — The exact error.tsx API (props: `error`, `reset`) matches Next.js 13+ App Router. Verified against Next.js 16.2.5 (same API). [CITED: nextjs.org/docs/app/api-reference/file-conventions/error]

### Pattern 5: AbcRenderer try/catch Error Boundary

**What:** Wrap `abcjs.renderAbc()` in try/catch. Display a fallback message if it throws. Use React error state pattern (not a class ErrorBoundary) since the error occurs in a `useEffect`.

```tsx
// AbcRenderer.tsx addition
const [renderError, setRenderError] = useState<string | null>(null)

useEffect(() => {
  const el = containerRef.current
  if (!el) return
  el.innerHTML = ''
  setRenderError(null)
  try {
    abcjs.renderAbc(el, abc, { responsive: 'resize', add_classes: true })
  } catch (e) {
    console.error('abcjs render failed:', e)
    setRenderError('Could not render notation.')
  }
}, [abc])

// In JSX:
if (renderError) {
  return <p className="text-sm text-muted-foreground italic">{renderError}</p>
}
```

## Common Pitfalls

### Pitfall 1: Sheet Component Not Installed

**What goes wrong:** Importing `from '@/components/ui/sheet'` throws a module not found error. Build fails.

**Why it happens:** `sheet.tsx` is not in `src/components/ui/` — confirmed by directory listing. shadcn does not auto-install; each component must be added explicitly.

**How to avoid:** First task in SiteHeader plan must run `npx shadcn add sheet` in `/data/home/psalter`.

**Warning signs:** TypeScript error: `Cannot find module '@/components/ui/sheet'`.

### Pitfall 2: base-ui Tabs TabsList Default Height Constraint

**What goes wrong:** `TabsList` has `group-data-horizontal/tabs:h-8` from the CVA definition — a fixed 8-unit height. A sticky bottom bar typically needs `h-14` or `h-auto`. Applying `fixed bottom-0` without overriding this height produces a squashed bar.

**Why it happens:** The existing `tabsListVariants` class applies `h-8` for horizontal orientation. The CVA class is applied before any `className` override.

**How to avoid:** In `PsalmTabs.tsx`, pass additional classes on `TabsList` for mobile: `className="md:hidden fixed bottom-0 left-0 right-0 h-14 ..."`. The `cn()` helper in shadcn merges with `twMerge` — later classes override earlier ones. But check: `tailwind-merge` ^3.5.0 is installed and `cn` uses it. Verify the height override actually wins. If CVA classes win over className, pass `h-auto` and set explicit `py-2` instead.

**Warning signs:** Tab bar renders at wrong height; triggers are clipped.

### Pitfall 3: z-index Conflict Between Sticky Tab Bar and SiteHeader Sheet

**What goes wrong:** The Sheet overlay opens behind the sticky tab bar, or the sticky tab bar appears over the Sheet backdrop.

**Why it happens:** SiteHeader is `z-50`; shadcn Sheet uses its own portal which typically renders at `z-50` or `z-[100]`. A sticky tab bar at `z-50` or higher conflicts.

**How to avoid:** Set sticky tab bar to `z-40`. shadcn Sheet portal renders above `z-50` by default (it uses Radix/base-ui portal). Verify the Sheet backdrop visually covers the tab bar when open.

**Warning signs:** Sheet opens but tab bar is visible on top of the backdrop; or tab bar disappears under Sheet.

### Pitfall 4: Static Page Revalidation After page.tsx Change

**What goes wrong:** After removing the static stanzas block from `page.tsx`, the production Docker container serves stale cached builds.

**Why it happens:** `generateStaticParams` pre-renders all 150 psalm pages. Production container runs `next start` from a build artifact.

**How to avoid:** After code changes, run `npm run build` and restart the Docker container (`docker restart psalter`). Do not test against the production URL until the rebuild is complete.

**Warning signs:** Old stanzas still visible after deploying; notation player still shows duplicate content.

### Pitfall 5: Tab Content Visibility with Fixed Tab Bar

**What goes wrong:** Fixed tab bar overlaps the bottom of tab content on mobile, hiding the last lines of text.

**Why it happens:** `position: fixed` removes the element from normal flow. Content below the fold does not account for the bar's height.

**How to avoid:** Add `pb-16` (or equivalent) to the tab content area wrapper on mobile (`md:pb-0`). This ensures the last content line is not obscured.

**Warning signs:** Last paragraph or list item in a tab is cut off at mobile viewport bottom.

### Pitfall 6: Regex Pattern for Stanza Number — Multi-digit and Case

**What goes wrong:** `stanza.replace(/^(\d+)([A-Z])/, '$1 $2')` — the original regex in the UI-REVIEW uses only uppercase `[A-Z]`. CONTEXT.md D-07 shows the correct version: `/^(\d+)([A-Za-z])/`. If only `[A-Z]` is used, stanzas starting with lowercase are not fixed.

**Why it happens:** Inconsistency between the UI-REVIEW finding (line 39: `/^(\d+)([A-Z])/`) and the CONTEXT.md decision (D-07: `/^(\d+)([A-Za-z])/`).

**How to avoid:** Use the CONTEXT.md version: `/^(\d+)([A-Za-z])/` — this is the locked decision.
