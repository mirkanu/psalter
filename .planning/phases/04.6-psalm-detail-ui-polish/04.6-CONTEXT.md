<decisions>
## Implementation Decisions

### Page Layout Restructure (Most Impactful)
- **D-01:** **Lyrics/notation moves to the TOP, tabs move BELOW.** New page flow: psalm title/header → lyrics + notation player (always visible) → [full-width divider] → tab strip + tab content. The primary worship surface is the first thing a precentor sees; reference content is below.
- **D-02:** **Desktop:** 2-column layout (notation 3fr left, SoundCloud 2fr right) stays as-is for the notation section. Below the notation section, a full-width tab strip + tab content section, clearly separated by a horizontal rule or border.
- **D-03:** **Mobile:** Tab strip becomes a **sticky bottom bar** (fixed, bottom-0). Horizontally scrollable (overflow-x-auto) with a subtle right-edge fade to signal more tabs. Tapping a tab reveals its content above the bar. Scrolling the page while in a tab view keeps the bottom bar stuck. A "← Lyrics" / "Back to Lyrics" affordance appears when the user has scrolled into tab content territory (e.g., above the sticky bar).
- **D-04:** The static stanzas block (`page.tsx:68–84`) is **removed**. The notation player (PsalmNotationPlayer) is the sole canonical lyrics surface. This also makes the "Lyrics only" toggle meaningful (no more duplication).

### Lyrics & Notation Player
- **D-05:** The "Lyrics only" toggle in PsalmNotationPlayer now works correctly once the static stanzas block is removed — it becomes the primary way to read plain-text stanzas.
- **D-06:** When `primaryTune` is null, show a contextual "No notation available for this psalm." message in the notation column (currently the column is silently empty).
- **D-07:** Stanza run-on numbers fixed at display layer: `stanza.replace(/^(\d+)([A-Za-z])/, '$1 $2')` applied in `PsalmNotationPlayer.tsx`. No DB change.

### Font Size Toggle (Accessibility)
- **D-08:** Add **A− / A+** buttons to the notation player controls row, alongside the existing Staff | Solfège and Show notation | Lyrics only toggles. Controls row: `[ Staff | Solfège ]  [ Show notation | Lyrics only ]  [ A− | A+ ]`
- **D-09:** A− / A+ adjusts the lyrics text size rendered by the notation player (not sitewide). 3 steps: sm → base → lg. Default: base. Persisted in localStorage (same key namespace as Staff/Solfège preference).
- **D-10:** Affects the lyric text size inside the notation player only — not tab content or any other page element.

### Mobile Navigation
- **D-11:** `SiteHeader.tsx` gets a **hamburger menu** for mobile. On small screens: logo stays, nav links collapse behind a `≡` button. Uses shadcn `Sheet` component (slide-in from right). On `md:` and above: existing horizontal nav links as-is.
- **D-12:** This is a global change — affects all pages (SiteHeader is shared). All other pages benefit from the fix.

### Visual Readability
- **D-13:** External links in the Study tab (currently `text-primary`, near-black on light theme): change to `text-blue-600 dark:text-blue-400`. Applies to `PsalmTabs.tsx:208,218,228`.
- **D-14:** No sitewide prose text size increase — the A− / A+ toggle (D-08) addresses the readability concern for lyrics. Tab content body text stays at `text-sm` for now.

### Error & Error Boundary
- **D-15:** Add `src/app/psalms/[id]/error.tsx` — `'use client'` component with a "Try again" reset button and message "Could not load this psalm."
- **D-16:** Add error catch boundary in `AbcRenderer.tsx` so abcjs render failures show a fallback ("Could not render notation.") instead of silently blank or stuck skeleton.

### Other Blockers from UI Review
- **D-17:** Tab content vertical rhythm consistency: standardise to `space-y-6` between major sections across all tabs (currently Study uses `space-y-6`, others use `space-y-4` or `space-y-2` inconsistently).

### Claude's Discretion

- Exact positioning/styling of "← Back to Lyrics" affordance on mobile (text link above bottom bar, or a chip)
- Whether the sticky bottom bar sits behind a `z-50` or higher to avoid conflicts with shadcn Sheet
- Exact right-edge fade treatment for horizontal-scroll tab bar (CSS mask-image or a gradient overlay div)
- localStorage key names for A− / A+ preference

<specifics>
## Specific Ideas

- **Bottom sticky tab bar:** The pattern is like iOS Safari's tab bar — scrollable horizontally, tabs clip at edge, fade on right signals more. On mobile the tab content appears in the page flow above the fixed bar; the bar stays fixed regardless of tab content length.
- **"Back to Lyrics" affordance:** When user has opened a tab and scrolled, they need a way back to the notation without scrolling all the way to the top. A sticky affordance just above the bottom tab bar, or a "scroll to top" chip.
- **Congregational accessibility rationale for A− / A+:** Older congregation members may need larger text to follow the lyrics during worship. The toggle lets each user set their preferred size without changing the site for everyone.
- **Layout rationale:** A precentor opens the psalm page during worship. They need the notation and lyrics immediately — not after scrolling past 8 tabs of metadata. Tabs (Overview, Study, Messianic, etc.) are reference content for preparation, not live worship use.

</specifics>
