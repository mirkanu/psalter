## Extended fetchPsalmDetail Return Shape

**Added relations:**

| Relation | Columns | Notes |
|----------|---------|-------|
| `dailyReadings` | `id, dayNumber, readingDate, notes` | `limit: 1` — at most one reading plan entry per psalm |
| `psalmTopics` | junction → `topic: { id, name, topicType }` | Overview category badges |

**Pre-existing (verified `tune: true`):**

The `psalmVersionTunes` relation already used `with: { tune: true }`, which fetches all tune columns including `abcNotation`, `solfegeJpgUrl`, `soundcloudUrl`, and `precentingComment`. No change was needed for the tune relation.

**New derived types:**

```typescript
export type PsalmDailyEntry = NonNullable<PsalmDetail['dailyReadings']>[number]
export type PsalmTuneLink = NonNullable<
  PsalmDetail['psalmVersions'][number]['psalmVersionTunes'][number]
>
```

## PsalmDetailSkeleton Shape

Matches D-01/D-02/D-03 real page layout:

1. **Header** — psalm number label + title (h-4 + h-9)
2. **Tab bar** — 8 pill skeletons on mobile (Tune tab visible), 7 on desktop (hidden on `md:`)
3. **Tab content area** — heading + 3 lines of text
4. **Below-tabs two-column section** (`md:grid-cols-[3fr_2fr]`):
   - Left (~60%): lyrics heading + stanza lines + score area (h-52) + toggle controls
   - Right (~40%): SoundCloud block — `hidden md:block` per D-03 (SoundCloud moves to Tune tab on mobile)
