# Phase 4.5: Psalm Detail Overhaul - Context

**Gathered:** 2026-05-09
**Status:** Ready for planning

<domain>
## Phase Boundary

Restructure the psalm detail page to a 7-tab layout (8 on mobile) matching psalter.cprc.co.uk; move lyrics + notation out of tabs into an always-visible section below the tabs; integrate abcjs notation with congregational-first UX (notation togglable, stanzas grouped 4-at-a-time); add loading.tsx skeletons to /psalms, /psalms/[id], /tunes, and /tunes/[id] routes.

</domain>

<decisions>
## Implementation Decisions

### Page Layout — Lyrics & Notation Section
- **D-01:** Lyrics + notation live BELOW the tabs, always visible — not inside any tab.
- **D-02:** Desktop: lyrics/notation on the left, SoundCloud embed on the right (side-by-side, both below tabs).
- **D-03:** Mobile: lyrics/notation full-width below tabs; SoundCloud embed moves into the "Tune" tab (not visible beside lyrics on mobile).

### Tab Structure
- **D-04:** Desktop: 7 tabs — Overview | 365 Days | Study | Messianic | Parallel | Backup Tunes | Historical Tunes
- **D-05:** Mobile: 8 tabs — Tune | Overview | 365 Days | Study | Messianic | Parallel | Backup Tunes | Historical Tunes ("Tune" prepended as first tab)
- **D-06:** "Tune" tab (mobile only) contains: SoundCloud embed, tune name, meter, precenting comment.
- **D-07:** Overview tab contains: psalm metadata only — NKJV title, Divisions/Sections, Category badges, Author, Date BC, Probable Occasion, Meter, Precenting comment. No lyrics, no SoundCloud.

### Notation Player (below tabs)
- **D-08:** abcjs renders ONE score with up to 4 stanzas as `w:` lyric lines underneath (standard abcjs multi-lyric approach — no repeated staves). Prev/Next pages through stanza groups (e.g. 1–4 of 6, then 5–6 of 6). Counter shows "Stanzas 1–4 / 6".
- **D-09:** Toggle 1 — **Staff | Solfège**: switches between live abcjs SVG (Staff) and R2 solfège JPG (Solfège). Preference saved to localStorage; global default is Staff. In Solfège mode, stanza navigation is hidden (solfège JPG is a static image).
- **D-10:** Toggle 2 — **Show notation | Lyrics only**: hides the abcjs/JPG score area entirely, showing plain text stanzas instead (all stanzas, scrollable). Stanza group navigation is hidden in lyrics-only mode.
- **D-11:** Rationale for this UX: Most congregation members cannot read standard notation. The default hymnal layout (notation + lyrics together) helps them learn to associate notes with words. "Lyrics only" serves those who just want the text.
- **D-12:** Controls sit ABOVE the score. Prev/Next stanza group buttons sit BELOW the score. Notation scrolls with page (no fixed height / internal scroll).
- **D-13:** Fallback chain: if abcNotation present → abcjs SVG (Staff mode). If abcNotation absent and solfegeJpgUrl present → show solfège JPG only. If neither → "Score not yet available."

### Claude's Discretion

- Whether the toggle group is the same row or two separate rows
- How Prev/Next buttons are styled on mobile (full-width or compact)
- Exact label for "Show notation | Lyrics only" toggle

</decisions>

<specifics>
## Specific Ideas

- **Congregational rationale for abcjs-first:** The goal is to help congregation members learn to read notation by seeing notes and words together, not just to display notation as a feature.
- **Stanza grouping:** up to 4 `w:` lines per abcjs render. If 6 stanzas: first render shows stanzas 1–4, second shows 5–6.
- **Solfège JPG context:** These are photos of printed solfège sheets (R2 `solfegeJpgUrl`). They are static images — no lyric overlay possible. Hide stanza nav in solfège mode.
- **localStorage key:** store Staff/Solfège preference so it persists across psalm navigations. Staff is global default (never override with Solfège unless user explicitly chose it).
- **Mobile "Tune" tab:** On mobile this is the primary tune engagement surface (SoundCloud + tune metadata). On desktop this content is always visible to the right of the score.

</specifics>
