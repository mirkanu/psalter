localStorage pattern to add (avoid SSR crash — component is client-only but useEffect is safest):

```typescript
// Add this useEffect AFTER the useState declarations:
useEffect(() => {
  // Restore preference on mount
  const stored = localStorage.getItem('psalter-score-mode')
  if (stored === 'solfege') {
    setScoreMode('solfege')
  }
}, []) // runs once on mount

// Add a second useEffect to persist on change:
useEffect(() => {
  localStorage.setItem('psalter-score-mode', scoreMode)
}, [scoreMode]) // runs whenever scoreMode changes
```

The two-effect pattern is correct here:
- Effect 1 restores saved preference once on mount (empty deps)
- Effect 2 persists to localStorage on every scoreMode change
- This avoids any race condition and keeps the logic explicit

Note: PsalmNotationPlayer is only ever loaded via dynamic(ssr:false), so `localStorage` is
always available when this component runs. The useEffect guard is still best practice.
