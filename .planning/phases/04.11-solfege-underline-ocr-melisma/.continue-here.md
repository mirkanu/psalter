## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Edit-op uses bare `tune.abcNotation` instead of `effectiveAbc` | The grid renders tokens parsed from `effectiveAbc` (with auto-injected PHRASE_BREAKs). If edit handlers use the bare ABC as their base, phraseIdx assignments mismatch the rendered grid → inserts land at end of piece. | blocking | All edit ops in `MelismaEditorClient.tsx` MUST read from `effectiveAbc` (or the editedAbc that derives from it). See commit `d11afeb`. |
| Bulk-script equal-length fast-path skips syllable validation | A regroup helper that returns lines verbatim when `lines.length === expected.length` without checking per-line syllable counts will accept malformed input as valid. Discovered in Darwall populate-structured-lyrics script. | blocking | Equal-length passthroughs MUST verify each line's syllable count is within tolerance of expected[i]. See `scripts/bulk-populate-structured-lyrics.ts` regroupBlock. |
| Direct curl POST to /api/dev/melisma-save without restoring tune row | curl tests with dummy ABC clobber the real tune's abc_notation. Lancaster was inadvertently destroyed once this way. | advisory | Always use a throwaway tune id for direct API tests, OR restore from backup immediately. Backups in `backups/`. |
| Haiku 4.5 silently misses second music system on multi-system OCR pages | Effingham JPG has top + bottom systems; Haiku returned only the top. Prompt update alone wasn't enough — model perception limit. | advisory | For OCR re-runs, use `--model=claude-sonnet-4-6` when meter expects more notes than Haiku returned. Future: auto-retry heuristic. |
