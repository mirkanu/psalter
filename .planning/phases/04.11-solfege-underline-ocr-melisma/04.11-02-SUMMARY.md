# Phase 04.11 Plan 02: buildEmbeddedWline Transform Summary

Pure, deterministic, unit-tested transform that converts (Vision OCR tokens + per-token underlined flags + stanza-1 syllables + existing ABC body with PHRASE_BREAK markers) into a new ABC body with embedded `w:` lines containing `_` continuation tokens at every underlined note position. Implements `lyric-to-note-alignment.md` §6 algorithm and locks D-01 (single source of truth — `w:` line carries melisma semantics; PHRASE_BREAK is purely visual).

## Test Suite (6 tests, all green)

1. **Crimond §8 worked example** — 10 notes, 8 syllables, underlines at positions 4 & 7 produce `w: The Lord's my _ shep- -herd, _ I'll not want;` plus three trivial syllabic phrases.
2. **Single-source-of-truth invariant** — for every phrase, `countNoteHeads(body) === wTokenCount(body)`.
3. **PHRASE_BREAK invariance** — two ABC bodies with the same total notes but different `% PHRASE_BREAK` positions produce the same concatenated w-token sequence (stripped of separators). Proves the algorithm consumes the global token stream regardless of where phrases are partitioned.
4. **Validation failure (count mismatch)** — passing 27 syllables when 28 are needed returns `passesValidation: false` with a warning naming the mismatch; does not throw.
5. **Multi-note melisma** — 3 consecutive underlined tokens after one syllable emit `w: lo _ _ _` (proves underline-spanning generalises beyond the canonical 2-note dot-pair).
6. **Edge cases (zero tokens / zero syllables)** — both return `passesValidation: false` with warnings; neither throws.

## Key Fixture Decisions

- **Crimond §8 fixture is deliberately minimal.** Phrases 2–4 use trivial 1:1 syllabic mappings; only phrase 1 carries the §8 worked-example melismas. This keeps the fixture inspectable while still exercising the multi-phrase walk.
- **The fixture's ABC music body is non-musical.** `countNoteHeads` only counts note heads — durations and rhythms don't affect the test. Each phrase has exactly the required head count (10 / 6 / 8 / 6) and the test verifies the w-stream slices align correctly.
- **PHRASE_BREAK invariance fixture uses TWO distinct splits of the same total note count (30).** The "moved break" variant slides one note from phrase 1 (was 10) into phrase 2 (was 6 → 7). The w-token sequence (PHRASE_BREAK-separators stripped) is identical, proving the algorithm doesn't gate melisma placement on phrase boundaries.

## `passesValidation` Semantics (for downstream consumers)

```
passesValidation === true  IFF
  (a) tokens.length === underlined.length
  (b) tokens.length > 0 AND syllables.length > 0
  (c) count(non-underlined tokens) === syllables.length
  (d) for every phrase: countNoteHeads(body) === wTokenCount(w-line)
  (e) zero warnings recorded during walk (no leftover tokens, no exhausted streams)
```

**Plan 04 batch driver MUST check `passesValidation` before writing to `tunes.abc_notation`.** A `false` return is the signal to skip the tune (D-05: heuristic fallback applies — no DB write). This is the explicit mitigation for threat T-04.11-02-01 (corrupt w: lines silently shipped to DB).

On `passesValidation === false`, the returned `abc` field is the **input `existingAbc` unchanged** in the up-front-bailout paths (length mismatch, zero tokens, zero syllables) and the **best-effort partial rewrite** in the mid-walk failure paths (cursor exhaustion, leftover tokens). Callers should treat any `false` as "skip, don't write" regardless.
