# Phase 04.9.15 Plan 02: Inline-Staff A+/A- Decoupling Summary

Extended the 04.9.14-01 split-leaf notation-scale decoupling pattern to inline (chromeless, non-split) Staff view: A+/A− now resizes lyric text only, while the abcjs staff notation scale is driven by a separate `notationBaseSize` state that tracks the existing viewport-resize proportional-zoom heuristic exclusively. Also corrected the A+/A− range to step 2px / floor 8 / soft-40 / hard-120 per UI-SPEC.

## What Was Built

**`src/lib/notation-scale.ts`** — a pure module (no React/DOM/abcjs imports) exporting:
- `SPLIT_LEAF_NOTATION_SCALE = 1`
- `INLINE_STAFF_NOTATION_SCALE = 13 / 14` (fallback constant, used ONLY when `notationBaseSize` is omitted by an uncontrolled caller)
- `computeNotationScale({ viewMode, chromeless, baseSize, notationBaseSize })` — a 3-way branch:
  1. `staff-split` / `solfege-split` → `SPLIT_LEAF_NOTATION_SCALE` (1)
  2. `chromeless && viewMode === 'staff'` (inline Staff) → `(notationBaseSize ?? 13) / 14` — tracks the viewport-derived `notationBaseSize`, independent of `baseSize`
  3. everything else (non-chromeless desktop staff, lyrics view, etc.) → `baseSize / 14` (unchanged coupled behaviour)

**`src/lib/notation-scale.test.ts`** — 9 vitest cases proving: split-leaf scale is inert to `baseSize`; inline-Staff scale tracks `notationBaseSize` and NOT `baseSize` (same `notationBaseSize` + different `baseSize` ⇒ identical scale); inline-Staff scale VARIES when `notationBaseSize` varies (proving it's not an inert fixed constant); fallback to `INLINE_STAFF_NOTATION_SCALE` only when `notationBaseSize` is omitted; non-chromeless and lyrics modes still couple to `baseSize`.

**`NotationRenderer.tsx`**:
- Exported `MIN_SIZE`, `MAX_SIZE` (120), `SIZE_STEP` (2) so `GlassBottomBar` can reuse the ceiling/step.
- Added optional `notationBaseSize?: number` prop.
- Replaced the local `isSplitForScale` / inline `SPLIT_LEAF_NOTATION_SCALE` / ternary with a single call to `computeNotationScale({ viewMode, chromeless, baseSize, notationBaseSize })`.

**`SingingView.tsx`**:
- Added `notationBaseSize` state (seeded `13`) + `notationBaseSizeRef` (kept in sync via `useEffect`, mirroring the existing `baseSizeRef` pattern).
- **Repurposed** (not duplicated) the existing 04.9.4-03 proportional-zoom resize effect: it now reads/writes `notationBaseSizeRef`/`setNotationBaseSize` instead of `baseSizeRef`/`setBaseSize`. The `clamp(x, 8, 40)` math, 150ms debounce, and 8px-delta suppression are byte-for-byte unchanged — only the target state variable moved.
- `handleBaseSizeChange` (fired by A+/A− presses) simplified to just `setBaseSize(newSize)` — no longer resets `referenceWidthRef`, since that ref now belongs exclusively to the notation-resize heuristic.
- `notationBaseSize={notationBaseSize}` passed to `<NotationRendererClient>` alongside the existing `baseSize={baseSize}`.

**`GlassBottomBar.tsx`**:
- Imports `MAX_SIZE`, `SIZE_STEP` from `NotationRenderer`.
- A− button: `Math.max(8, baseSize - SIZE_STEP)`, `disabled={baseSize <= 8}`.
- A+ button: `Math.min(MAX_SIZE, baseSize + SIZE_STEP)`, `disabled={baseSize >= MAX_SIZE}`.
- Both buttons get `disabled:opacity-40 disabled:pointer-events-none` styling. `aria-label`s unchanged (`Decrease size` / `Increase size`).
