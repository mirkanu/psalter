# Phase 04.9.15 — UI Design Contract

> Visual and interaction contract for mobile inline-staff optimization: shrink the repeated clef/key-signature block on wrapped rows, decouple A+/A− to control lyric text size only, add verse numbers to inline staff (matching lyrics-only/split-leaf), fix row-stretch/justification whitespace, and gate the Inline Staff layout option behind explicit `tuneMelismaDecisions.status === 'approved'`. Inherits all tokens, `GlassBottomBar`, and `GearPopover` component patterns from Phase 04.9.4/04.9.13/04.9.14 (approved). Only delta decisions are recorded here.

## Layout Contract

### (a) Clef/Key-Signature Shrink on Wrapped Rows

**Decision (confirmed):** Shrink, do not hide. Per `.planning/notes/abcjs-clef-keysig-research.md`, abcjs has no reliable native option to suppress the repeated clef/key-signature block on wrapped continuation lines (`clef.hide` is buggy under `wrap: true` per abcjs GitHub #437), and standard engraving convention redraws it on every system regardless. SVG post-processing to remove the glyph group is explicitly rejected as fragile.

**Rule:**
- Row 1 (first staff system): clef + key signature render at 100% of the row's staff scale (unchanged).
- Row 2+ (every wrapped continuation system): the clef + key-signature glyph group renders at **60%** of the row-1 size.
- This is a glyph-group-local scale, not a full-system rescale — notes, stems, and lyrics on rows 2+ remain at full staff scale. Only the leading clef/key block shrinks.

**Implementation anchor (best-known, verify against rendered SVG before implementation):** abcjs's SVG output groups the leading clef/key/time area of each staff system under `.abcjs-top-line` inside each `.abcjs-staff-wrapper` (confirmed present in `abcjs-basic.js`'s emitted class list; no dedicated `.abcjs-clef` / `.abcjs-key-signature` class exists). Target via a `transform: scale(0.6)` with an appropriate `transform-origin: left center` on `.abcjs-staff-wrapper:not(:first-of-type) .abcjs-top-line`, scoped to inline Staff view only (`[data-view-mode="staff"]`). The executor must render a real multi-row tune and inspect the actual DOM/class structure before finalizing the selector — this is a CSS-only visual contract, not a verified implementation detail.

**Row 1 exclusion:** The first system's clef/key/time signature is the reader's primary orientation point and must stay full size — never scale row 1.

**Vertical alignment:** Shrinking only the leading glyph group must not shift the staff lines vertically relative to the rest of the row's notes (i.e. the 5-line staff itself stays at full scale; only the clef/key glyphs shrink within their allotted space). If `transform: scale()` on the group visually mis-aligns the staff lines, fall back to shrinking the glyph paths via a narrower `staffwidth`-driven approach scoped to that group — but the default, simplest approach (CSS transform) should be tried first.

---

### (b) A+/A− — Lyric Font Size Only (Inline Staff)

**Decision (confirmed):** In Inline Staff view, A+/A− in `GlassBottomBar` controls **lyric text size only** — it no longer drives abcjs notation `scale`. This extends the decoupling pattern already shipped for split-leaf in 04.9.14-01 (`SPLIT_LEAF_NOTATION_SCALE` constant, see `NotationRenderer.tsx` lines 488–496) to inline Staff.

**Range:**
- Primary range: **8px–40px**, step **2px** (matches `GlassBottomBar`'s existing A+/A− convention: `min-h-10 min-w-10` tap targets, `active:scale-[0.90]` feedback).
- Decrease is **unconstrained** below the primary range down to the hard floor of **8px** (same floor as existing `GlassBottomBar` behaviour — do not go lower).
- 40px is a **soft threshold**, not a hard cap. Pressing A+ past 40px is allowed and explicitly **relaxes the one-phrase-per-row / single-screen-fit rule** as a last resort (i.e. once lyric text exceeds 40px, the layout may require scrolling or may break the "one phrase per row" wrapping guarantee — this is an accepted tradeoff for readability at that size, not a bug).
- Hard ceiling: **120px** (matches the existing `MIN_SIZE`/`MAX_SIZE` constants already defined in `NotationRenderer.tsx` — `MIN_SIZE = 4`, `MAX_SIZE = 120` — reuse `MAX_SIZE` as the lyric-size ceiling; do not introduce a second magic number).

**Staff notation scale (unaffected by A+/A−):** Inline Staff notation scale continues to be governed exclusively by the existing 04.9.4-03 proportional zoom heuristic (`referenceWidthRef` / viewport-resize-driven `clamp(baseSize × newWidth/refWidth, 8, 40)` in `SingingView.tsx`), decoupled from the lyric-only A+/A− control introduced here. Concretely: introduce an `INLINE_STAFF_NOTATION_SCALE` fixed constant (mirroring `SPLIT_LEAF_NOTATION_SCALE = 1` at `NotationRenderer.tsx:495`) so `scale` for inline Staff no longer reads `baseSize / 14`.

**A+/A− aria-labels:** Unchanged — `Decrease size` / `Increase size` (existing `GlassBottomBar` copy, reused verbatim; do not rename to imply "lyrics" since the control is contextually lyric-only only in Staff/inline mode and remains the general size control in Lyrics-only/Solfège modes).

### (c) Verse Numbers in Inline Staff

**Decision (confirmed):** Reuse the exact existing `.verse-number` treatment from lyrics-only/split-leaf — no new visual treatment, no new CSS class.

**Style (inherited, unchanged):**
```css
.verse-number {
  font-size: calc(var(--staff-base-size, 14px) * 0.5);
  vertical-align: super;
  line-height: 1;
}
```

**Placement:** Inline-superscript, prefixed to the verse text exactly as `StanzaList.tsx` already does via `<sup className="verse-number">{ref}</sup>` for lyrics-only/split-leaf. Inline Staff's `w:` lyric line rendering must surface the same `bibleVerseRef` prefix in the same superscript position relative to the first syllable of each verse — no repositioning, no different font-size multiplier, no color change.

**Scoping note:** The `--staff-base-size`-relative sizing means verse numbers in Inline Staff will scale with whatever drives `--staff-base-size` in that view. Per (b) above, since A+/A− now controls lyric size independently of staff `scale`, verse numbers (being lyric-adjacent) scale with the lyric A+/A− control, not with notation scale — consistent with how `.verse-text` already behaves.

### (d) Row-Stretch / Justification Fix

**Decision (confirmed):** Fix wasted whitespace caused by row justification/stretch on **non-last rows** (confirmed reproducible on rows 1 and 2 of multi-row tunes, not only the trailing/underfull last row).

**Visual rule:** Every staff row except the final row of the tune should visually fill its available width with evenly-distributed note spacing (abcjs's normal justified behaviour) — rows must **not** render with excess trailing blank space before the row wraps to the next system. This is a layout correctness fix, not a new visual pattern: the target state is "abcjs's own default justification, restored" — no new spacing tokens or component are introduced by this item.

**No new copy or component.** This is purely a layout-bug fix; out of scope for design-token changes. Executor should treat this as a regression fix against the intended (pre-bug) justified-row behaviour, not a new interaction to design.

---

### (e) Inline Staff Approval Gate

**Decision (confirmed):** Inline Staff (`viewMode === 'staff'`, non-split) is gated behind explicit `tuneMelismaDecisions.status === 'approved'` for the active tune. `null` / `'not_approved'` / any other value is **not sufficient** — only an explicit `'approved'` row unlocks Inline Staff. This mirrors the existing solfège inline gating pattern (`solfegeInlineAvailable`) already present in `GearPopover.tsx`.

**Gear menu (disabled state):** In `GearPopover`'s Layout sub-toggle group (`Inline` / `Split-Leaf`, `data-settings-sub="layout"`), when the active notation is Staff (`isStaff === true`) and the tune is not approved:
- The `Inline` button renders in the existing disabled visual treatment (`opacity-40 cursor-not-allowed`, `disabled` attribute) — same styling already used for the solfège-inline-unavailable case at lines 220–233 of `GearPopover.tsx`.
- Tooltip (native `title` attribute on the button, same pattern as the existing `title="Inline Solfège coming soon"`):
  > `Inline Staff notation isn't approved for this tune yet`

**Fallback (reached via navigation, e.g. next/prev psalm while already in Inline Staff mode):** If the user navigates to a psalm/tune where Inline Staff is requested but not approved, silently fall back to Split-Leaf (JPEG) — the same fallback mechanism already used for non-approved solfège — and surface a toast (via `sonner`, same call pattern as the existing `toast('Coming soon', { description: ... })` calls in `GearPopover.tsx`):
  > `Inline Staff not available for this tune — showing Split-Leaf. Pick a different view in Settings.`

**Toast styling:** Reuse the existing `sonner` default toast treatment already wired via `<Toaster richColors />` in `layout.tsx` — no custom toast variant. This is an informational fallback notice, not an error — do not use the `richColors` destructive/red variant.

**No gating change to Split-Leaf Staff or either Solfège mode.** This gate applies exclusively to `viewMode === 'staff'` (inline, non-split). `staff-split` (Split-Leaf JPEG) remains gated only by `staffAvailable` (ABC exists), unchanged from current behaviour.

Add `staffInlineApproved: boolean` prop (derived from `tuneMelismaDecisions.status === 'approved'` for the active tune, resolved server-side or via existing client data flow — data-layer wiring is a planning/execution concern, not a design-contract concern). No new component — extend the existing `.verse-number` CSS class usage into the inline-staff code path.

Introduce `INLINE_STAFF_NOTATION_SCALE` constant (fixed, viewport-heuristic-driven — not the lyric A+/A− value) so inline Staff's abcjs `scale` prop no longer reads `baseSize / 14`. `baseSize` continues to drive `--staff-base-size` (lyrics + verse numbers) exactly as it does today.

## Interaction States

### Clef/Key Shrink (Row 2+)

Static — no animation. Applied at render time based on row index within the SVG (row 1 excluded, rows 2+ scaled to 60%). No transition needed since this is a structural render-time property, not a user-triggered state change.

### A+/A− (Lyric-Only, Inline Staff)

- Tap `A−`/`A+`: `active:scale-[0.90] transition-transform duration-75` (existing `GlassBottomBar` tap feedback, unchanged).
- Below 8px: buttons stay enabled at 8px but decrementing further is a no-op (floor, not disabled-state — matches existing `Math.max(8, baseSize - 1)` pattern, adapted to step 2).
- At/above 40px: `A+` remains enabled and continues incrementing toward 120px — no confirmation dialog, no warning toast. The relaxation of one-phrase-per-row/single-screen-fit is silent and automatic (the layout simply reflows/wraps more as needed).
- At 120px: `A+` becomes a no-op at the ceiling (parity with existing `MAX_SIZE` disabled-at-ceiling pattern in `NotationRenderer.tsx` lines 672–673 — Inline Staff's `GlassBottomBar` A+/A− should disable at 120 rather than silently clamp with no visual feedback).

### Approval Gate — Gear Menu

Disabled `Inline` button in the Layout sub-toggle: `opacity-40 cursor-not-allowed`, `disabled` attribute prevents `onClick`, `title` attribute surfaces tooltip on hover/long-press (native browser tooltip — no custom tooltip component introduced). Identical interaction pattern to the existing solfège-inline disabled state.

### Approval Gate — Fallback Toast

Fires once per navigation event that lands the user in a non-approved Inline Staff state (e.g. next/prev psalm nav while Inline Staff was active). Uses `sonner`'s default toast entrance/exit animation (no custom timing specified — inherits `<Toaster richColors />` global config from `layout.tsx`). Does not repeat on every render — fire-once-per-navigation-transition, matching the existing `toast(...)` call-site pattern (called from an event handler / effect keyed to the navigation change, not from the render body).

## Accessibility

Inherits all a11y requirements from 04.9.3/04.9.4/04.9.13/04.9.14, plus:

- **Disabled `Inline` button (Staff branch):** `disabled` attribute (not just visual opacity) so screen readers and keyboard nav correctly skip/announce it as unavailable — matches existing solfège-inline pattern.
- **Verse numbers in Inline Staff:** `<sup>` semantic element (unchanged from `StanzaList.tsx` precedent) — screen readers announce superscript context appropriately; no `aria-hidden` needed since the verse number is meaningful content (verse/Bible reference).
- **A+/A− at extreme sizes (≥40px, up to 120px):** No accessibility regression expected — larger text only improves legibility. Layout relaxation (allowing scroll / breaking one-phrase-per-row) at these sizes is an accepted tradeoff, not an a11y violation, since the content remains fully readable and navigable.
- **Fallback toast:** `sonner`'s built-in `aria-live` region handles announcement; no additional work needed.
