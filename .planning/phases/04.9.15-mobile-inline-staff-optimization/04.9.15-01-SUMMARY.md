# Phase 04.9.15 Plan 01: Inline-Staff Clef/Key + Row-Stretch Diagnostic Summary

Committed a Playwright diagnostic (`tests/diagnostics/inline-staff-clef-stretch-diff.mjs`) that renders live multi-row inline-Staff tunes at a 375px mobile viewport and confirms both facts Plan 05's fixes depend on: the exact DOM/class nesting of the repeated clef + key-signature group on wrapped rows, and whether non-last staff rows under-fill the notation container width.

## What Was Built

A single diagnostic script mirroring the structure of `tests/diagnostics/split-leaf-staff-diff.mjs`:

- Uses the shared Playwright daemon (`require('/home/services/playwright-daemon/client.js')`) exclusively — never spawns raw Chromium.
- Polls `waitForBrowserReady()` (10 tries, 3s apart) before submitting any job; prints `DIAGNOSTIC-UNAVAILABLE: ...` and exits 0 if the daemon never becomes ready.
- Suppresses the onboarding tour via `page.addInitScript` (`psalter_tour_v2` localStorage flag) before each navigation.
- Renders `/psalms/23` (Crimond) and `/psalms/78` (Azmon/Denfield, CM) at 375x667, switches to inline Staff via the Gear popover (`[data-singing-gear]` → radio "Staff" → radio "Inline" → Escape).
- **Part A (item a):** scopes to `[data-notation-body][data-view-mode="staff"]`, collects all `.abcjs-staff-wrapper` rows, and for each row reports the full class attribute of every `.abcjs-clef`, `.abcjs-key-signature`, and `.abcjs-staff-extra` element, plus the topmost `<g>`/`<text>` elements preceding the first note — printed with a `CLEF-ROW <i>:` prefix.
- **Part B (item d):** measures `[data-notation-viewarea]` container width and each row's `getBoundingClientRect().width`, computes `fillRatio`, flags `underFilled` (fill < 0.97) for non-last rows, and prints `STRETCH-ROW <i>:` lines plus a per-URL and overall `VERDICT` line.
- Captures a full-page screenshot per URL under `tests/diagnostics/out/`.
- Wraps `main()` in a `.catch` that also prints `DIAGNOSTIC-UNAVAILABLE:` and exits 0 — never throws.

## Live Run Results (dev server + daemon both available)

The diagnostic was run against the live dev server (`http://localhost:3005`) and the shared Playwright daemon, both already running. It exited 0 and produced conclusive results for both open assumptions:

### CONFIRMED — Clef/key-signature selector (item a, resolves Assumption A1)

On every row of both tunes:
- `.abcjs-clef` and `.abcjs-key-signature` each carry the combined class `abcjs-staff-extra abcjs-clef ...` / `abcjs-staff-extra abcjs-key-signature ...` (plus `abcjs-l{N}`, `abcjs-m0`, `abcjs-mm{N}`, `abcjs-v0` line/measure/voice suffixes).
- Both elements are direct children `<g>` elements of `.abcjs-staff-wrapper`, siblings of `.abcjs-staff` (the ruling-line group) and, on row 0 only, `.abcjs-time-signature`.
- `hasClefClass=true` and `hasKeySigClass=true` on ALL rows (not just wrapped continuation rows) — the repeated clef/key group is present on every row, confirming the shrink-on-wrap fix (Plan 05) needs a `:not(:first-of-type)` row selector, exactly as the corrected Code Examples §1 selector in RESEARCH.md proposes:
  ```css
  .abcjs-staff-wrapper:not(:first-of-type) .abcjs-clef,
  .abcjs-staff-wrapper:not(:first-of-type) .abcjs-key-signature { ... }
  ```
- `.abcjs-top-line` was NOT targeted or scaled anywhere in the diagnostic (confirmed via grep — only mentioned in a code comment documenting why it's the wrong selector).

### CONFIRMED — Row-stretch under-fill (item d, resolves Assumption A2)

**VERDICT: non-last rows under-fill = YES** on both tunes:

| Tune | Row 0 fill | Row 1 fill | Row 2 fill | Row 3 (last) fill | Worst-case (non-last) |
|------|-----------|-----------|-----------|-------------------|------------------------|
| psalm-23 (Crimond) | 0.893 | 0.893 | 0.896 | 0.897 | 0.893 |
| psalm-78 (Azmon/Denfield) | 0.808 | 0.807 | 0.897 | 0.897 | 0.807 |

Both tunes rendered 4 staff rows at 375px viewport (container width 375px). The last row in both cases fills to ~0.897, while non-last rows fill anywhere from 0.807–0.897 — confirming the bug reproduces live and quantifying the gap (up to ~19% under-fill on psalm-78's first two rows) that Plan 05's fix must close. This is consistent with RESEARCH.md's Assumption A2 hypothesis that the root cause lies in this codebase's own `effectiveStaffWidth`/`targetStaffwidth` computation (`AbcPlayer.tsx`), not a missing abcjs format option.
