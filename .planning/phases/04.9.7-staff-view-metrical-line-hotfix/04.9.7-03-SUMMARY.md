# Phase 4.9.7 Plan 03: Per-Line Inner-Array Contract (RENDER-07b) Summary

Resolved the cross-stanza spill artefact identified at Plan 02's human-verify checkpoint. Promoted "one metrical line = one sub-staff" from heuristic to structural invariant by changing `mapCycleToPhraseSyllableLines` to return `string[][]` (one entry per metrical line per phrase slot) and threading that shape through `NotationRenderer`.

## Chosen Approach: B (Multi-Element Inner Array)

**Problem:** Plan 01's joined-string shape (`result[p] = [text]` where `text` joined all metrical lines for a phrase) forced `NotationRenderer` to use `splitWLineIntoChunks` to proportionally re-split the joined payload. This split was token-count-driven and drifted across stanzas — causing "...I'll not vale, want." to appear on system 1 stanza 1 row 1 instead of "...I'll not want."

**Fix:** `mapCycleToPhraseSyllableLines` now returns `string[][]` where each inner array holds one string per metrical line for that phrase slot. The renderer indexes `wLines[cycleIdx][sub]` directly — no proportional splitting needed.

## Code Changes

### `src/lib/stanza-cycles.ts` — `mapCycleToPhraseSyllableLines`

**Before (Plan 01, joined):**
```ts
const linesPerPhrase = Math.max(1, Math.floor(flatLines.length / phrasesPerCycle))
for (let p = 0; p < phrasesPerCycle; p++) {
  const start = p * linesPerPhrase
  const slice = flatLines.slice(start, start + linesPerPhrase)
  if (slice.length === 0) continue
  const text = slice.map((l) => l.syllables?.join(' ') ?? syllabifyForAbc(l.text)).join(' ')
  result[p] = [text]   // ← single joined string
}
```

**After (Plan 03, per-line):**
```ts
const linesPerPhrase = Math.max(1, Math.floor(flatLines.length / phrasesPerCycle))
for (let p = 0; p < phrasesPerCycle; p++) {
  const start = p * linesPerPhrase
  const slice = flatLines.slice(start, start + linesPerPhrase)
  for (const l of slice) {
    const text = l.syllables && l.syllables.length > 0
      ? l.syllables.join(' ')
      : syllabifyForAbc(l.text)
    result[p]!.push(text)   // ← one push per metrical line
  }
}
```

Under-fill: trailing slots return `[]` (was `['']`).

### `src/components/notation/NotationRenderer.tsx`

- `wLinesForPhrase(i)` return type changed from `string[]` to `string[][]`
- Sub-staff loop now derives `targetSubdivisions = max(naturalSubdivisions, linesPerPhrase || 1)` from the inner array length
- Each sub-staff emits `w: wLines[cycleIdx][sub]` directly — `splitWLineIntoChunks` is no longer called on the lyric path
- `splitWLineIntoChunks` left defined with a TODO comment

## UAT Extension (Task 3) — Stage 1c

Added Stage 1c (RENDER-07b) to `scripts/uat/psalm-23-crimond-regression.js`:

Instead of y-coordinate bucketing (which is fragile against abcjs layout changes), the assertion groups abcjs SVG `text.abcjs-lyric` nodes by their `abcjs-lN` class (abcjs emits one text node per syllable, grouped by `l0`/`l1`/`l2`... sub-staff line index). This is the correct mechanism: Plan-03 assertion inspects the sub-staff lines directly.

**Key assertion:** Sub-staff line 0's last syllable text node starts with `"want"` (stanza-1 contribution) — proving no cross-stanza spill from "vale,". Line 1 contains `"makes"` and `"down"` — confirming line-1 content is in its own sub-staff.
