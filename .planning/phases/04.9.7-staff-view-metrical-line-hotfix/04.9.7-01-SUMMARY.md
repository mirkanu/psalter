### The fix (Task 2 — GREEN)

Replaced the truncating loop in `src/lib/stanza-cycles.ts` (`mapCycleToPhraseSyllableLines`).

**Before (broken):**
```ts
for (let i = 0; i < Math.min(flatLines.length, phrasesPerCycle); i++) {
  const line = flatLines[i]!
  const text =
    line.syllables && line.syllables.length > 0
      ? line.syllables.join(' ')
      : syllabifyForAbc(line.text)
  result[i] = [text]
}
```

**After (D-02 verbatim):**
```ts
const linesPerPhrase = Math.max(1, Math.floor(flatLines.length / phrasesPerCycle))
for (let p = 0; p < phrasesPerCycle; p++) {
  const start = p * linesPerPhrase
  const slice = flatLines.slice(start, start + linesPerPhrase)
  if (slice.length === 0) continue
  const text = slice
    .map((l) =>
      l.syllables && l.syllables.length > 0
        ? l.syllables.join(' ')
        : syllabifyForAbc(l.text),
    )
    .join(' ')
  result[p] = [text]
}
```

## Deviations from Plan

**1. [Rule 1 — Bug] Tightened Psalm 23 line-2/line-3 regexes to tolerate inter-syllable whitespace**
- **Found during:** Task 2 GREEN verification
- **Issue:** Plan-specified regexes `/In pas-?tures green/` and `/qui-?et waters by/` assumed contiguous hyphenation, but `syllabifyForAbc` emits `"In pas- tures green"` and `"qu- i- et waters by"` (space between syllables).
- **Fix:** Adjusted regexes to `/In pas-?\s*tures green/` and `/qu-?\s*i-?\s*et waters by/`. Intent unchanged — still asserts both dropped metrical lines appear. The lines are now present in the output (proving the production fix worked); the regex literal in the plan was overly strict against the actual syllabifier output format.
