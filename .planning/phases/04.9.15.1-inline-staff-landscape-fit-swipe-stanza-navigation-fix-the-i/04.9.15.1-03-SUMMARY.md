### Checkpoint-requested fixes and fold-ins

**1. [Checkpoint round 1, issue 1] Padding around inline Staff broke MOBILE-09's landscape height-fit — required fix before the checkpoint could pass**
- **Found during:** Task 4 human-verify, round 1 (human tested the merged build live)
- **Issue:** Inline Staff notation needed top padding (portrait + landscape) and bottom padding (landscape only), but the fit-scale calculation in `AbcPlayer.tsx` measures `data-notation-viewarea`'s `clientHeight` directly to compute its SVG scale — adding CSS padding to that exact element would inflate its measured height without shrinking the space actually available to content, reintroducing MOBILE-09's landscape scroll bug.
- **Fix:** Introduced a plain flex wrapper (`data-notation-viewarea-wrap`) OUTSIDE the measured element, carrying the padding. Flexbox content-box math then naturally reduces the inner fit-slot's own `clientHeight` by the padding amount, so the fit calculation sees the already-reduced budget.
- **Files modified:** `src/components/notation/NotationRenderer.tsx`
- **Verification:** Playwright daemon (real device UA + touch emulation), portrait and landscape: rendered SVG bounds stay exactly within the padded area with zero overflow.
- **Committed in:** `d9b6571`

**2. [Checkpoint round 1, issue 2] Swipe tour hand animation badly positioned, dot-preview invisible off-screen**
- **Found during:** Task 4 human-verify, round 1
- **Issue:** The swipe step's hand + dot-preview overlay was anchored to the raw `unionBbox` of the `'scroll-area'` target, which can be taller than or shifted outside the visible viewport (scroll-hide reflow's negative margin / 100dvh growth), landing the hand over real content and pushing the dot-preview off-screen entirely.
- **Fix:** Clamped/intersected the overlay's positioning rect to the visible viewport before using it as the anchor.
- **Files modified:** `src/components/singing/OnboardingTour.tsx`
- **Verification:** Playwright daemon, portrait and landscape: hand + dot-preview render fully within the viewport; reduced-motion still correctly disables the hand's animation.
- **Committed in:** `56022a0`

**3. [Checkpoint round 2, issue 3] Remove the tour's dot-preview clone and its wording entirely**
- **Found during:** Task 4 human-verify, round 2
- **Issue/request:** Human preference — the decorative dot-indicator-preview clone (bottom-right pill inside the swipe step overlay) should not exist at all; the real `StanzaDotIndicator` speaks for itself.
- **Fix:** Deleted the dot-preview clone block; updated `SWIPE_STEPS[0].copy` to drop the "the dots show where you are" clause.
- **Files modified:** `src/components/singing/OnboardingTour.tsx`
- **Verification:** Playwright daemon: dot-preview clone confirmed absent from the DOM; copy text confirmed updated.
- **Committed in:** `847e1b9`

**4. [Checkpoint round 2, issue 4] Tour bubble clipped above the viewport top edge on mobile portrait**
- **Found during:** Task 4 human-verify, round 2
- **Issue:** For the `'scroll-area'` target (tall, near-top bbox), `placeBelow` evaluated false, and the un-clamped `top: bbox.top - padding - 8` (the bubble's bottom edge, paired with `translate(-50%, -100%)`) pushed most of the ~142px-tall bubble off-screen above the viewport.
- **Fix:** Added a general clamp on the bubble's vertical position (`[12px, viewportH - 12px]`), applied to all steps (not just the swipe step), since `'scroll-area'` was also used by a scroll-hide step at the time.
- **Files modified:** `src/components/singing/OnboardingTour.tsx`
- **Verification:** Playwright daemon: all 5 tour steps' bubbles confirmed fully within the viewport in both portrait and landscape.
- **Committed in:** `847e1b9`

**5. [Checkpoint round 3] New feature: post-commit slide/fade transition on stanza-page change**
- **Found during:** Task 4 human-verify, round 3 — human explicitly requested this as new scope after approving the core swipe functionality, choosing the recommended approach from a discussion of options.
- **Rationale:** A live finger-following drag was rejected because `NotationRenderer` drives its internal `cyclePage` from the controlled `stanzaPage` prop and abcjs re-renders the SVG on that change — not a static draggable image — so live drag-follow would require snapshotting rendered SVGs (high risk/complexity). A discrete post-commit transition avoids touching abcjs's rendering internals at all.
- **Implementation:** `stanzaAnimDirectionRef` (set inside `handleStanzaNext`/`handleStanzaPrev`, read+cleared in an effect) tracks direction without diffing old/new page numbers (avoids first/last-page off-by-one edge cases). `notationAnimRef` wraps `NotationRendererClient` in a stable flex wrapper that never unmounts/remounts the subtree. A `useEffect` keyed on `[stanzaPage]` fires a transform/opacity-only Web Animations API `.animate()` call (translateX 24px↔0 + opacity 0.4→1, 180ms ease-out, direction-mirrored), respecting `prefers-reduced-motion`. Only fires for handler-driven navigation (not tune-switch sync-back or synth-playback auto-advance, both of which bypass these handlers).
- **Files modified:** `src/components/singing/SingingView.tsx`
- **Verification:** Playwright daemon: button-driven and swipe-driven navigation both fire the correctly-directed `.animate()` call; `prefers-reduced-motion: reduce` correctly skips it; the new wrapper introduces zero layout/overflow disturbance (verified against the round-1 padding-fix baseline in both chrome-visible and chrome-auto-hidden landscape states). **Approved live by the human.**
- **Committed in:** `c22b59c`

**6. [Checkpoint round 5] Remove SCROLL_HIDE_STEPS from OnboardingTour entirely**
- **Found during:** Task 4 human-verify, round 5 — human noticed the auto-triggered tour and "Restart tour" showed different lengths and requested the scroll-hide explanation be removed completely (scroll-to-hide is discoverable naturally).
- **Fix:** Deleted `SCROLL_HIDE_STEPS` and its comment block; removed the conditional spread from the `steps` `useMemo`. Cascade-removed now-dead code: `isSplitLeafMobile` (only consumer removed), `isMobile` state + resize-listener effect (only consumer was `isSplitLeafMobile`), and the `viewMode` prop (only consumer was `isSplitLeafMobile`) — including dropping `viewMode={viewMode}` from `SingingView.tsx`'s `<OnboardingTour>` call site and the now-unused `ViewMode` import. Updated three stale comments referencing `SCROLL_HIDE_STEPS`. Did not bump `TOUR_KEY` (content removal, not new functionality).
- **Files modified:** `src/components/singing/OnboardingTour.tsx`, `src/components/singing/SingingView.tsx`
- **Verification:** Playwright daemon: forced `staff` (non-split) and `staff-split` view modes both now show the identical 5-step tour (4 base + 1 swipe) — previously split-leaf would have shown 8. `tsc --noEmit` clean; no remaining references to removed identifiers anywhere in `src/` or `tests/`.
- **Committed in:** `c872276`

## Issues Encountered

- **Verification tooling:** All Playwright-daemon and `npx tsc`/build commands had to be run from the worktree checkout path, not `/home/services/psalter` (the main repo) — the plan's own literal verify snippets pointed at the main repo and would have silently graded stale/wrong files if followed literally (same issue documented in this phase's Plan 01 SUMMARY).
- **Real-device emulation for Playwright:** `browser.newContext({ userAgent, hasTouch, isMobile })` reliably threw `Cannot redefine property: userAgent` in this daemon's persistent browser context. Worked around by using a CDP session's `Network.setUserAgentOverride` for UA spoofing and `page.addInitScript` to patch `navigator.maxTouchPoints` for touch-capability detection, then dispatching synthetic `TouchEvent`/`Touch` objects directly at the DOM level to simulate swipes — this combination reliably exercised the app's real device-detection code paths (`isPhoneDevice()`, `isTouchDevice`) without needing full native touch-hardware emulation.
- **Playwright daemon job timeout:** The daemon enforces a hard ~30s server-side job timeout regardless of the client's requested timeout value; `page.goto(..., { waitUntil: 'networkidle' })` against the Next.js dev server (persistent HMR websocket) sometimes never resolves within that window. Switched to `waitUntil: 'domcontentloaded'` + explicit `waitForTimeout` throughout for reliability.
- **Dev-server side effects on the worktree:** Running `npm run dev` in the worktree for live verification caused Next.js to auto-append an entry to `tsconfig.json`'s `include` array on every start; reverted with `git checkout -- tsconfig.json` after each verification session so it never leaked into a commit. A temporary `.env` (copied from the main repo, gitignored) was also removed after each session.
