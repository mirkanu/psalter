## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] vitest test-worker inherited VPS-wide NODE_ENV=production, breaking all React-rendering tests**
- **Found during:** Task 1 (writing and running `useSwipeGesture.test.ts`, which uses `@testing-library/react`'s `renderHook`)
- **Issue:** The VPS environment exports `NODE_ENV=production` globally (documented elsewhere in STATE.md as a known quirk — e.g. it also suppressed `drizzle-kit`'s devDependency install). This value was inherited unchanged by the vitest worker process because vitest only defaults `NODE_ENV` when it is unset — a preset value from the parent shell wins. With `NODE_ENV=production`, Node's `require('react')` resolves `react.production.js`, which does not export `React.act` (a dev-only testing export). `@testing-library/react`'s `act-compat.js` falls back to `react-dom/test-utils`'s deprecated `act`, which throws `TypeError: React.act is not a function` under React 19. This broke every test using `render()`/`renderHook()` — not just this plan's new test, but the pre-existing `src/components/notation/StanzaList.test.tsx` as well (confirmed failing identically before this fix).
- **Fix:** Added `test.env: { NODE_ENV: 'test' }` to `vitest.config.mts`, scoping the override to the vitest test-worker process only (no effect on `next build`/`next start` or any other command).
- **Files modified:** `vitest.config.mts`
- **Verification:** `npx vitest run src/hooks/useSwipeGesture.test.ts` (5/5 pass) and `npx vitest run src/components/notation/StanzaList.test.tsx` (5/5 pass, previously failing) both green after the fix.
- **Committed in:** `1a2589c` (part of Task 1 commit)
