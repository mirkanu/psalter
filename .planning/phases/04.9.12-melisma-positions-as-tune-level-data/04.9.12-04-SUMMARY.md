# Phase 04.9.12 Plan 04: Replace embedded-w branch with positions-based branch — Summary

NotationRenderer now uses `melismaPositions` from the DB to generate correct w: lines for ALL stanza cycles of approved tunes, replacing the old embedded-w branch that always emitted cycle 0 verbatim (causing stanza-page-2+ to show stanza 1 text repeated).

## What Changed

### NotationRenderer.tsx

- Removed `import { hasEmbeddedWLines, extractEmbeddedWLines }` and `import { renderEmbeddedWPhrase }` — both unused after branch deletion
- Added `melismaPositions?: number[][] | null` to `NotationRendererProps` interface
- Destructured `melismaPositions = null` from props
- Replaced the Phase 04.10 embedded-w branch (lines 812-864) with the Phase 04.9.12 positions branch:
  - Looks up `melismaPositions[phraseIndex]` — a Set of 0-based intra-phrase note indices that are melisma continuations
  - For each visible cycle, calls `wLinesForPhrase(i)` to get real stanza syllables, then places `_` tokens at position indices and syllables at non-position indices
  - Pushes music lines once (cycleIdx === 0), then one `w:` line per cycle — correct abcjs multi-stanza format
  - Falls through to existing heuristic path when `melismaPositions` is null or phrase has no positions
- Added `melismaPositions` to the `unifiedAbc` useMemo dependency array

### src/db/queries/tunes.ts

- Added `melismaPositions: number[][] | null` to `AlternateTune` interface
- Added `melismaPositions: true` to `fetchTunesByMeter` column selection

### src/app/psalms/[id]/page.tsx

- Added `melismaPositions` to the manually-built `primaryTune` object (cast from `primaryTuneRow` which has all columns via `tune: true`)

### src/components/singing/SingingView.tsx

- Added `melismaPositions` prop to `NotationRendererClient` JSX call
