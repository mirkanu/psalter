**Change A — onSave: derive melismaPositions and strip w: before posting**

The `onSave` callback currently posts `abcToSave` which may contain embedded w: lines (when `willSaveMode === 'melisma'`). Change it to:

1. Derive `melismaPositions: number[][]` from the current `tokens` and `underlined` state:
   ```typescript
   // Derive per-phrase melisma positions from underlined state.
   // tokens is the extractSopranoTokensWithPos result (has .phraseIdx and .globalIdx).
   const positsByPhrase = new Map<number, number[]>()
   for (const tok of tokens) {
     if (underlined[tok.globalIdx]) {
       const arr = positsByPhrase.get(tok.phraseIdx) ?? []
       arr.push(tok.phraseIdx === tok.phraseIdx ? /* 0-based within phrase */ 0 : 0)
       positsByPhrase.set(tok.phraseIdx, arr)
     }
   }
   ```
   Wait — the positions must be 0-based indices WITHIN the phrase, not globalIdx. Compute this correctly:
   ```typescript
   // Group tokens by phraseIdx in order, then for each phrase record
   // which intra-phrase indices are underlined.
   const melismaPositions: number[][] = []
   const phraseIdxSet = [...new Set(tokens.map(t => t.phraseIdx))].sort((a, b) => a - b)
   for (const pIdx of phraseIdxSet) {
     const phraseToks = tokens.filter(t => t.phraseIdx === pIdx)
     const positions: number[] = []
     phraseToks.forEach((tok, intraIdx) => {
       if (underlined[tok.globalIdx]) positions.push(intraIdx)
     })
     melismaPositions.push(positions)
   }
   ```

**Change C — pre-populate underlines from melismaPositions on tune load**

In the `useEffect` that calls `parseSavedWLines(tune.abcNotation)` to pre-populate underlines, add a fallback path:

```typescript
useEffect(() => {
  if (!tune) return

  // NEW PATH: if the tune has melismaPositions, restore underlines from positions.
  // This is the post-migration path for approved tunes (their abc_notation no longer
  // has w: lines, so parseSavedWLines would return null).
  if (tune.melismaPositions && tune.melismaPositions.length > 0) {
    // Convert per-phrase positions back to globalIdx → true map.
    const u: Record<number, boolean> = {}
    const allTokens = effectiveAbc ? extractSopranoTokensWithPos(effectiveAbc) : []
    const phraseIdxSet = [...new Set(allTokens.map(t => t.phraseIdx))].sort((a, b) => a - b)
    for (const pIdx of phraseIdxSet) {
      const phraseToks = allTokens.filter(t => t.phraseIdx === pIdx)
      const posSet = new Set(tune.melismaPositions[pIdx] ?? [])
      phraseToks.forEach((tok, intraIdx) => {
        if (posSet.has(intraIdx)) u[tok.globalIdx] = true
      })
    }
    setUnderlined(u)
    setUnderlinedUserDirty(false)
    setSavedSyllablesPerPhrase(null) // positions path doesn't carry syllables
    return
  }

  // EXISTING PATH: parse from embedded w: lines (legacy tunes not yet migrated,
  // or tunes the user is editing before their first save under the new system).
  const parsed = parseSavedWLines(tune.abcNotation)
  if (!parsed) {
    setUnderlined({})
    setSavedSyllablesPerPhrase(null)
    setUnderlinedUserDirty(false)
    return
  }
  const u: Record<number, boolean> = {}
  for (const gi of parsed.underlinedGlobalIndices) u[gi] = true
  setUnderlined(u)
  setUnderlinedUserDirty(false)
  setSavedSyllablesPerPhrase(
    parsed.syllablesPerPhrase.some(p => p.length > 0) ? parsed.syllablesPerPhrase : null,
  )
}, [tune])
```

Note: `extractSopranoTokensWithPos` is already imported in the editor. This effect now depends on `tune` and `effectiveAbc` (add effectiveAbc to the dependency array carefully — or use `tune.abcNotation` directly to avoid infinite re-render since effectiveAbc is derived from tune).

To avoid re-render loops, use `tune.abcNotation` (the raw DB value, not `effectiveAbc`) for token extraction in this effect:


The dependency array remains `[tune]` only.
