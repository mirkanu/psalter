## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Plan stated 17 approved tunes; actual DB has 34**
- **Found during:** Task 2 dry-run
- **Issue:** The plan's objective referenced "17 approved tunes" but the DB had 34 rows with `status='approved'` in `tune_melisma_decisions`.
- **Fix:** Script processes all approved tunes dynamically via the SQL query — no hardcoded count. All 34 were extracted and migrated correctly.
- **Files modified:** None (script was written to query dynamically from the start)

**2. [Rule 3 - Blocking] `scripts/migrate/` directory did not exist**
- **Found during:** Task 1
- **Issue:** Plan specified path `scripts/migrate/extract-melisma-positions.ts` but the directory didn't exist.
- **Fix:** Created `scripts/migrate/` directory.
- **Files modified:** Directory created

**3. [Rule 3 - Blocking] `melismaPositions` column absent from worktree schema**
- **Found during:** Task 1 TypeScript compilation
- **Issue:** Plan 01 (which adds the column) runs on a different worktree branch. This worktree's `src/db/schema.ts` didn't have the column, so the Drizzle `.set({ melismaPositions: ... })` call failed to type-check.
- **Fix:** Cherry-picked commit `135d3e2` (Plan 01's schema addition) into this worktree. The same change will be present on master after both branches merge (non-conflicting identical addition).
- **Files modified:** src/db/schema.ts

**4. [Rule 1 - Bug] `db.execute<TuneRow>()` type incompatibility with postgres.js + Drizzle**
- **Found during:** Task 1 TypeScript compilation
- **Issue:** Drizzle's `db.execute()` requires a `SQLWrapper` argument; passing `pgClient\`...\`` (a PendingQuery) caused TS2345. Also `TuneRow` needed an index signature for the generic constraint.
- **Fix:** Used `pgClient<TuneRow[]>\`...\`` (raw postgres.js query) for the `DISTINCT ON` query, and used Drizzle ORM only for the `UPDATE` within transactions.
- **Files modified:** scripts/migrate/extract-melisma-positions.ts
