# Phase 04.9.14 Plan 03: PlayMiniBar Positioning — Fixed Above GlassBottomBar Summary

Fixed the Phase 4.9.13 regression where `PlayMiniBar` (in `variant="inline"`, used on the chromeless SingingView) flowed inline in the document after `GlassBottomBar`'s `fixed bottom-0` element — placing it at the true bottom of the page and requiring a scroll to reach — by switching it to `fixed` positioning anchored directly above the bottom bar, wiring it into Plan 01's existing scroll-hide listener for auto-hide, and reserving exact bottom padding via a height self-report instead of a static guess.

## What Was Built

### Task 1 — DOM order (already satisfied, no change needed)
Read the current `SingingView.tsx` render order before starting: `GlassBottomBar` already renders before `PlayMiniBar` (both as siblings after `<main>`), matching the plan's target order exactly. No diff was needed for this task — it appears a prior session/plan had already applied this part of the fix (Plan 01/02 both touched `SingingView.tsx` extensively). Verified via direct read rather than assumed.

### Task 2 — PlayMiniBar fixed positioning above GlassBottomBar
`PlayMiniBar.tsx`'s `variant="inline"` branch (used exclusively by `SingingView`) now renders with `fixed inset-x-0` and a `bottom` offset expressed as `calc(2.75rem + max(env(safe-area-inset-bottom) - 12px, 0px))` (44px, matching `GlassBottomBar`'s `h-11` + its own safe-area formula) on mobile, `calc(3.25rem + ...)` (52px, matching `h-13`) at `md:`. Desktop (`md:`) additionally switches to a right-aligned floating card (`md:inset-x-auto md:right-4 md:max-w-md md:w-auto md:rounded-lg md:border md:shadow-lg`), matching the existing `variant="fixed"` desktop treatment used on `/tunes/[id]`. The previous non-fixed `!isFixed && 'ml-auto rounded-lg ...'` class (which put the bar in normal document flow) was removed for the inline variant.

### Task 3 — Scroll-driven auto-hide, independent of manual collapse
`SingingView.tsx` gained a `miniBarAutoHidden` state, set by the same scroll listener Plan 01 already attaches to `[data-notation-viewarea]` (100px scroll-down threshold, same as `bottomBarHidden`, since the mini bar sits directly above the bottom bar). A new `effectiveMiniBarVisible = miniBarVisible && !miniBarAutoHidden` derivation is passed as the `visible` prop to `PlayMiniBar` instead of the raw `miniBarVisible` state. `miniBarVisible` itself remains the manual toggle (set `false` by the collapse button, set `true` by `handlePlayingChange`/`handlePlayToggle`) — a user's manual collapse is never overridden by an upward scroll, since `effectiveMiniBarVisible` stays `false` regardless of `miniBarAutoHidden`'s value once `miniBarVisible` is `false`.

### Task 4 — Dynamic bottom padding (no gap/overlap, all height modes)
Rather than the plan's literal static `pb-[90px] md:pb-[96px]` guess (which would either waste space when the bar isn't visible or under-reserve space in the 80px-tall SoundCloud mode), `PlayMiniBar` now accepts an `onHeightChange?: (heightPx: number) => void` prop, wired to a `ResizeObserver` on its own root element (reporting `0` when not mounted/hidden, and the live `offsetHeight` otherwise — so it tracks both the 44px compact profile and the 80px SoundCloud profile automatically). `SingingView` stores this in `miniBarHeight` state and renders a dynamic spacer `<div style={{ height: effectiveMiniBarVisible ? miniBarHeight : 0 }} />` as the last child inside `<main>`, on top of the existing `pb-11 md:pb-13` reserved for `GlassBottomBar` alone. `GlassBottomBar.tsx` itself required no changes — its existing fixed positioning, height, and border were already correct; the gap/overlap problem was entirely in `PlayMiniBar`'s stacking, not `GlassBottomBar`'s.

### Task 5 — Playwright UAT
Created `tests/e2e/play-mini-bar.spec.ts` covering: mobile — renders above `GlassBottomBar` with no scroll required after starting playback; desktop — fixed + right-aligned floating card; auto-hide on scroll down / restore on scroll up (via `aria-hidden` attribute, since PlayMiniBar keeps `display:none` only after its exit transition completes); manual collapse staying collapsed through a scroll-up cycle; and no gap/overlap between the two bars in both compact and SoundCloud-toggled modes.
