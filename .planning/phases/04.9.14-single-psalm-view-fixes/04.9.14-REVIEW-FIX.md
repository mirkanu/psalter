## Fixed Issues

### CR-01: OnboardingTour crashes if the step list shrinks while mid-tour

**Files modified:** `src/components/singing/OnboardingTour.tsx`
**Commit:** 46a427b
**Applied fix:** Added an effect that clamps `step` to `steps.length - 1` whenever `steps` shrinks (e.g. resize/rotation crosses the 768px breakpoint mid-tour). Also hardened the measurement effect and the render path with a locally-derived `currentStep = Math.min(step, steps.length - 1)`, since the clamping effect commits one tick after the render/measurement pass that could otherwise read `steps[step]` as `undefined` in the same tick `steps` shrank.

### CR-04: GearPopover's single `solfegeAvailable` boolean blocks split-leaf Solfège for unapproved tunes

**Files modified:** `src/components/singing/GearPopover.tsx`, `src/components/singing/SingingView.tsx`
**Commit:** 685a5bd
**Applied fix:** Replaced the single `solfegeAvailable` prop with `solfegeInlineAvailable` (gated by `isTuneApproved`) and `solfegeSplitAvailable` (ungated, derived from `solfegeJpgUrl`/`solfegePages` presence). `GearPopover` now derives the effective `solfegeAvailable` used for the notation-type button from whichever variant matches the *currently selected layout* (`isSplit`), matching `NotationRenderer`'s documented "split-leaf solfège is unaffected by melisma approval status" gating exactly.

### CR-03: Scroll-hidden chrome can get stuck hidden after a tune switch

**Files modified:** `src/components/singing/SingingView.tsx`
**Commit:** a1c4691
**Applied fix:** The scroll-hide effect now resets `topBarHidden`, `bottomBarHidden`, and `miniBarAutoHidden` to `false` at the top of its body, every time it (re)attaches (including on tune switch, since `abc` is its only dependency).

### CR-02: Public solfège approval gate depended on a dev-tools API route

**Files modified:** `src/app/api/melisma-status/route.ts` (new), `src/components/singing/SingingView.tsx`
**Commit:** f1483ae
**Applied fix:** Checked `middleware.ts` — its `matcher` only covers `/dev/:path*` and `/precent/:path*`, NOT `/api/dev/:path*`, so the app-level auth gate does not actually cover the endpoint SingingView was calling; the Cloudflare Access ingress rules referenced in the route's docstring live outside this repo (VPS tunnel dashboard config) and could not be conclusively verified from the codebase. Per the task's guidance, took the safer option: added a new stable, intentionally-public read-only route `GET /api/melisma-status?tuneId=N` (duplicates the read-side query rather than importing from `/api/dev/melisma-decision`, so its public contract is self-contained) and switched `SingingView`'s fetch to it. `/api/dev/melisma-decision` (GET + POST) is untouched and remains the admin/precentor path.

## Skipped Issues

### WR-01: Shared `melismaPositions` applied across two ABC sources with potentially different phrase counts

**File:** `src/components/notation/NotationRenderer.tsx:750-756, 1040-1051`
**Reason:** Read `.planning/research/lyric-to-note-alignment.md` (binding per project CLAUDE.md) before assessing this finding. The finding's own suggested fixes are (a) a data-authoring-time verification process for every tune with `melismaPositions` set, or (b) computing/storing per-source melisma positions instead of a single shared array — the latter requiring a DB schema change (a second `melismaPositions`-like column keyed to the SATB/solfège source), a migration, and changes to the melisma editor's authoring UI (`/dev/melisma-editor`). Both are legitimate but are data-model/process changes, not a targeted code diff that can be safely applied and verified via this fixer's 3-tier verification strategy (which only confirms syntax, not the correctness of a redesigned melisma data model). Applying a superficial code-only patch (e.g. silently skipping mismatched phrase counts) risked masking real data errors rather than fixing them, and risked conflicting with the binding alignment rules in the research doc without a human able to confirm against a verified score. Deferred to the phase owner for a deliberate data-model decision.
