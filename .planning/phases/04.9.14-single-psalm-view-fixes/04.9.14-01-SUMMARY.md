# Phase 04.9.14 Plan 01: Split-Leaf Core Layout Fixes Summary

Fixed four Phase 4.9.13 split-leaf regressions (desktop side-by-side grid, mobile height overflow, missing scroll-hide chrome, coupled zoom) via a shared `renderSplitLeaf()` layout helper, a scroll-hide navigation system wired to the notation view's own scroll container, and split-leaf-only notation scale decoupling — plus 3 new onboarding tour steps and a Playwright UAT covering all four fixes.

## What Was Built

### Task 1 — Desktop split-leaf: lyrics under notation
`NotationRenderer.tsx` gained a `renderSplitLeaf(notationSlot, stanzaSlot)` helper used by both the `staff-split` and `solfege-split` branches. It replaces the old `grid-cols-1 md:grid-cols-5` (notation `md:col-span-3` beside lyrics `md:col-span-2`) with a layout that always stacks notation above lyrics — a single-column `grid grid-cols-1 gap-4` for non-chromeless callers (e.g. `/tunes/[id]`, `/study`), and a height-managed flex column for chromeless (SingingView).

### Task 2 — Mobile split-leaf: ≤50% notation height
For chromeless callers, `renderSplitLeaf` produces `flex flex-col h-full` with two `flex-1 min-h-0 max-h-[50%] overflow-y-auto` regions (notation, lyrics) below 768px, reverting to `md:max-h-none md:overflow-visible md:flex-none` (simple stacked flow) at `md:`. The outer `data-notation-viewarea` wrapper switches from `overflow-y-auto` to `overflow-hidden md:overflow-y-auto` in split mode so it doesn't double-scroll against the two inner regions. The solfège JPG fallback's `<img>` gets `max-h-full w-auto object-contain` in split mode so it shrinks to fit its 50%-height parent instead of overflowing (previously only the ABC path respected a height cap).

### Task 3 — Scroll-hide navigation
Added `topBarHidden`/`bottomBarHidden` state in `SingingView.tsx`, driven by a scroll listener attached to the actual scrollable element — `[data-notation-viewarea]` inside the `<main>` — rather than `window.scrollY` (this page's fixed-height flex layout never scrolls at the window level, so the literal CONTEXT sketch would never fire). The listener is attached via `mainRef.current.querySelector(...)` with an `requestAnimationFrame` retry loop, since `NotationRendererClient` is a `dynamic({ssr:false})` component that mounts asynchronously. `PsalmTopBar` hides past 40px of downward scroll; `GlassBottomBar` hides past 100px; both reappear immediately on any upward scroll, via `translate`/`opacity` transitions (200ms) on a new `hidden` prop on each component. `data-tour-target="top-bar"`, `"bottom-bar"`, and `"scroll-area"` were added for Task 5.

### Task 4 — Zoom decoupling
`NotationRenderer.tsx`'s `scale` derivation now checks `isSplitMode(viewMode)`: in split-leaf, `scale` is a fixed constant (`1`) instead of `baseSize / 14`, so A-/A+ (which still updates `baseSize` → `--staff-base-size`) only affects the lyrics `.verse-text`/`.verse-number` CSS var; the abcjs-rendered staff no longer resizes. Non-split modes are unchanged.

### Task 5 — Onboarding tour for scroll-hide
`OnboardingTour.tsx` gained 3 new steps (`SCROLL_HIDE_STEPS`) appended to the existing 4-step tour when `viewMode` is `staff-split`/`solfege-split` AND viewport `<768px` (`isSplitLeafMobile`, computed via a resize-listening `isMobile` state). Tour key bumped `psalter_tour_v1` → `psalter_tour_v2` to re-surface for users who already dismissed the old tour; `SingingView`'s `handleRestartTour` clears both keys. `OnboardingTour` now accepts an optional `viewMode` prop, passed from `SingingView`.

### Task 6 — Playwright UAT
Created `tests/e2e/split-leaf.spec.ts` covering Task 1 (desktop stacking), Task 2 (mobile ≤50% notation height), Task 3 (top bar `data-scroll-hidden` after scrolling the internal viewarea), and Task 4 (A+ changes `.verse-text` font-size but not the notation SVG `viewBox`) at 375/768/1200px.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] Scroll-hide wired to the wrong scroll source**
- **Found during:** Task 3
- **Issue:** The plan's CONTEXT sketch and Task 3 action both listen on `window.scrollY`. SingingView's actual layout is a fixed-height flex column (`<main class="h-[calc(100dvh-104px)] ... flex flex-col">`) whose scrolling happens entirely inside NotationRenderer's internal `[data-notation-viewarea]` div — the window itself never scrolls, so a `window` listener would never fire.
- **Fix:** Attached the scroll listener to `[data-notation-viewarea]` (located via a `mainRef` + `querySelector`, with an `requestAnimationFrame` retry loop to handle the async `dynamic({ssr:false})` mount of `NotationRendererClient`).
- **Files modified:** `src/components/singing/SingingView.tsx`
- **Commit:** `29c4575`

**2. [Rule 2 — Missing functionality] `files_modified` frontmatter didn't list all files the tasks required**
- **Found during:** Task 3, Task 5

These are correctness requirements for the scroll-hide feature to work (bars can't hide without a `hidden` prop on the bar components themselves).
- **Fix:** Edited `PsalmTopBar.tsx`, `GlassBottomBar.tsx`, and `OnboardingTour.tsx` as the task actions require.
- **Files modified:** `src/components/singing/PsalmTopBar.tsx`, `src/components/singing/GlassBottomBar.tsx`, `src/components/singing/OnboardingTour.tsx`

**3. [Rule 4-adjacent, resolved without a checkpoint] Task 5's third tour target ('scroll-up') has no DOM element**
- **Found during:** Task 5
- **Issue:** The plan lists three tour-step targets: `top-bar`, `scroll-area`, `scroll-up`. The first two correspond to real elements (`PsalmTopBar`, the `<main>` region). `scroll-up` describes a user action, not a UI control — there's no element to tag `data-tour-target="scroll-up"` on, and `OnboardingTour`'s `measure()` dismisses the whole tour gracefully if a target has zero matching elements (a pre-existing DoS-mitigation from Phase 4.9.4), so inventing a step around a non-existent target would silently kill the tour.
- **Resolution (no architectural change, so handled inline rather than as a Rule-4 checkpoint):** The third step reuses the `top-bar` target with different copy ("Scroll back up anytime to bring the bars back") — the same bar the user just watched hide is the natural element to highlight when explaining how it comes back.
- **Files modified:** `src/components/singing/OnboardingTour.tsx`
- **Commit:** `c8ce492`

**4. [Rule 3 — Blocking/convention mismatch] Task 6's example test uses `@playwright/test`, which isn't installed**
- **Found during:** Task 6
- **Issue:** The plan's Task 6 code sample imports `{ test, expect } from '@playwright/test'`. That package is not a dependency of this project (`package.json` has no `playwright` or `@playwright/test` entry); every existing spec in `tests/e2e/` (e.g. `abc-player.spec.ts`) is a plain Node script that does `require('/usr/lib/node_modules/playwright')` and is run via `node tests/e2e/<file>.spec.ts`.
- **Fix:** Wrote `tests/e2e/split-leaf.spec.ts` following the established convention (raw `chromium.launch()`, custom pass/fail tracking, `run()` entrypoint) instead of the `@playwright/test` runner API.
- **Files modified:** `tests/e2e/split-leaf.spec.ts`
- **Commit:** `f194145`
