Supported flags (all optional): `--quality=N`, `--width=N`, `--out=<abs-or-cwd-relative dir>`, `--limit=N` (process only the first N image files, sorted by filename), `--only=<substring>` (process only files whose name contains the substring), `--force` (delete an existing non-empty out dir first), `--skip-backup-check` (MUST print `WARNING: backup pre-flight skipped` to stderr when used; intended only for the sample-render path in Task 2 which writes outside `public/tunes-compressed/`).

Five abort guards, each printing `ABORT: <reason>` to stderr and calling `process.exit(1)` (port the shape from `backup-tunes.sh` lines 14-35):
1. **Never in place.** `if (resolve(outDir) === resolve(TUNES_DIR))` → `ABORT: refusing to write into the live tunes directory`. This guard must be the first thing checked, before any filesystem read.
2. **Source sanity.** Read `TUNES_DIR` with `readdirSync`; count files matching `/\.(jpg|jpeg|png)$/i`. If the count is `< MIN_IMAGE_COUNT` → `ABORT: only N images found in <dir> (expected ~326)`.
3. **Backup pre-flight.** Unless `--skip-backup-check`: `existsSync(BACKUP_ARCHIVE)` must be true, and `createHash('sha256')` streamed over the archive (`node:crypto` + `createReadStream`, never shell out, never load 1.4GB into a Buffer) must equal `BACKUP_SHA256` → otherwise `ABORT: backup archive missing or checksum mismatch — refusing to compress`. Print `Backup pre-flight OK: <sha256>` on success. This takes ~12s; that is acceptable and expected.
4. **Free space.** `execSync("df -Pk " + <parent dir of outDir>)`, take the last line, field 4, divide by 1024/1024 → GB. If `< MIN_FREE_GB` → `ABORT: only NGB free on <fs> (need at least 2GB)`.
5. **Clean staging dir.** If `outDir` exists and is non-empty: with `--force`, `rmSync(outDir, { recursive: true, force: true })`; without it → `ABORT: <outDir> already exists and is not empty (pass --force to overwrite)`. Then `mkdirSync(outDir, { recursive: true })`.

Processing (RESEARCH.md Pattern 1 — this is the OOM mitigation, do not "optimise" it):
```typescript
import sharp from 'sharp'
sharp.cache(false)
sharp.concurrency(1)

for (const name of entries) {          // plain sequential for...of — NEVER Promise.all / .map
  // ...
  await sharp(src)
    .resize({ width, withoutEnlargement: true })
    .jpeg({ quality, mozjpeg: true, chromaSubsampling: '4:4:4' })
    .toFile(dest)
}
```
Per-entry routing, based on the filename in `TUNES_DIR` (use `readdirSync(TUNES_DIR, { withFileTypes: true })`, skip directories, sort names ascending for deterministic ordering):
- `.jpg` / `.jpeg` → the sharp pipeline above, output filename identical to input (keep `.jpg`, do not rename).
- `.png` → `copyFileSync(src, dest)` byte-for-byte, NO re-encode. Rationale: ASSET-01 says "tune JPEGs"; the 6 PNGs are already small (12KB–194KB) and re-encoding them buys nothing while risking a "did not shrink" failure. They must still land in the staging dir so the Plan 03 swap does not lose them.
- Any other file (`.gitignore`, `.gitkeep`) → `copyFileSync(src, dest)` byte-for-byte. These two files exist and MUST survive the swap.

Per-file shrink check (RESEARCH.md Pattern 3): after each `.jpg`/`.jpeg` write, compare `statSync(dest).size` vs `statSync(src).size`. If `compressedSize >= originalSize`, `console.warn(\`WARN: ${name} did not shrink (${originalSize} -> ${compressedSize})\`)` and increment a `notSmaller` counter. Do NOT auto-fall-back to copying the original — record it and let Plan 02's verifier fail loudly.

OOM canary: every 25 files, log `\`[${i}/${total}] rss=${Math.round(process.memoryUsage().rss / 1048576)}MB\``.
