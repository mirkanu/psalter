## v1.0 Scope Decisions (Deferred at Close)

The following phases were part of Milestone 1 planning but explicitly deferred at v1.0 close rather than blocking the tag — see `.planning/STATE.md` Deferred Items table for full rationale:

- **Phase 4.9** (Tune Notation Conversion) — superseded by the manual `/dev/melisma-editor` workflow built during Phase 4.11
- **Phase 4.10** (Verified MusicXML Pilot — Crimond) — superseded by Phase 4.11; 4/5 plans done, sing-test checkpoint never run
- **Phase 4.11** (Solfège Underline OCR) — pivoted from a mechanical batch OCR push to a manual per-tune editor. At v1.0 close: 70/172 tunes marked `approved` (unlock live inline-Staff notation); 5 `not_approved`; 8 in-progress; 89 never reviewed. Non-approved tunes gracefully fall back to the JPEG scan (Phase 4.9.15 gate) — no production breakage. Remaining tune-by-tune approval continues as ongoing background work, not a release gate.
- **Phase 4.9.11** (Lyric-Count False Positive Fix) — not started
- **Phase 4.9.12** (Melisma positions as tune-level data) — 3/4 plans done; final NotationRenderer positions-based rewire not applied (current embedded-`w:` rendering path still in production use, works correctly for approved tunes)
