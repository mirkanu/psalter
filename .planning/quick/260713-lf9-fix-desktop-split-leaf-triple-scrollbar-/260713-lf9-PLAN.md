<task type="auto">
  <name>Task 2: Clamp iOS rubber-band overscroll in the mobile scroll-hide handler (bug 2)</name>
  <files>src/components/singing/SingingView.tsx</files>
  <action>
MOBILE-ONLY fix (the `if (!mql.matches) return` gate stays first — no desktop code path is touched). Root cause: iOS Safari rubber-band overscroll lets `scrollTop` oscillate/overshoot past `[0, scrollHeight - clientHeight]` at the scroll boundary; the current handler has no clamping/hysteresis, so every bounce frame is treated as an authoritative direction signal, flipping the hidden state rapidly.

Replace the `handleScroll` function (~382-395) with a clamped + thresholded version:
```tsx
const lastByEl = new WeakMap<EventTarget, number>()
const handleScroll = (e: Event) => {
  if (!mql.matches) return
  const el = e.target as HTMLElement | null
  if (!el || typeof el.scrollTop !== 'number') return
  // iOS Safari rubber-band overscroll reports scrollTop OUTSIDE the natural
  // [0, maxTop] range and oscillates rapidly at the boundary. Clamp to the
  // valid range so bounce frames collapse to a constant boundary value
  // (delta ~0) instead of registering as real up/down movement.
  const maxTop = Math.max(0, el.scrollHeight - el.clientHeight)
  const scrollTop = Math.min(Math.max(el.scrollTop, 0), maxTop)
  const last = lastByEl.get(el) ?? 0
  const delta = scrollTop - last
  // Ignore sub-threshold jitter (bounce settle / tiny finger tremor). Normal
  // scrolling easily exceeds 4px; slow real scrolls still accumulate because
  // we do NOT advance `last` until the threshold is crossed.
  if (Math.abs(delta) < 4) return
  const scrollingDown = delta > 0
  setTopBarHidden(scrollTop > 40 && scrollingDown)
  setBottomBarHidden(scrollTop > 100 && scrollingDown)
  setMiniBarAutoHidden(scrollTop > 100 && scrollingDown)
  lastByEl.set(el, scrollTop)
}
```
Behavior preserved: the 40px/100px thresholds, instant restore on upward scroll (any real ≥4px upward movement sets `scrollingDown = false` → un-hides), the WeakMap per-element last-scroll tracking, and the capture-phase listener. Do NOT change the `useEffect` deps, the `mql` gate, the tune-switch reset (setTopBarHidden(false) etc.), or the `handleMql` desktop-reset. The 4px threshold is imperceptible for normal scrolling (a single scroll gesture moves tens of px) and does not add a timer/debounce, so there is no perceptible lag.
