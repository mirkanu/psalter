<root_cause_analysis>
Confirmed by reading the source (do not re-derive — implement against these findings):

- **Bug (a) — bars don't fully hide.** `PsalmTopBar` is `sticky top-14` (56px = 3.5rem below the viewport top, sitting under SiteHeader). Its hidden class `-translate-y-full` moves it up by only its OWN rendered height (~48px mobile), which leaves it parked at roughly y=8..56px — still on-screen (occluded behind SiteHeader z-50) instead of fully gone. Additionally BOTH bars use `transition-transform transition-opacity`; in Tailwind each of these sets `transition-property`, so the second wins and ONLY opacity animates — the transform snaps. Fix: translate the top bar fully clear of its top offset, and collapse the two transition utilities into one `transition-[transform,opacity]`. `GlassBottomBar` (`fixed bottom-0`) already uses `translate-y-full` which fully clears the bottom edge — it only needs the transition-property fix.

- **Bug (b) — SiteHeader never hides.** `SiteHeader` renders in `src/app/layout.tsx` (root layout), completely disconnected from `SingingView`'s local `topBarHidden` state. It needs to receive the hidden signal without becoming coupled to the singing view or breaking on other pages.

- **Bug (c) — split-leaf never fires.** In split-leaf chromeless mode the `[data-notation-viewarea]` wrapper is `overflow-hidden md:overflow-y-auto` (NotationRenderer.tsx ~line 1360) and does NOT scroll below 768px; the two inner `renderSplitLeaf` regions (`flex-1 min-h-0 max-h-[50%] overflow-y-auto`, ~lines 1090/1093) scroll independently. SingingView's listener attaches ONLY to `[data-notation-viewarea]` (SingingView.tsx ~line 402), so no scroll event ever fires in split mode. Fix: attach a single capture-phase scroll listener to `mainRef.current` and read `e.target.scrollTop` — capture-phase catches scroll from ANY descendant (the non-split viewarea AND both split-leaf inner regions), and removes the need for the `querySelector` + rAF-retry attach loop.
</root_cause_analysis>
