<objective>
Eliminate the iOS Safari rubber-band scroll-hide flicker on HARD flicks by disabling
native overscroll/bounce on every flickable scroll region in the chromeless singing view.

Background: quick task 260713-lf9 added a JS clamp + 4px delta threshold to the
scroll-hide handler in SingingView.tsx. Real-device testing confirmed this fixed GENTLE
flicks but a HARD flick still flickers — the hard flick's rubber-band overshoot produces
LARGE intermediate scrollTop deltas (not the sub-4px jitter the threshold was built for),
so they pass the filter and read as genuine direction reversals, flipping the hidden/shown
state rapidly.

Research (MDN, WebSearch/WebFetch confirmed) says the standards-based fix for this class
of bug is the CSS `overscroll-behavior` property, not more JS event filtering. Setting
`overscroll-behavior-y: none` on the scroll container disables the element's native
overflow bounce ENTIRELY (a firm stop at the boundary, no elastic rubber-band). Because
our bug is the SAME element's own scrollTop oscillating during ITS OWN bounce (not scroll
CHAINING to a parent), `none` is correct — NOT `contain` (which still bounces locally).
With no bounce, iOS never generates the erratic intermediate scrollTop values, regardless
of flick force. This is more robust than debouncing after the fact and adds no lag to
normal scrolling.

Trade-off (accepted): removes the tactile edge-bounce iOS users expect on these regions,
trading a familiar-but-buggy feel for a firm-stop-but-reliable one. This is the standard
accepted trade-off (libraries like iNoBounce existed for years to solve exactly this
before overscroll-behavior was standardized).

Purpose: Kill the hard-flick flicker at its source (native bounce) rather than filtering
its downstream scroll events.
Output: overscroll-y-none on all six scroll containers in NotationRenderer.tsx. No JS
changes. 260713-lf9's clamp/threshold stays as defense-in-depth for non-supporting engines.
</objective>
