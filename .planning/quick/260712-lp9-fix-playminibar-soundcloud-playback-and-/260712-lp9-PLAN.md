<objective>
Fix two PlayMiniBar bugs found in human UAT of phase 04.9.14:

(a) **SoundCloud playback is dead.** Commit `1a7afbe` (review finding WR-03) dropped `allow-same-origin` from the SoundCloud iframe's `sandbox`, on the theory the embed "does not require same-origin storage access." That theory is FALSE — proven by a live Playwright test during planning (see Context). The SoundCloud widget accesses `localStorage` during init; under `sandbox="allow-scripts"` alone the frame is an opaque origin, `localStorage` throws `SecurityError`, the widget never mounts its UI (body stays a 478-char shell), and NO play button renders. Restore `allow-scripts allow-same-origin` and document it as a deliberate, low-risk, cross-origin exception rather than silently reverting a real security finding.

(b) **Desktop positioning is wrong.** The `variant="inline"` PlayMiniBar uses `md:right-4`, pinning its right edge 16px from the far VIEWPORT edge. But the controls (GlassBottomBar) live in a centered `max-w-4xl` column, so on wide screens the mini bar floats far right of the Gear icon (measured 144px off at 1200px, 264px off at 1440px). It should instead align its right edge with the content column / Gear button. A prior attempt at this (Phase 04.9.14-03) is warned to have risked breaking mobile — so the fix MUST touch ONLY the `md:` class and leave mobile's unprefixed `inset-x-0` untouched.

Purpose: Restore SoundCloud playback and correct desktop chrome alignment without regressing mobile.
Output: One-file CSS/attribute change in PlayMiniBar.tsx + regression assertions, gated by a human visual check.
</objective>

## Live diagnostic evidence gathered during planning (do NOT re-derive — act on it)

### Bug (a) — SoundCloud sandbox, proven via Playwright daemon
Loaded the real SoundCloud widget URL in two iframes and inspected each frame:

| sandbox | localStorage | widget body | play button |
|---------|-------------|-------------|-------------|
| `allow-scripts` (current, WR-03) | **THROWS SecurityError** | 478 chars (empty shell) | **absent (false)** |
| `allow-scripts allow-same-origin` | accessible | 8200 chars (rendered) | **present (true)** |

Conclusion: `allow-same-origin` is REQUIRED. The WR-03 fix broke playback.

Security note on the exception (record this in the code comment, do not silently revert):
- The frame src is `w.soundcloud.com`, **cross-origin** to `psalter.gsdlabs.dev`. For a cross-origin embed, `allow-same-origin` grants the framed doc ITS OWN origin (soundcloud's) — it does NOT grant access to our DOM, cookies, or storage. The classic "`allow-scripts` + `allow-same-origin` lets the frame remove its own sandbox / script the parent" escape concern applies to SAME-origin framed content; here the frame cannot reach our origin.
- `soundcloudUrl` is a DB field editable only by admin/precentor (not raw public input). The `src` is URL-encoded via `encodeURIComponent`.
- Net residual risk: low. This is a knowing, documented re-introduction, not an accidental regression of WR-03.

### Bug (b) — desktop positioning, measured live (px, y-axis omitted)

| viewport | PlayMiniBar.right | Gear.right | max-w-4xl column.right | delta (bar past gear) |
|----------|-------------------|-----------|------------------------|-----------------------|
| 375 (mobile) | 375 (full width, left 0) | 367 | 375 | n/a — correct |
| 1200 | 1184 | 1040 | 1048 | +144 too far right |
| 1440 | 1424 | 1160 | 1168 | +264 too far right |

Fix geometry (validated against these exact measurements):
`right = max(0px, (100vw - 56rem)/2) + 0.5rem` reproduces the Gear's right edge exactly (1200 -> 1040, 1440 -> 1160). `56rem` = `max-w-4xl` (896px); `+0.5rem` matches GlassBottomBar's inner `px-2`. The singing page has no window vertical scrollbar (fixed 100dvh layout, notation scrolls internally), so `100vw` == content width — confirmed: at 1200px the column is perfectly centered (152 + 896 + 152 = 1200).
