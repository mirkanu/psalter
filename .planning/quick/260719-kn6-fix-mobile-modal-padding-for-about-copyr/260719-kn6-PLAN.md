Base DialogContent className (src/components/ui/dialog.tsx, unchanged):
```
"fixed top-1/2 left-1/2 z-50 grid w-full max-w-[calc(100%-2rem)]
 -translate-x-1/2 -translate-y-1/2 gap-4 rounded-xl bg-popover p-4 ...
 sm:max-w-sm ..."
```
- `max-w-[calc(100%-2rem)]` = 1rem gap each side on mobile (the desired behaviour).
- Any UNQUALIFIED `max-w-md` / `max-w-lg` passed via className is merged by
  tailwind-merge and overrides `max-w-[calc(100%-2rem)]` at ALL breakpoints,
  removing the mobile side gap. This is the bug.

Reference (correct) pattern — New Set modal, src/components/precent/CreateSetForm.tsx:128:
```
<DialogContent className="sm:max-w-[420px]">
```
The `sm:` prefix means the width override only kicks in at ≥640px, so the mobile
`max-w-[calc(100%-2rem)]` gap is preserved. Apply this same `sm:`-scoping pattern
to the three target modals.
