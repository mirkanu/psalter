# Quick Task 260513-q07 Summary: Fix AbcPlayer BPM

## Objective

Fix audio playback speed and highlight sync when user adjusts BPM in the player. BPM slider had no effect on either.

## Work Completed

### 1. Fixed AbcPlayer.tsx: millisecondsPerMeasure positioning
- Moved `millisecondsPerMeasure` from nested `options: {}` to top-level of `synth.init()` call
- abcjs `CreateSynth.init()` reads from top-level, not nested — this was preventing BPM changes from affecting audio speed

### 2. Fixed AbcPlayer.tsx: TimingCallbacks BPM parameter
- Changed TimingCallbacks initialization to use `qpm: bpm` instead of `millisecondsPerMeasure`
- TimingCallbacks reads `params.qpm` to control highlight timing rate — the previous parameter was being ignored

### 3. Switched OCR model to Haiku
- Updated `ocr-solfege-v2.ts` and `scripts/ocr-solfege.ts` to use `claude-haiku-4-5-20251001`
- Reason: Sonnet token limit exhausted after 139 tunes; Haiku succeeded on all 5 remaining failures

### 4. Re-ran OCR for 5 tune failures
- Tunes: Bays of Harris, Kingsfold, Wallace, Effingham, Forest Green
- Result: 100% success — all 144 tunes now have solfege_ocr_text + abc_satb columns populated
- Updated psalter-db and redeployed

## Verification

**Tested on site:** ✓ BPM slider now controls both audio playback speed and highlight sync
- At BPM 100: audio plays slower, highlight moves slower
- At BPM 160: audio plays faster, highlight moves faster
- Key change (transpose) still works correctly
